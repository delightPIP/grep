# 상세 구현 명세 (색인)

- 성격: **색인**이다. 화면·데이터·로직·모듈을 정한 원본 문서와 정책 ID를 가리키기만 하고 값·문구를 옮겨 적지 않는다. 값을 고칠 때는 원본 한 곳만 고친다
- 기준: `origin/main` 커밋 `509482f`(2026-11-26), [개발 전달 문서 08](planning/collab-2026-11-26/08-po-dev-handoff.md) 판 0.6
- 범위: 12/01 발표 데모 흐름(로그인 → 담기 → 찾기 → 넘기기)과 첫 플랫폼인 웹. 다른 플랫폼은 4절에 원본 위치만 적는다
- 우선순위: 정책([docs/policies](policies/README.md))이 서비스 동작·값·문구의 유일한 근거다(AGENTS.md). 이 색인이나 다른 기획 문서가 정책과 다르면 정책을 따른다
- 정하는 사람: 화면·문구·규칙은 PO, 데이터 구조·API 모양·파일 구성은 개발자([개발 팀 설정](dev-team-config.md) 역할과 결정권)
- 판단 표시: 이 문서의 묶음과 대응은 `AI 제안·미확인`이다. 개발자는 아직 보지 않았다

## 1. 화면 및 UI 컴포넌트 구조

웹은 터미널 화면 하나다. 상단 메뉴·사이드바·모달을 두지 않고, 명령 한 줄과 결과 블록이 쌓인다([명령어 설명서](planning/commands.md) 1절·6절).

| 영역 | 담는 것 | 원본 |
|---|---|---|
| 상태줄 | 자료 건수, 처리 중 건수, 선택 건수, 연결 끊김 | 명령어 설명서 6절, ARC-005 규칙 10, COM-009 규칙 5 |
| 출력 영역 | 명령과 결과 블록(목록 행, 성공·실패 줄, 다음 명령 칩) | 명령어 설명서 6절 화면 문구, [화면 체크리스트](planning/screen-checklist.md) 1절 W1~W34 |
| 입력줄 | 명령 입력, 이어 쓰기 `\|`, 확인 답 | 명령어 설명서 3·4절, COM-007 |
| 칩 | `→` 뒤 명령(누르면 입력줄에 찍기만), 화면 칩 `펼치기`(바로 동작) | 명령어 설명서 6절, STATE 12절(04 질문 3) |
| 첫 화면(자료 0건) | 한 문장, 표어, 세 명령, 샘플 안내 | 명령어 설명서 6절, ARC-010 |
| 공통 부품·토큰 | 시안의 부품 목록과 플랫폼 대응 | [공통 부품](planning/components.md) |

화면 상태는 아래에서 찾는다.

| 찾는 것 | 원본 |
|---|---|
| 웹 화면 목록(W1~W34)과 각 화면의 근거 정책 | [화면 체크리스트](planning/screen-checklist.md) 1절 |
| 흐름 단계별 화면과 분기 | [사용자 흐름도](planning/user-flow.md) 2~11절(`[데모]` 표시) |
| AI 기능 상태 ST-01~34, 수용 기준 AC, 시험 TC | [05 AI UX 설계](planning/collab-2026-11-26/05-designer-ai-ux-design.md) 초안 0.2(PR #25 반영 전, 08 8절 19번) |
| 데모 장면별 나와야 하는 것·나오면 안 되는 것 | [데모 시드](planning/demo-seed.md) 5절 |
| 넘길 글과 넘기기 화면의 대응 | [넘길 글 형식](planning/handoff-format.md) 5절 |

## 2. 데이터 모델

필드 이름·타입·저장 방식은 **개발자가 정한다**(ADR-0001: OpenAPI 계약이 원본, 계약 파일 위치는 [개발 팀 설정](dev-team-config.md)에서 아직 비어 있음). 아래는 정책이 이미 정한 **값과 제약**의 위치다.

| 대상 | 정책이 정한 것 | 원본 |
|---|---|---|
| 자료 | 사용자별 고유 번호(목록 위치가 아님, 지운 번호 재사용 안 함) | ARC-001 |
| 자료 | 처리 상태 다섯 가지(`received`·`processing`·`ready`·`blocked`·`failed`), 저장과 처리는 따로 | ARC-005 |
| 자료 | 받는 형식, 파일 크기 상한 | COM-004, COM-005 |
| 자료 | 같은 링크·파일 판정 | COM-001 |
| 자료 | 휴지통 30일, 영구 삭제 | ARC-008 |
| 요약·태그 | AI 생성 표시, 직접 고친 요약은 따로, 태그 최대 개수·지운 태그 기억 | ARC-004, ARC-002 |
| 사용자 | 소셜 로그인, 세션 기간, 사용자별 분리 | ACC-001, COM-006 |
| 묶음 | 한 단계, 이름 규칙 | ARC-003 |
| 넘길 글 | 칸 순서·이름, `[자료 N]`은 순서이고 자료 번호가 아님 | [넘길 글 형식](planning/handoff-format.md) 2절 |
| 측정 이벤트 | 이름 세 개, 넣지 않을 속성(가정) | 08 T-14, 05 6-5절 |
| 터미널 기록 | 이 기기에만, 서버에 두지 않음 | COM-009 |

서버 쪽 구조와 API 영역은 [백엔드 설계](planning/backend-design.md) 2절(엔드포인트는 예시)과 3절(데이터 프로파일), 저장소 구성은 ADR-BCK-002·006에 있다. 정하지 않은 것은 백엔드 설계 6절과 08 6절 개발 확인이다.

## 이 색인을 고칠 때

- 원본 문서의 절 번호나 이름이 바뀌면 이 표의 위치만 고친다. 값은 옮겨 오지 않는다
- 새 정책이 생기면 2절(데이터 제약)이나 3절(로직) 표에 ID만 더한다
- 개발자가 OpenAPI 계약과 파일 구성을 정하면 2·4절 첫 문단에 그 위치를 적는다
