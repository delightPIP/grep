# 2026-11-26 · 저장된 자료 보기 흐름과 시안 (자세히 보기, 보관함)

- 작성자: TAENI
- 이슈·PR: 없음(PR 전)
- 커밋: 없음(커밋 전)

> **요약** PO가 "아카이빙된 자료를 화면에 어떻게 보여 줄지 흐름도 디자인도 없다"고 짚었고, AI가 문서·정책·웹 시안을 대조해 빈칸 네 가지(자세히 보기, 보관함 흐름, 넓은 웹 배치, 목록의 이미지·PDF 표시)와 기본안을 냈다. PO가 기본안으로 진행하기로 했고, AI가 정책 ARC-011, `열기` 명령, 사용자 흐름도 12절, 시안 세 장을 만들었다.

## 사용 도구

Claude Code(Opus 5.5), Artifact(디자인 캔버스 "그렙 웹 화면 시안"), `Scripts/check-docs.sh`, PowerShell `Get-Command`·bash `type -t`(명령 이름 겹침 확인)

## 요청

- 저장된 자료를 화면에 보여 주는 흐름과 디자인이 없어 전체 흐름이 완성되지 않은 것 같다.
- (빈칸과 기본안을 본 뒤) 기본안으로 진행.

## AI 산출물

- 점검: 자세히 보기는 ARC-004, 기획서 F2, 모바일 시안 M3이 전제하지만 여는 명령·내용·시안이 없음. 보관함은 ARC-007이 묶는 기준만 정했고 흐름·시안이 없음. 600px 이상 웹 배치는 MOB-001 비고로 미정. 목록의 이미지·PDF 표시와 휴지통 화면 미정
- [ARC-011](../../policies/archive/ARC-011-item-detail-view.md)(검토 중): `열기 <번호>`(peek), 제목 누르기로 열기, 보여 주는 차례, 본문 접힘, 원본 미리보기(이미지·PDF, 링크는 그림 없음), 동작은 같은 명령으로 터미널 기록에 남김
- [명령어 설명서](../../planning/commands.md): `열기` 추가(도움말 목록, 설명서, 화면 문구, 이름 겹침 확인)
- [사용자 흐름도](../../planning/user-flow.md) 12절: 자세히 보기, 보관함, 넓은 웹·데스크톱 배치. 옛 12절은 13절로
- 시안: 웹 09(터미널의 `열기`), 웹 10(넓은 웹 보관함, 사이드바·목록·자세히 보기 칸, 직접 눌러 볼 수 있음), 모바일 M6(보관함 탭 → 목록 → 자세히 보기). M3 메뉴의 `열기` 동작을 새 정책에 맞춤

## 사람의 판단

- PO가 AI 기본안을 그대로 채택: 자세히 보기 [P0], 명령 `열기`, 본문 접힘·원본 미리보기, 보관함 리스트 기본(이미지 묶음만 그리드), 넓은 웹 사이드바 + 오른쪽 자세히 보기, 보관함 [P1]
- 폭 값(600px, 1008px)과 레일·사이드바 전환은 개발자가 정하도록 남김

## 검증

- `bash Scripts/check-docs.sh`: 통과
- `peek`는 PowerShell 5.1과 Git Bash에서 기존 명령이 아님을 확인. `view`는 Git Bash에 있어 후보에서 뺌
- 시안은 게시만 했고 화면을 열어 보거나 눌러 보지 않음

## 검증하지 못한 것

1. 맥 터미널(zsh)에서 `peek` 이름 겹침
2. 시안 세 장의 실제 렌더링과 상호작용(디자인 시스템 컴포넌트 `Next`에 `{ text: '또는' }` 꼴을 넣은 것이 의도대로 보이는지 포함)

## AI의 오류와 정정

1. 처음 기본안은 넓은 웹에서 터미널 옆에도 자세히 보기 칸을 두는 것이었으나, 디자인 시스템 1절 원칙("터미널은 창 하나, 패널을 나누지 않음")과 부딪혔다. 터미널에서는 늘 출력 블록으로 보여 주고, 오른쪽 칸은 보관함 화면에만 두도록 고쳤다.
