> **요약** 순수 뷰(`web/features/logged-in/view.tsx`)에 `찾기` 결과 머리줄(`4건`, `23건 중 10건`), 0건 뒤 `(검색 결과 아님)` 머리줄과 최근 자료, 일치 위치 `· 이미지 속 글자`를 더했다. AI가 핸드오프 문서와 정책 원문을 읽고 테스트를 먼저 쓴 뒤 구현했다. 사람은 브라우저 미리보기를 보고 일치 위치 앞에 `·`를 붙이기로 정했다.

## 사용 도구

Claude Code(Claude Opus 5.5). git worktree, gh, vitest, Vite 개발 서버, 헤드리스 Chrome 스크린샷. 스킬: docs:ai-usage.

## 요청

핸드오프 문서(`.handoff-latest.md`)를 확인하고 #61 뷰 작업을 이어 하라고 했다. 구현 뒤 브라우저로 띄워 보여 달라고 했고, 확인 뒤 로그 작성, 핸드오프 삭제, 푸시까지 하라고 했다.

## AI 산출물

- `origin/main`(ADR-0015 문서 커밋) 위로 리베이스
- commands 3절·6절, ARC-002 사용자 문구, Swift 계약 주석(`LoggedInInterface.swift`)에서 문구 확인
- view 테스트 9개(given/when/then) 먼저 작성, 8개 실패(RED) 확인
- `searchResult`: 머리줄은 보인 행 수가 전체보다 적으면 `23건 중 10건`, 같으면 `4건`. 행과 `→ 더 보기`는 #60 목록 재사용
- `noResults`: `· 0건: "<친 검색어>"`, 최근 자료가 있으면 `· 최근 저장 N건 (검색 결과 아님)`과 그 행
- 일치 위치: `imageText`만 요약 줄 끝에 흐리게(`.gt-row-match`). 행에 이미 보이는 곳(제목·출처·요약·태그)은 붙이지 않음
- 예시 상태를 넣은 임시 미리보기 페이지로 화면을 띄우고 스크린샷 확인. 확인 뒤 페이지 삭제

## 사람의 판단

- 핸드오프의 "검색어 머리줄"은 정책 문구(`4건`)대로 건수만 두는 AI 해석을 받아들였다(검색어는 입력줄에 이미 보임)
- `본문` 일치 표시는 정책 문구가 없어 비워 두는 안을 받아들였다
- 미리보기에서 `이미지 속 글자`가 흐린 요약 문장과 붙어 구분되지 않는다는 AI 지적에, 앞에 `·`를 붙이는 안을 골랐다
