> **요약** PO가 빠진 결정으로 로그인, 기기 관리, 일련번호, 태그, 폴더링을 짚었다. AI가 기존 문서의 빈 곳과 충돌(자료 번호의 두 가지 뜻, 로그인 없는 데모와 사용자별 데이터 분리)을 찾아 선택지를 냈고, PO가 고른 대로 정책 5건(ACC-001·002, ARC-001~003)을 새로 등록하고 기획서와 명령어 설명서를 맞췄다.

## 사용 도구

Claude Code(Opus 5.5), `docs:policy-manager` 스킬, `Scripts/check-docs.sh`.

## 요청

로그인 정책, 디바이스 관리 정책, 일련번호 부여 방식, 자료 태깅 기능 확정, 폴더링이 정해지지 않았으니 정리해 달라는 요청.

## AI 산출물

- 기존 정책·기획서·명령어 설명서·ADR에서 다섯 주제의 빈 곳과 충돌을 찾은 결과
  - COM-001의 `N번`(고유 번호)과 명령어 설명서의 `고르기 1 3`(목록 위치)이 서로 다른 번호를 뜻함
  - 서버는 토큰의 사용자 ID로 자료를 나누는데 계정(F6)은 P1이고 데모 필수 범위 밖
  - 기획서는 자동 태그를 내부 재료로만 두고 태그·폴더 관리를 "하지 않는 것"에 둠
- 선택지와 추천안 두 차례(주제별 방향, 세부 값)
- 새 정책 영역 계정(ACC)과 자료(ARC), 정책 5건, 영역별 README·CHANGELOG·열린 질문
- 기획서 0.6(F6a 로그인 P0, 데모 필수 범위에 로그인, F2·F12·하지 않는 것 갱신), 명령어 설명서(자료 번호, `#태그`, 묶음 하위 명령, `로그아웃`)
- COM-001 사용자 문구의 N이 ARC-001 번호임을 밝힘

## 사람의 판단

- 자료 번호: 고유 번호 하나만(추천안 채택)
- 로그인: 추천안(익명으로 시작 후 연결)을 고르지 않고 "처음부터 로그인 필수"를 고름. 방식은 Google과 GitHub. 로그인만 P0, 동기화는 P1
- 기기 관리: 추천안(제한 없음, 모든 기기 로그아웃, 연결별 끊기)에 "나중엔 제한을 걸 거라고 기록"을 더함
- 모든 기기 로그아웃은 최대 1시간 안에 반영하고 AI 도구 연결도 끊음
- 태그: 자동 태그를 보이기만, 자료당 최대 5개, 목록에는 3개
- 폴더: 묶음이 폴더 역할, 목록·보기·넣기·빼기·지우기, 이름은 띄어쓰기 없이 1~20자
