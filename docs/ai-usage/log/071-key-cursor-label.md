# 2026-11-26 · 명령 버튼의 `…`을 커서 `_`로 바꾸기

- 작성자: TAENI
- 이슈·PR: (이 PR)
- 커밋: 없음(커밋 전)

> **요약** PO가 모바일 명령 버튼의 `찾기…`에서 `…`이 별로라며 다른 표시를 물었다. AI가 네 가지 안(커서 `_`, 두 줄 버튼, 표시 없음, 모양으로 구분)을 시안 미리보기로 보였다. PO는 커서 `_`를 골랐다. AI가 시안 7개 화면·부품과 기획 문서 두 곳, 결정 로그를 바꿨다.

## 사용 도구

Claude Code(Opus 5.5). 선택지 질문(미리보기), 시안 캔버스(Artifact), Python(문구 바꾸기), `Scripts/check-docs.sh`

## 요청

- `찾기 …`의 `…`이 별로다. 다른 것 없나.

## AI 산출물

- 선택지 4개와 장단점: 커서 `_`(추천, 폭 같음), 두 줄 버튼(친절하지만 44→56px), 표시 없음(깔끔하지만 바로 실행과 구분 안 됨), 모양으로 구분(색·모양만으로 뜻 전달)
- 시안(버전 62): MCommandBar 기본 버튼, M1·M2·M3·M8·M12·I1의 `찾기 _ · 고르기 _`, M2 설명판의 `묶음 _`과 설명 "_ 붙은 것은 이어 치기", M1 안내 "_ 붙은 명령은 뒤를 이어 침", M3 더보기 시트의 `묶음 _ · 버리기 _`
- 문서: [모바일·데스크톱 화면 설계](../../planning/design-mobile-desktop.md) 규칙 2에 `_`의 뜻, [흐름 점검표](../../planning/flow-inventory.md) M1 줄, [STATE](../../planning/STATE.md) 결정 로그 한 줄
- 바꾸지 않은 것: 고른 것 줄의 `묶음…` 버튼(이름 시트를 여는 버튼이라 흔한 "더 묻는다" 뜻), 안내 문장 속 `(AI 앱 · 메모 · …)` 같은 줄임표

## 사람의 판단

- 커서 `_`를 골랐다.
- 시트를 여는 `묶음…` 버튼을 그대로 둔 것은 AI 판단이다. PO 확인 전.

## 검증

- 시안 파일에서 `찾기…` · `고르기…`가 0건인 것을 확인했다.
- `bash Scripts/check-docs.sh`: 통과

## 검증하지 못한 것

1. 바뀐 버튼을 시안에서 다시 열어 보지는 않았다. 글자만 바뀌어 폭은 같다.
