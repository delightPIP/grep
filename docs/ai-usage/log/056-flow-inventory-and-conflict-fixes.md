> **요약** PO가 설치·시작부터 종료까지 사용자 흐름을 글로 모두 적고 없는 화면·과정을 뽑아 달라고 했다. AI가 플랫폼별 흐름 점검표를 만들었고, PO가 어긋남부터 고치라고 한 뒤 스킬을 모두 써서 다시 점검하라고 했다. AI는 다시 점검해 빠졌던 데모 장면과 잘못 매긴 우선순위를 바로잡고, 정책을 기준으로 문서와 시안 12곳을 맞췄다. 결정이 필요한 것은 PO에게 남겼다.

## 사용 도구

Claude Code(Opus 5.5). 스킬 `po-workflow:planning-gap-audit`, `product-design`(harden), `docs:policy-manager`, `po-workflow:decision-propagation`. 서브에이전트 `it-service-planner:planning-critic`(독립 검토). `Scripts/check-docs.sh`, `Scripts/check-stage-sensors.sh`, `Scripts/check-policy-acceptance.sh`. 시안 캔버스 읽기·고치기(Artifact)

## 요청

- 사용자 흐름을 처음부터 끝까지 글로 정리하고, 없는 화면과 없는 과정을 뽑아 달라.
- 문서끼리 어긋난 것부터 고쳐 달라.
- 쓸 수 있는 스킬을 모두 써서 한 번 더 점검해 달라.

- [처음부터 끝까지 사용자 흐름과 빈칸](../../planning/flow-inventory.md): 웹, 모바일 웹·PWA, 데스크톱, iOS, AI 도구 쪽 흐름. 없는 화면 S1~S19, 없는 과정 P1~P20(우선순위 칸 포함), 고친 어긋남 X1~X12, 남은 어긋남 X13~X19, 범위 밖 목록
- 정책: COM-003 알림 버튼을 낱말 `담기 · 무시`로, ARC-001 비고의 번호 범위를 ARC-010에 맞춤. 공통 열린 질문의 북마크 임시값을 200건으로. 각 이력·변경 이력에 적음
- 문서: 흐름도(받지 않는 형식 문구, 끌어 오기 안내, 태그 지우기, 북마크 200건), 설명서(휴지통 명령 세 줄, `고치기 -#태그`, 끌어 오기 안내)
- 시안 9장 수정: 웹 05·07, 모바일 M1·M2·M3·M4·M5, 데스크톱 D4·D5(버리기 1건은 바로 휴지통, 숫자 선택지를 낱말로, 자료 번호를 고유 번호로, 표어, 이미 저장 번호)

## 사람의 판단

- 흐름을 먼저 글로 다 적고 빈칸을 뽑는 순서로 하라고 했다.
- 어긋남부터 고치라고 했다(AI 추천은 발표 전 과정부터였다).
- 스킬을 모두 써서 다시 점검하라고 했다.

## 검증

- `bash Scripts/check-docs.sh`: 통과
- `bash Scripts/check-stage-sensors.sh`: 이 작업 파일의 미결 표기는 고쳤다. 다른 파일(`design-skill-intake.md`)의 기존 표기 1건이 남아 있다
- `bash Scripts/check-policy-acceptance.sh`: 등록된 규칙 없음. COM-003 규칙(기본 꺼짐, 8초)은 버튼 문구와 무관해 바꾸지 않았다
- 기획 비평 에이전트가 이 점검표를 원문과 대조했다. 지적 26건을 반영했다

## 검증하지 못한 것

1. 시안을 렌더링해 보지 않았다. 고친 시안 9장은 코드만 바꿨다.
2. 점검 뒤 캔버스에 다른 작업이 올린 화면(Detail, Archive, MobileArchive)은 검토하지 않았다.

## AI의 오류와 정정

1. 1차 점검표가 데모 장면 몇 개(`도움말` 0건 출력, `최근` 목록, 로그아웃 전환, `! 요약 없음`, 요약 완료 반영)를 빠뜨렸고, 데모에 없는 자세히 보기와 샘플 저장 화면을 "발표 전"으로 올렸다. 다시 점검해 우선순위를 데모 장면 기준으로 바꿨다.
2. 1차 점검표가 COM-004에 이미 있는 받지 않는 형식 문구를 "없다"고 적었고, 정해진 것이 있는 자세히 보기·`보관함`·`고치기`·모바일 로그인을 "아무것도 없음"으로 표시했다. 원문을 다시 대조해 고쳤다.
3. 1차 점검은 시안 4장만 열어 보고 어긋남을 셌다. 다시 점검하며 시안 18장을 모두 열어 숫자 선택지, 목록 위치 번호, 표어 차이를 더 찾았다.
4. 시안을 고치는 중에 다른 작업이 M3를 먼저 고쳐 올렸다. 덮어쓰지 않고 새 판을 다시 읽어 그 위에 고쳤다(M3의 `열기 peek`은 그 작업의 것이라 두었다).
