# 2026-11-26 · 웹 화면 시안 디자이너 검토 대조

- 작성자: TAENI
- 이슈·PR: 없음

> **요약** PO가 받아 온 외부 디자이너의 시안 7장 검토를 AI가 기존 정책(ARC-001, ARC-005, ADR-IOS-009)과 명령어 설명서, 넘길 글 형식에 대조했다. 이미 정해져 시안만 고칠 것, 기존 결정과 부딪혀 PO가 정할 것, 새 제안, 개발 확인, 발표 현장 점검으로 나눠 기획 문서에 남겼다. PO가 기존 결정과 부딪힌 다섯 항목을 추천대로 반영하기로 해서 명령어 설명서·사용자 흐름도·기획서를 고쳤다. 같은 숫자 선택지가 있던 정책 ACC-002·ARC-003과 ARC-002 문구도 PO 승인 뒤 고쳤다.

## 사용 도구

Claude Code(Opus 5.5), `Scripts/check-docs.sh`. 외부 검토는 PO가 다른 곳에서 받아 왔다.

## 요청

디자이너 전문가 첨언을 첨부하며 반영을 요청.

## AI 산출물

- [웹 화면 시안 디자이너 검토](../../planning/design-review-2026-11-26.md): 대조 결과 다섯 묶음, 항목별 기존 결정과 대조 의견
- 명령어 설명서 1·2·4·5·6·8절, 사용자 흐름도, 기획서 엣지 케이스, STATE 결정 로그 수정

## 사람의 판단

- 외부 검토는 첨언으로 보고, PO가 고른 항목만 정책·설명서에 옮긴다(038과 같은 원칙)
- 반영: 확인 답을 숫자 대신 낱말로, 진짜 터미널 명령 받아 실행(`rm`·`copy` 등은 안내만), 첫 화면은 세 명령과 샘플 안내, 찾기 0건 뒤 `(검색 결과 아님)`, 표어 `담기 → 찾기 → 넘기기`
- 샘플 자료의 동작은 자료 영역 열린 질문으로 넘김

## 검증

`bash Scripts/check-docs.sh` 통과. 시안 원본 이미지는 AI가 직접 보지 않았고, 검토자의 서술만으로 대조했다.

## 검증하지 못한 것

1. 검토자가 시안에서 확인했다는 사실(번호 반복, 명령 12줄 등)을 시안 원본과 대조하지 않았다.
