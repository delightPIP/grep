# 2026-11-25 · 모바일과 데스크톱 두더지 화면 시안

- 작성자: TAENI
- 이슈·PR: 없음
- 커밋: 없음(커밋 전)

> **요약** 그렙 터미널 디자인 시스템으로 모바일 화면 5장과 Windows 오른쪽 아래 상주 앱(데스크톱 두더지) 화면 5장을 기존 웹 시안 캔버스에 페이지로 더했다. 정리와 열린 질문은 `docs/planning/design-mobile-desktop.md`에 적었다. PO는 데스크톱 앱에 두더지를 쓰자고 했고, 나머지는 아직 확인 전이다.

## 사용 도구

Claude Code(Claude Opus 5.5), Design 캔버스 아티팩트, 그렙 터미널 디자인 시스템 컴포넌트.

## 요청

PO: 만든 디자인 시스템을 바탕으로 모바일 디자인을 확정하고, 화면 오른쪽 아래에 상시로 띄울 데스크톱 앱은 두더지를 활용하자.

## AI 산출물

- 웹 화면 시안 캔버스에 "모바일" 페이지(M1~M5)와 "데스크톱 두더지" 페이지(D1~D5), 페이지별 규칙 메모
- `docs/planning/design-mobile-desktop.md`: 화면별 내용, 규칙, 열린 질문 5개

## 사람의 판단

- 데스크톱 상주 앱에 두더지를 쓴다(PO)
- 복사한 링크 알림은 기본 꺼짐으로 넣는다(PO). 알림 8초, 이미 저장한 링크는 알리지 않음, 무시한 링크는 앱이 켜져 있는 동안 다시 묻지 않음, 연속 복사는 새 링크로 바꿈을 골랐다. 정책 COM-003로 확정하고 `Scripts/check-policy-acceptance.sh`에 규칙을 더했다
- 모바일 검토(ui-design Audit) 결과 12건 중 1~7번을 반영하기로 했다(PO): 안전 영역, 입력칸 16px, OS 공유 시트로 넘기기, ⋯ 메뉴, 칩 빼기, 공유 시트 자동 닫힘 멈춤, 명령 버튼 4칸
- iOS 공유 시트 구현을 ADR-IOS-009로 기록했다(PO 승인). 대안 6개는 AI가 비교해 채웠다. 이에 따라 M4를 "본문 옴 / 링크만"으로 나누고 M1에 공유 시트 안내를 더했다
- 나머지 데스크톱 동작 규칙은 확인 전이다

## 검증

화면을 렌더링해 눈으로 확인하지 않았다. `bash Scripts/check-docs.sh` 실행.

## 검증하지 못한 것

1. 캔버스에서 각 화면이 깨지지 않는지, 끌어다 놓기와 버튼 동작이 시안에서 되는지 보지 않았다.
2. 데스크톱 상주 앱이 PRD 범위에 없어 우선순위가 정해지지 않았다.

## AI의 오류와 정정

1. 처음 모바일 시안은 웹 화면에 버튼을 붙인 수준이었고(안전 영역·입력칸 확대·OS 공유 시트 빠짐), M4에 "공유된 글을 본문으로 저장"을 항상 되는 것처럼 그렸다. iOS에서는 보내는 앱이 글을 넘길 때만 된다. 검토 뒤 고쳤다.
2. 정책 검사 스크립트에 규칙을 넣을 때 정규식에 보이지 않는 백스페이스 문자가 섞여 검사가 늘 실패했다. 통과·실패 예제로 돌려 보고 찾아 고쳤다.
