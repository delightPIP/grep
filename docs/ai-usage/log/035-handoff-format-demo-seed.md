> **요약** PO가 기획자 시선으로 빠진 문서를 점검해 달라고 했고, AI가 개발·발표 일정 기준으로 10개를 꼽았다. PO가 그중 넘길 글 형식과 데모 시드 자료를 먼저 쓰라고 정해, AI가 두 문서를 제안 상태로 썼다.

## 사용 도구

Claude Code(Claude Opus 5.5), 웹 페이지 확인용 하위 에이전트(WebFetch).

## 요청

기획자 시선으로 PO가 작업해야 할 빠진 문서를 확인해 달라고 했다. 이어서 우선순위 1·2번(넘길 글 형식, 데모 시드 자료)을 써 달라고 했다.

## AI 산출물

- 빠진 문서 점검: 넘길 글 형식, 데모 시드 자료, 웹 계정 결정, 빠진 화면 문구와 정책 값, 겹치는 서비스 사용 기록, 발표 구성안, 데모 대본, overview 갱신, 저니맵 미결 판단, PR #8 후속
- `docs/planning/handoff-format.md`: 태그로 감싼 넘길 글 형식, 칸 규칙, 요약 없을 때 문구, 본문 넣기, 화면·MCP와 맞추기, 정하지 않은 것
- `docs/planning/demo-seed.md`: 결제 주제 데모 이야기, 데모 당일 기준 상대 날짜로 넣는 시드 12건과 무대 저장 2건, 팀이 만들 글·PDF·스크린샷 내용, 장면별 기대 결과, 리허설 전 확인표
- 기획서 8·12절과 사용자 흐름도에 두 문서 링크

## 사람의 판단

- 넘길 글 형식과 데모 시드 자료를 먼저 쓰기로 정함
- 두 문서의 내용은 아직 검토 전

## 검증

시드의 웹 링크 8개 후보를 하위 에이전트로 열어 봤다. 5개는 한국어 공개 페이지로 읽혔고, 카카오페이 문서는 본문이 클라이언트에서 그려져 읽히지 않았으며, 네이버페이 개발자 문서는 자동 접근이 막혀 둘 다 뺐다. 위키백과 항목은 다른 문서로 넘어가 뺐다. `bash Scripts/check-docs.sh`를 실행했다.

## 검증하지 못한 것

1. 넘길 글을 실제 AI 도구에 붙여 넣었을 때 자료를 지시로 오해하지 않는지
2. `찾기 결제` 등 장면별 실제 건수(웹 본문에 달려 있어 시드 후 실측)
3. 넘기기용 요약 400자 안팎이 소형 모델로 나오는지

## AI의 오류와 정정

1. 넘길 글 예시의 제목을 처음에 "결제위젯 연동 가이드"로 지어 썼다. 링크를 확인해 보니 실제 페이지 제목은 "주문서형 결제 연동하기"라 예시를 고쳤다. 명령어 설명서 6절의 같은 예시 문구는 화면 문구 예라서 그대로 뒀다.
