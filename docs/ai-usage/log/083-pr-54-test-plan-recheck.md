## 검증하지 못한 것

1. 같은 이메일로 Google·GitHub에 로그인했을 때 계정이 둘로 남는지(ACC-001 규칙 4). 같은 이메일을 쓰는 계정 쌍이 있어야 한다.
2. `app_metadata.provider`가 처음 가입한 방식으로 굳는지. 두 계정이 서로 다른 사용자라 가려지지 않는다.
3. 비밀번호를 아는 상태에서 GitHub 계정 전환에 걸리는 전체 시간.
4. Chrome 항목은 개발자 보고이고 AI가 화면을 보지 못했다. `✗ 로그인 취소됨`이 뜨기까지 걸린 시간은 재지 않았다.
5. 이번 순서에서는 로그아웃 전에 출력 줄이 없어 "전환 뒤 이전 출력이 안 보임"을 다시 보지 못했다(AI 로그 081의 Safari 결과 그대로).
6. `cd server && ./gradlew test`. 이 Mac에 Docker가 없다. PR에는 Windows 결과로 체크돼 있다.

## AI의 오류와 정정

1. "이미 로그인된 계정을 고르는 클릭은 AI가 할 수 있다"고 했다. 앱 내장 브라우저는 AI의 입력으로 열리는 팝업을 막아서 로그인 버튼을 누를 수 없었다. 정정하고 클릭을 개발자에게 넘겼다.
2. GitHub 로그인 창에서 걸린 116.7초를 보고 "2분 시간 초과에 걸릴 수 있다"고 경고했다. 개발자가 비밀번호를 찾느라 걸린 시간이라고 알려 경고를 거뒀다.
3. Supabase authorize 주소로 `?attempt=`의 허용 여부를 가리려 했으나, 등록되지 않은 주소도 그대로 받아 줘서 판정하지 못했다. 실제 로그인의 콜백으로 확인했다.

## 발견 사항

1. 브라우저가 팝업을 막으면 그렙은 `✗ 로그인 실패: 권한 거부`로 표시한다. AI의 클릭이 막혔을 때 확인됐다.
2. 로그아웃해도 서버 `sessions` 행은 남는다. 조회 시점에 사용자 2명, 세션 7행이었다. 만료 판정에만 쓰여 동작에는 영향이 없다.
