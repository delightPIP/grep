# 2026-11-25 · PO 메모 대응과 범위, 글자 읽기, 같은 링크 정책

- 작성자: @carti1108
- 이슈·PR: #3, #4
- 커밋: f371394

> **요약** PO 메모(F21, F16, 발표 일정)에 답하기 위해 범위, 이미지 글자 읽기 방식, 같은 링크 판정 기준을 정했다. 범위는 P0와 P1 전부에 F21을 더하고 클라이언트는 웹부터 만들기로 했다. 글자 읽기는 ADR-BCK-005, 같은 링크 기준은 정책 COM-001로 남겼다.

## 사용 도구

Claude Code(Claude Opus 5.5), 웹 검색, GitHub CLI, docs 플러그인(adr-manager, policy-manager, ai-usage).

## 요청

PR #3에 올라온 PO 메모를 확인하고, 각 플랫폼의 글자 인식 방법을 조사하고, PR #3 코멘트를 수정해 다시 올리되 올리기 전에 초안을 보여 달라고 했다.

## AI 산출물

- 플랫폼별 기기 안 글자 인식 조사: iOS Vision, Android ML Kit, Windows.Media.Ocr, 웹 TextDetector, Tesseract
- 이미지 글자 읽기 방식 비교(LLM 비전, Tesseract, 기기 안 인식, 클라우드 OCR)와 비용 추정
- 같은 링크 판정 방식 비교(규칙 정규화, 리다이렉트 따라가기, 대표 주소, 내용 비교, 완전 일치)
- ADR-BCK-005, 정책 COM-001, 수정한 PR #3 코멘트 초안

## 사람의 판단

- 서버를 포함해 P0와 P1을 모두 만들고, 클라이언트는 웹부터 만든다. 웹 먼저는 ADR로 쓸 만한 결정이 아니라고 판단함
- 글자 읽기: 서버 LLM 비전을 기본으로, 모바일은 기기 안 인식 결과를 함께 보내는 안을 채택함
- 같은 링크: 규칙 정규화로 시작하고, 리다이렉트와 대표 주소 판정은 나중에 붙일 것으로 정책에 적어 두라고 함
- 정책의 열린 항목(`http`·`www` 동일 취급, `#/` 유지, 같은 파일 포함)은 AI 제안대로 확정함
- 초안 확인 없이 PR과 코멘트를 올린 것을 지적하고, 앞으로 올리기 전에 초안을 보여 달라고 함

## 검증

플랫폼별 글자 인식 지원은 공식 문서와 개발자 포럼 검색으로 확인했다. `bash Scripts/check-docs.sh`를 실행했고 통과했다. 코드는 없어 빌드와 테스트는 하지 않음.

## 검증하지 못한 것

1. iOS Vision API의 한국어 지원 최소 버전(iOS 18.1에서 확인했다는 보고만 있음)
2. Windows OCR의 한국어 언어 팩 이름과 지원(공식 문서에서 찾지 못함)
3. LLM 비전의 한국어 스크린샷 인식 품질과 실제 비용

## AI의 오류와 정정

1. PR #4와 PR #3 코멘트를 본문 초안 확인 없이 올렸다. 개발자가 지적했고, 이후로는 초안을 먼저 보여 주고 승인 뒤 올리기로 했다.
2. PR #3 코멘트를 쓸 때, 그보다 먼저 올라온 PO 메모(발표 12월 1일, F21·F16 질문)를 읽지 않았다. 그래서 PO의 질문에 답하지 않았고, "범위와 첫 플랫폼은 아직 정하지 않았다"고 써 시안 일정을 막는 답이 됐다. 수정 코멘트로 바로잡는다.
3. 글자 읽기에서 비용 0을 우선해 서버 Tesseract를 먼저 추천했다. LLM 비전 비용이 이미지당 약 0.4원으로 작다는 계산을 한 뒤 추천을 바꿨다.
