## 검증하지 못한 것

1. wasm 빌드와 `npm run build`는 하지 않음(Windows에서 안 됨). 브리지 수정은 Mac에서 컴파일 확인이 필요하다
2. 브라우저 장면(저장, 크기 초과, L1 → 30번, 붙여 넣기 한 번에 저장 한 번)은 하지 않음
3. 실제 Supabase Storage 연결은 하지 않음(#55 키 대기)
4. 갈래 세 곳의 작업 내용 자체(서버·코어·브리지 구현)는 이 기록이 다루지 않는다. 각 갈래의 AI 활용 기록은 아직 없다

## AI의 오류와 정정

1. W2 작업 중 현재 브랜치를 확인하지 않아, W2 테스트 변경이 같은 폴더에서 W1 세션이 쓰던 `feat/57-server` 작업 트리에 섞였다. 사용자가 브랜치를 물어 알았다. 변경을 패치로 떠서 `feat/57-core` 워크트리로 옮기고 원래 폴더에서는 그 파일만 되돌렸다. 서버 파일은 건드리지 않았다
2. bridge 핸드오프에 줄 종류를 25개로 잘못 적었다가 23개로 고치는 커밋을 더했다

## 발견 사항

1. 한 폴더를 두 세션이 쓰면 브랜치 전환이 서로에게 보이지 않는다. 갈래마다 워크트리를 따로 두어야 한다
2. 코어 계약을 Windows(W2)에서 바꾸면 Mac(M) 브리지는 통합 때까지 그 변경을 모른다. 계약 변경은 #56 같은 공용 이슈에 바로 알리는 편이 낫다
