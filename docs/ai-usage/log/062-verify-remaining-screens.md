# 2026-11-26 · 부품으로 바꾼 화면 나머지 열어 보기

- 이슈·PR: #25
- 커밋: 없음(커밋 전)

> **요약** 061에서 열어 보지 못한 화면을 PO가 확인해 달라고 했다. AI가 시안에서 C9·C10 카탈로그, 데스크톱 D2~D11, 웹 09·24·28을 차례로 열었다. 화면은 모두 공통 부품으로 그려졌다. 카탈로그 C9·C10은 보드가 짧아 아래 예시가 잘렸고, 길어진 C9가 "부품 원본" 제목을 덮었다. 이 둘을 고쳤다.

## 사용 도구

Claude Code(Opus 5.5). 내장 브라우저(시안 캔버스 열기·확대), 시안 캔버스(Artifact), Python 스크립트(카탈로그 생성, 보드 배치), `Scripts/check-docs.sh`

## 요청

- 확인 못 한 화면도 열어서 확인해 달라.

## AI 산출물

- 확인: 데스크톱 D2~D11(바탕, 다른 앱 창, 놓는 곳, 두더지, 로그 카드, 트레이 메뉴, 설정 창, 작업 표시줄), 웹 09(자세히 보기 블록 2개), 24(연결 승인 카드 4장면), 28(아이콘 레일과 자세히 보기 칸)
- 고침: C9 데스크톱 부품 보드 높이 2700 → 3100(DDropHint·DDropTarget 예시가 잘림), C10 넓은 웹 부품 보드 높이 2400 → 3600(ItemDetailPanel 예시가 잘리고 ItemDetail·UiSettingRow 카드가 보이지 않음), "부품 원본" 제목과 부품 원본 줄을 C9·C10 아래로 내림
- main에 들어온 AI 활용 기록 055와 번호가 겹쳐, 이 PR의 기록을 056~061로 옮김

## 사람의 판단

- 열어 보지 못한 화면을 확인하라고 정했다.

## 검증

- 내장 브라우저로 위 화면을 50~89% 배율로 열어 부품이 그려진 것을 봤다. D5는 처음 찍었을 때 두더지·작업 표시줄이 안 보였으나, 그려지기 전에 찍힌 것이었고 다시 보니 있었다.
- 높이를 고친 뒤 C9를 다시 열어 마지막 카드(DDropTarget 점선 칸)까지 보드 안에 들어온 것을 확인했다.
- `bash Scripts/check-docs.sh`: 통과

## 검증하지 못한 것

1. 화면의 누르는 동작(시트 열기, 고르기, 뒤로 가기)은 눌러 보지 않았다. 캔버스가 축소된 상태에서는 보드 안 클릭이 전달되지 않았다.
2. C10은 높이를 3600으로 늘린 뒤 다시 열어 보지 않았다(3400에서 마지막 카드가 보드 끝에 걸려 200을 더함).
3. 28 보드는 두 장면이 한 줄에 들어가 아래가 비어 있다. 모양 문제라 그대로 뒀다.
