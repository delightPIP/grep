## 검증

- `cd web && npm test`: 이슈마다 실행, 마지막 283개 통과(9개 파일)
- 새 테스트는 구현 전에 실패하는 것을 먼저 확인했다
- `npx tsc --noEmit`: 이번에 고친 파일에는 오류 없음. `support/swift.ts`·어댑터의 오류는 이 워크트리에 Swift Wasm 빌드 산출물(`.build`)이 없어 나는 것으로, 이번 변경과 관계없다
- 서버(`./gradlew test`)·코어(`swift test`)·브라우저 실측: 하지 않음(뷰 갈래 범위 밖)

## 검증하지 못한 것

1. 브라우저에서 실제로 그려 보지 않았다. 자세히 보기 격자, 이미지 미리보기 크기, 이름 목록 줄(`gt-name-row`)의 폭은 CSS만 쓰고 눈으로 확인하지 않았다.
2. 새 계약 필드(`isSavedSearch`, `url`, `sub`, `related`)는 서버(W1)와 코어(M)가 채워야 동작한다. 연결된 상태로 확인하지 않았다.
3. 웹 보관함 화면이 없는데 찾아두기 결과에 `· 보관함 저장한 찾기에 있음`을 정책대로 보인다.
4. 서버·코어 테스트와 Swift 빌드를 돌리지 않았다.

## AI의 오류와 정정

1. 묶음 목록 줄을 처음에 자료 목록 격자(`gt-row`, 번호 칸 5ch)로 그렸다. 묶음 이름이 번호 칸에 들어가 줄이 깨지는 구조라, #134에서 이름 목록 공용 줄(`gt-name-row`)로 바꿨다.
2. 첫 테스트에서 줄 값을 `as const`로 만들어 읽기 전용 배열이 계약 타입과 맞지 않는 `tsc` 오류를 냈다. `TerminalLine` 타입을 붙여 고쳤다.
3. 셸 heredoc 안에 패치 스크립트를 넣다가 따옴표 해석 오류로 아무것도 적용되지 않았다. 편집 도구로 다시 적용했다.
4. #134 찾기 결과 칩을 넣자 기존 찾기 결과 테스트 2개가 마지막 줄을 `→ 더 보기`로 기대해 실패했다. 칩이 정책(ARC-012 규칙 9)상 맞는 동작이라 기존 테스트의 기대값을 고쳤다.
