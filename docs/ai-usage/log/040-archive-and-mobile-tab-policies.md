# 2026-11-26 · 보관함·모바일 탭 정책과 시안의 하단 탭

- 작성자: TAENI

> **요약** 학습 노트에서 남긴 PO 질문 가운데 보관함 구성과 설정 위치를 정책으로 정했다. 보관함은 ARC-007(자동 묶음·묶음·저장한 찾기, 따로 폴더 없음), 모바일 탭은 새 모바일 영역의 MOB-001(터미널 · 보관함 · 설정, 설정은 탭)이다. 같은 규칙대로 모바일 시안 M1·M3에 하단 탭을 그렸다.

## 사용 도구

Claude Code(Claude Opus 5.5), `docs:policy-manager` 스킬, Design 캔버스 아티팩트(그렙 웹 화면 시안), 그렙 터미널 디자인 시스템.

## 요청

- 보관함은 자동 묶음만으로 정책을 써 달라고 했다.
- 설정은 탭으로 두는 정책을 써 달라고 했다.
- 모바일 시안에 탭바를 그려 달라고 했다.
- 디자이너 검토에서 나온 칩 번호 표기를 시안과 원본 디자인 시스템에서 고쳐 달라고 했다.

## AI 산출물

- `docs/policies/archive/ARC-007-archive-auto-groups.md`, 자료 영역 변경 이력과 정책 목록
- `docs/policies/mobile/`(README, CHANGELOG, open-questions, MOB-001), 정책 목록의 영역 표
- 시안 M1(첫 화면)에 하단 탭, M3(찾기)에 고르기 전 상태의 하단 탭, 캔버스 모바일 규칙 메모 8번
- 디자이너 검토 A1 반영: 칩 번호 앞 `#`을 뺐다(ARC-001 규칙 12). 시안 캔버스의 Chip 컴포넌트와 M3 칩, 원본 디자인 시스템(그렙 터미널)의 Chip과 설명
- `design-mobile-desktop.md` 규칙 1과 M1·M3 행, 학습 노트의 해결된 질문 표시

## 사람의 판단

- 보관함 묶는 기준을 형식·출처·날짜·자동 태그로 정하고, 자동 태그 묶음을 보여 주기로 했다. 저장한 찾기를 넣고, 태그 편집은 이번 단계에서 두지 않기로 했다.
- main에 ARC-002·ARC-003이 먼저 확정된 것을 알고, 처음 쓴 COM-003 초안을 버리고 ARC-007로 다시 쓰기로 했다.
- 하단 탭은 터미널 · 보관함 · 설정, 늘 터미널에서 시작, 키보드·시트·고르기 중·로그인 전에는 숨김, 상태 유지, 배지 없음으로 정했다.

## 검증

`bash Scripts/check-docs.sh` 통과. 시안은 캔버스에 올렸지만 렌더링해 눈으로 확인하지 않았다.

## 검증하지 못한 것

1. 시안 M1·M3에서 하단 탭이 깨지지 않는지, M3에서 모두 해제하면 탭이 나타나는지 보지 않았다.
2. 키보드·입력줄·탭바가 함께 있을 때의 실제 기기 동작(MOB-001 검증 방법).

## AI의 오류와 정정

1. 보관함 정책을 처음에 COM-003으로 커밋했는데, main에서 그 번호와 같은 주제(ARC-002·003)가 이미 쓰이고 있었다. 리베이스 충돌로 알게 되어 최신 main에서 새 브랜치를 만들고 ARC-007로 다시 썼다. 폴더 입력 안내 문구도 ARC-003에 맞춰 묶음으로 안내하게 바꿨다.
