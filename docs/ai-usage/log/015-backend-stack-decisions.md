- 서버 언어에서 Swift를 제외함
- 클라이언트는 플랫폼별 뷰와 공유 코어로 만들 계획임을 밝힘(공유 코어는 Swift 후보, 결정은 보류)
- "프론트와 백엔드는 서로 무엇을 쓰든 상관없게 설계해야 한다"고 지시함. 이에 따라 ADR-0001이 나옴
- Rust를 비교에 다시 넣으라고 요청함
- 저장 경로가 공유 시트만이 아니라 링크, 이미지, md 등 여러 파일임을 정정함
- 4개 결정을 채택함(추천안 그대로)
- 요약 방식과 호스팅은 나중에 정하기로 보류함
- PR #3에는 리뷰 코멘트로 답하고 ADR은 스택 PR로 올리기로 정함
- ADR 초안에서 개발자 개인의 경력 서술을 빼라고 고침(ADR-BCK-004 배경은 유지)

## 검증

`bash Scripts/check-docs.sh`를 실행했다(결과는 근거 링크의 PR에 적는다). 라이브러리 현황(Apache Tika, MCP Kotlin SDK)은 웹 검색으로 확인했다. 코드는 아직 없어 빌드와 테스트는 하지 않음.

## 검증하지 못한 것

1. MCP Kotlin SDK가 원격 MCP용 OAuth를 지원하는지 확인하지 못했다. 스파이크가 필요하다.
2. 관리형 DB와 호스팅 서비스의 가격과 무료 한도는 2차 출처(검색 결과) 기준이고, 출처끼리 엇갈리는 부분이 있었다.
3. 한국어 자료 요약을 소형 모델로 해도 품질이 충분한지 확인하지 않았다.

## AI의 오류와 정정

1. Rust의 학습 비용만 강조하고 Swift와 타입 시스템이 가깝다는 점을 빠뜨렸다. 개발자의 질문을 받고 비교를 고쳤다.
2. carti-RIBs-Swift를 보기 전에 Swift의 Android와 웹 지원을 "젊다", "웹 바이너리 최대 50MB"로 평가했다. 레포의 실측(웹 gzip 2.81MB, Android 계측 테스트 통과)을 보고 정정했다.
3. "넘길 글은 Swift 공유 코어만 만든다"고 제안했는데, 이는 프론트 구현에 기댄 설계였다. 개발자 지적 후 서버 엔드포인트로 바꿨다(ADR-0001 결정 4).
4. 서버 언어로 처음에는 Python을 추천했다. 개발자의 기존 프로젝트를 확인한 뒤 Kotlin으로 바꿨다.
5. 저장 경로를 공유 시트 중심으로 가정했다. 개발자가 정정했다.
