> **요약** PO가 개발 전반 흐름을 담은 개발 스킬을 만들려고 개발자 첨삭 자료 3건(각각 1~8단계)을 넘겼고, AI가 다 받은 뒤 세 자료가 공통으로 말한 규칙 8개, 갈린 지점과 추천, 그렙과 부딪히는 점을 수집 노트에 정리했다. 스킬은 아직 쓰지 않았고 위치·범위·1차 범위·문서 ID는 PO 결정 대기다.

## 사용 도구

Claude Code(Opus 5.5), `Scripts/check-docs.sh`

## 요청

- 개발 전반 흐름을 담은 개발 AI 스킬을 만들고 싶으니, 개발자 첨삭 내용을 보고 어떻게 만들지 고민해 달라.
- 자료는 다 받고 한 번에 정리해 달라. 정리한 뒤: 수집 노트부터 남겨 달라.

## AI 산출물

- [개발 스킬 수집 노트](../../planning/dev-skill-intake.md): 자료 C1·C2·C3마다 가져갈 것·그렙에 맞게 바꿀 것·버릴 것, 세 자료가 공통으로 말한 규칙 8개, 갈린 지점 표, 최종 합본 계획(입구 스킬 + 새로 쓸 단계 + 기존 스킬로 넘길 단계), 그렙 팀 설정 메모, 정할 것 4개

## 사람의 판단

- 자료는 세 건이며 "끝"으로 수집을 마쳤다.
- 받는 중에는 짧게만 답하고 다 받은 뒤 한 번에 정리하기로 했다.
- 정리 뒤 디자인 스킬 때처럼 수집 노트부터 남기기로 했다(AI 추천안 수용).
- 스킬 위치·범위·1차 범위·문서 ID 체계는 아직 정하지 않았다.

## 검증

- `bash Scripts/check-docs.sh`: 통과.

## 검증하지 못한 것

- 기존 스킬(`tdd-integrity`, `google-eng-review-standards`, `diagnosing-bugs` 등)이 고정 핵심 규칙을 지키는지는 본문을 열어 보지 않아 확인하지 않았다.
- 첨삭 자료에 인용된 외부 출처(Scrum Guide, Nygard ADR, Apple·Google·Microsoft 배포 문서, WCAG 등)는 원문으로 확인하지 않았다.
- Claude Code 스킬이 자기 폴더 밖 공용 파일을 읽을 수 있는지 확인하지 않았다.

## AI의 오류와 정정

- 수집 중 C3의 2단계가 C1 자리에 섞여 들어온 것을 AI가 "C1이 1단계에서 정한 가상 예시를 2단계에서 스스로 바꿨다"는 환각 신호로 잘못 해석했다. PO가 섞였다고 알려 주어 지적을 철회했고, 다시 받은 C1은 1~8단계가 일관됐다.
