> **요약** 그렙을 모르는 디자인 전문가에게 시안 첨삭을 부탁할 프롬프트를 쓰고, 함께 보낼 시안 18장을 2배 해상도 이미지로 렌더해 저장했다.

## 사용 도구

Claude Code(Claude Opus 5.5). 내장 브라우저, Playwright(로컬 렌더), Python 정적 서버.

## 요청

PO가 서비스를 모르는 디자인 전문가에게 물을 수 있게 서비스 설명 프롬프트를 만들어 달라고 했고, 이어 함께 보낼 시안 이미지를 캡처해 달라고 했다.

## AI 산출물

- `docs/planning/design-review-prompt.md`: 서비스 한 줄, 문제 가설, 해결 방식, 화면 컨셉과 정해진 것, 걱정 다섯 가지, 답변 형식을 담은 복사용 프롬프트와 첨부 이미지 표
- `docs/planning/design-review-shots/`: 웹 8장(2560×1604), 모바일 5장(780×1688), 데스크톱 5장(2560×1600). 시안 캔버스 버전 25 기준

## 사람의 판단

- 브라우저 창 캡처는 해상도가 낮아, 시안 캔버스 파일을 이 컴퓨터에서 렌더하는 방식을 PO가 허용함
- PR을 올린 뒤 프롬프트를 #18, #19의 결정에 맞춰 고치라고 함

## 검증

- `bash Scripts/check-docs.sh` 통과
- 렌더 중 페이지 오류 없음. 다시 렌더한 첫 화면과 모바일 찾기를 열어 버전 25 내용(한 문장 소개, `담기 → 찾기 → 넘기기`, 샘플 8건)을 확인함
- 프롬프트의 바뀐 내용은 STATE 결정 로그(2026-11-26)와 디자이너 검토 문서에 대조함

## 검증하지 못한 것

- 인터랙티브 시안(웹 Play, 데스크톱 D5)은 첫 상태만 찍혔다
- 모바일·데스크톱 시안은 첫 검토 반영 전이라 프롬프트에 그렇게 밝혔다. 시안 자체는 고치지 않았다

## AI의 오류와 정정

1. 처음 캡처는 이 세션 앞부분에 내려받아 둔 옛 시안 파일로 렌더해서, 첫 검토 반영(캔버스 버전 25) 전의 화면이었다(표어 `저장 → 찾기 → 넘기기`, 명령 13줄 첫 화면). 프롬프트를 고치다 이미지를 열어 보고 알았고, 살아 있는 캔버스를 다시 내려받아 18장을 다시 렌더했다.
2. 프롬프트를 #18, #19 머지 전 문서로 썼다. PO 요청으로 확인 낱말화, 진짜 명령 받아 주기, 첫 화면, 칩, 글꼴 분리, 데모 이야기를 반영하고 "이미 한 번 받은 검토" 절을 더했다.

## 발견 사항

1. 모바일 M3의 선택 칩 줄에서 두 번째 칩이 오른쪽 끝에서 잘린다. 캡처 오류가 아니라 시안 자체의 모습이다.
