> **요약** PO 역할과 디자이너 역할의 AI 에이전트 둘이 po-workflow 스킬 일곱 개를 나눠 썼다. 4라운드 동안 서로 피드백을 주고받으며 바로 고쳐, 빈칸 점검·설문 검증·결정 전파 검증·결정 질문·AI 기능 UX 설계·검토 대조·개발 전달 문서를 만들었다. 실제 PO는 아직 아무것도 고르지 않았다. 모든 판단은 AI 제안이다.

## 사용 도구

Claude Code(Claude Opus 5.5). 오케스트레이터 하나와 백그라운드 서브에이전트 둘(PO, 디자이너). po-workflow 플러그인 0.3.0의 planning-gap-audit, survey-tally, decision-propagation, po-decision-gate, ai-ux-design, review-triage, dev-handoff-docs.

## 요청

PO가 자신이 만든 po-workflow 스킬을 모두 써서 PO와 디자이너에게 필요한 산출물을 만들어 달라고 했다. 두 에이전트가 따로 일하되 서로 피드백을 주고받아 바로 반영하고, 모든 작업이 끝나면 스킬별 결과물 목록으로 알려 달라고 했다.

## AI 산출물

- [협업 산출물 폴더](../../planning/collab-2026-11-26/README.md)의 문서 01~08과 상태 보드 HTML. 스킬별 대응과 라운드별 피드백은 그 폴더의 README에 있다
- 기존 기획 문서 수정 7곳(user-flow 3곳, PRD, overview, presentation-notes, survey-result 제목). 모두 이미 확정된 PO 결정이 덜 반영된 곳이다

## 사람의 판단

- 이 작업에서 사람이 고른 것은 없다. PO가 맡기고 자리를 비웠다
- 차단 질문 6개, 승인 2개, 확인 2개는 실제 PO의 답을 기다린다(04 문서)

## 검증

- `bash Scripts/check-docs.sh` 통과
- `bash Scripts/check-stage-sensors.sh` 통과
- 에이전트들이 서로의 지적을 원문 파일:줄로 다시 열어 확인했다. 디자이너 지적의 인용 줄 번호 두 곳이 틀렸고(내용은 맞았음), PO가 바로잡았다

## 검증하지 못한 것

1. 설문 "실패 8건 중 6건이 대략 언제를 기억"은 표로 세면 5건이다. 응답 시트 원자료가 저장소에 없어 확인하지 못했다
2. 시험 TC-01~27과 AI 품질 평가는 실행하지 않았다. 저장소에 앱 코드가 없다
3. 웹 시안과 PR #21의 캡처는 이 문서들과 대조하지 않았다
4. 상태 보드의 색은 디자인 시스템 "그렙 터미널"의 원본 토큰을 찾지 못해 임시 값으로 썼다

## AI의 오류와 정정

1. 디자이너가 처음에 요약 없음 칸의 이름을 새로 만들었다. PO 피드백을 받고 handoff-format·ARC-004·ARC-005의 원본 문구로 되돌렸다
2. 디자이너가 가정에 기댄 상태를 "정의함"으로 표시했다. PO 지적을 받고 "일부 정의"로 낮췄다
3. 두 에이전트가 PO 결정을 바꾸는 질문의 AI 추천안을 `[가정]`으로 설계에 먼저 넣었다. 4라운드에서 규칙을 정했다. PO가 답하기 전까지는 현행 원문을 기본값으로 쓴다

## 발견 사항

1. 열린 PR #20과 #21이 AI 로그 번호 046을 같이 쓴다. 이 로그는 겹치지 않게 048을 썼다
2. 결정 질문이 여러 라운드를 거치면 번호가 바뀐다. 04 끝의 번호 대응표가 없었다면 05·06·08의 참조가 어긋났을 것이다. po-decision-gate에 "질문 번호를 다시 매기면 대응표를 남긴다"를 더할 후보다
3. "이전 PO 결정을 바꾸는 질문은 답 전까지 현행 원문을 기본값으로 한다"는 규칙은 dev-handoff-docs와 ai-ux-design 양쪽에 Gotcha로 더할 후보다
