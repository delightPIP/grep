# 2026-11-27 · #57 브라우저 확인과 CORS 허용 헤더 수정(M)

> **요약** AI가 #72 저장 장면을 브라우저에서 확인하다가 서버 CORS가 `Idempotency-Key`를 허용하지 않아 저장이 전부 막히는 것을 찾아 고쳤다. 사람은 서버를 Docker로 띄우기로 정하고, 수정 진행과 이슈 댓글 게시를 승인했다.

## 사용 도구

Claude Code(Claude Fable 5.2). swift(Wasm), npm, Docker(JDK 21 컨테이너), gh, 내장 브라우저.

## 요청

핸드오프의 1순위인 #72 브라우저 확인을 시작해 달라는 요청. 이어서 CORS 수정 진행, 댓글 초안 확인 뒤 게시를 요청.

## AI 산출물

- `SecurityConfig.kt`: CORS 허용 헤더에 `Idempotency-Key` 추가
- `SaveItemApiTest.kt`: `/items` 사전 요청이 그 헤더를 허용하는지 보는 테스트 1개
- #57·#58에 장면별 확인 결과 댓글
- `server/.env`에 스토리지·LLM 키 양식 추가(값은 사람이 채움)

## 사람의 판단

- 이 Mac에 JDK가 없어 서버를 Docker로 띄우기로 정함
- CORS 수정을 새 브랜치에서 진행하라고 지시
- 댓글 초안을 본 뒤 그대로 올리라고 지시
- `GEMINI_MODEL`은 AI가 고르라고 맡김(AI가 `gemini-3.5-flash-lite`로 넣음)

## 검증

- 새 테스트가 수정 전에 실패(20개 중 1개)하는 것을 확인한 뒤 수정
- 서버 `./gradlew test` 74개 통과(Docker)
- 브라우저: 링크·글·PDF 저장, 같은 링크 중복 알림, 20MB 초과, 붙여 넣기 한 번에 저장 한 번, 명령을 치던 중 붙여 넣기 통과

## 검증하지 못한 것

1. 휴지통 분기(삭제 명령·API 없음), 같은 파일 다시 올리기, 시드 L1 → 30번 알림
2. 받지 않는 형식(.exe)은 스토리지가 415로 막아 `서버 오류`로 나옴. 정책 문구와 맞는지는 정하지 않음
3. 붙여 넣기·끌어다 놓기는 페이지에서 이벤트를 만들어 보냄. 실제 키 입력·마우스 끌기는 아님
4. Gemini 무료 한도는 공개 문서에 모델별 수치가 없어 비교하지 못함
5. CI는 PR을 열지 않아 돌지 않음

## AI의 오류와 정정

1. Wasm 빌드를 Xcode 기본 툴체인으로 돌려 `Foundation` 모듈 버전 불일치로 실패했다. `TOOLCHAINS`로 6.4.2 툴체인을 골라 통과시켰다
2. 명령을 치던 중 붙여 넣기를 확인할 때 입력이 입력줄에 들어가지 않은 채 붙여 넣어 링크가 저장됐다. 입력줄 값을 확인하고 다시 해 저장되지 않음을 봤다
3. 서버 컨테이너와 테스트 컨테이너가 Gradle 캐시를 같이 써 잠금 오류가 났다. 서버를 내리고 다시 돌렸다
4. 서버를 띄우면서 공유 Supabase DB에 `V2__items_jobs` 마이그레이션이 적용됐다. 띄우기 전에 알렸지만 따로 확인을 받지는 않았다
