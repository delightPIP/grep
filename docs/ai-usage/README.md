# AI 활용 기록

이 디렉터리는 그렙 프로젝트를 진행하는 동안 AI를 어떻게 사용했는지를 남기는 곳이다. 기업 등 외부에서 AI 활용 이력을 요구할 때 제출할 수 있도록, 작업 중에 그때그때 쌓는다.

## 파일

| 파일 | 역할 |
|---|---|
| `README.md` | 기록 원칙과 항목 형식 (이 문서) |
| `log/` | 시간순 로그. 단계가 끝날 때마다 항목 파일을 하나씩 추가한다 |
| `REPORT.md` | 로그를 집계한 제출용 요약 |

## 기록 원칙

1. **append-only**: 한 번 쓴 항목의 내용(단어)은 고치지 않는다. 정정이 필요하면 새 항목 파일로 덧붙인다. 형식(제목 줄, 빈 줄, 목록 기호와 들여쓰기, 라벨을 제목으로 바꾸기)만 고치는 것은 허용한다. 이때 변경 전후의 단어 열이 같아야 한다.
2. **사람과 AI를 구분**: AI가 제안·생성한 것과 사람이 결정·수정·거부한 것을 분리해서 적는다.
3. **소급 기록 표시**: 기록 체계를 만들기 전의 작업은 제목에 "(소급 기록)"을 붙인다.
4. **비밀 정보 제외**: 토큰, 키, 비밀번호, 이메일 같은 개인 정보는 기록하지 않는다.
5. **요약 우선**: 요청 원문은 요약을 기본으로 하고, 핵심 결정이 담긴 발언만 짧게 인용한다.

## 항목 형식

작업 단위마다 `log/` 안에 새 파일 하나를 만든다. 파일명은 `NNN-<영문-슬러그>.md`이고 파일의 첫 줄(제목)은 `# 날짜 · 단계명`이다. 만든 뒤 [log/README.md](log/README.md)의 목록 표에 한 줄을 추가한다.

번호는 파일을 만들기 직전에 현재 브랜치의 `log/`, `origin/main`의 `log/`, 열린 PR이 추가한 로그 파일을 모두 본 최대 번호 + 1로 정한다. 그래도 번호가 겹치면 먼저 머지된 쪽이 번호를 갖고, 머지되지 않은 쪽만 파일명·목록 표 번호를 다시 매긴다. 이미 `main`에 들어간 로그는 고치지 않는다.

형식의 원본은 [templates/ai-log.md](../templates/ai-log.md)다. 아래 예시는 그 요약이며, 둘이 다르면 `templates/ai-log.md`를 따른다.

제목 아래에 `- 작성자:`, `- 이슈·PR:`, `- 커밋:` 세 줄을 쓰고, 이어서 `> **요약** <두세 문장>`을 쓴다(무엇을 했고 사람이 무엇을 결정했는지).

항목 본문은 제목(`## 필드`)으로 구분한다. 필드 이름과 내용을 같은 줄에 붙이지 않고, 여러 항목은 목록으로 쓴다. 빈 줄을 항목 사이에 둔다.

```markdown
# 2026-10-19 · 단계명

- 작성자: @계정 또는 이름
- 이슈·PR: #번호 (없으면 "없음")
- 커밋: 짧은 SHA (없으면 "없음(커밋 전)")

> **요약** 무엇을 했고, 사람이 무엇을 결정했는지 두세 문장으로 쓴다.

## 사용 도구

도구, 모델, 사용한 플러그인/스킬.

## 요청

사용자가 무엇을 요청했는지 요약.

## AI 산출물

- AI가 만든 것: 파일, 명령, 제안

## 사람의 판단

- 사용자가 결정·수정·거부한 것

## 검증

빌드, 테스트, 리뷰 여부와 결과. 하지 않았으면 "하지 않음".

## 근거 링크

커밋 SHA, Issue/PR 번호. 없으면 "없음(커밋 전)".
```

| 제목 | 내용 | 필수 |
|---|---|---|
| 작성자 (제목 아래 목록) | 로그를 쓴 사람의 GitHub 계정 또는 이름 | 예 |
| 이슈·PR, 커밋 (제목 아래 목록) | 연결된 이슈·PR 번호와 커밋 SHA. 없으면 "없음" | 예 |
| 요약 (`> **요약**` 인용) | 두세 문장으로 한 일과 사람의 결정 | 예 |
| 사용 도구 | 도구, 모델, 사용한 플러그인/스킬 | 예 |
| 요청 | 사용자가 무엇을 요청했는지 요약 | 예 |
| AI 산출물 | AI가 만든 것: 파일, 명령, 제안 | 예 |
| 사람의 판단 | 사용자가 결정·수정·거부한 것 | 예 |
| 검증 | 빌드, 테스트, 리뷰 여부와 결과 | 예 |
| 검증하지 못한 것 (있을 때만) | 확인하지 못한 부분과 남은 위험 | 있을 때 |
| AI의 오류와 정정 (있을 때만) | AI가 틀렸거나 놓친 것과 어떻게 바로잡았는지 | 있을 때 |
| 발견 사항 (있을 때만) | 플러그인·도구에서 알게 된 문제와 개선 제안 | 있을 때 |
| 근거 링크 | 커밋 SHA, Issue/PR 번호 | 예 |

## 한계

- 이 기록은 AI가 작성한 요약이다. 대화 원문을 대체하지 않는다.
- 토큰 사용량, 비용 같은 수치는 포함하지 않는다.
