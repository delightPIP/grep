# ACC-001 Google 또는 GitHub로 로그인해야 그렙을 쓸 수 있다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 모든 화면과 명령. 서버 API 전부. 데모 포함

> **요약** 그렙은 로그인한 사용자만 쓴다. 로그인은 Google과 GitHub 두 가지 소셜 로그인뿐이고, 로그인하지 않은 화면에서는 로그인 말고 아무것도 할 수 없다. 로그인은 30일 동안 쓰지 않거나 로그인한 지 90일이 지나면 만료된다. 로그인 방식이 다르면 이메일이 같아도 다른 계정이다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 로그인 방식 | 사용자가 본인을 확인받는 외부 계정. Google, GitHub 두 가지 |
| 계정 | 그렙의 사용자 한 명. 자체 `users` 테이블의 행 하나이고, 로그인 방식의 외부 ID를 하나 이상 가진다(ADR-BCK-006) |
| 세션 | 한 기기에서 로그인해 유지되는 상태. 접근 토큰과 갱신 토큰으로 이뤄진다 |

## 규칙

> **주의** 서버는 사용자 ID를 요청 본문이나 주소에서 받지 않고 접근 토큰에서만 읽는다. 다른 사용자의 자료에 닿는 길을 만들지 않기 위해서다(기획 백엔드 설계 10. 보안).

1. 로그인하지 않았으면, 클라이언트는 로그인 화면만 보여 준다. 명령 입력, 저장, 끌어다 놓기, `도움말`을 받지 않는다.
2. 로그인 방식은 Google과 GitHub만 둔다. 이메일·비밀번호 로그인과 이메일 링크 로그인은 두지 않는다.
3. 처음 로그인하면, 서버는 계정을 새로 만든다. 별도 가입 절차나 약관 동의 화면은 두지 않는다(발표 뒤 개인정보 처리 안내에서 다룬다).
4. 로그인 방식이 다르면, 이메일이 같아도 서버는 계정을 합치지 않고 따로 만든다. 운영자도 이메일만 보고 계정을 합치지 않는다.
5. 세션은 사용자가 로그아웃하거나 ACC-002의 "모든 기기에서 로그아웃"을 하거나, 아래 "값"의 미사용 기간 또는 최대 기간이 지나면 끝난다.
6. 접근 토큰이 만료되면, 클라이언트는 갱신 토큰으로 조용히 새 토큰을 받는다. 갱신에 실패하면 로그인 만료로 본다.
7. 로그인 만료이면, 클라이언트는 입력 중이던 줄을 지우지 않고 남긴 채 로그인 화면으로 보낸다. 다시 로그인하면 그 줄을 되살린다.
8. 로그인 중 사용자가 취소하거나 외부 로그인이 실패하면, 클라이언트는 로그인 화면에 남아 이유를 한 줄 보여 준다.
9. 로그인 버튼을 여러 번 눌러도, 클라이언트는 로그인 창을 하나만 띄운다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 로그인 방식 | Google, GitHub | 이 둘 말고는 받지 않는다 |
| 접근 토큰 수명 | Supabase 기본값(1시간) | 바꾸면 ACC-002의 "모든 기기에서 로그아웃" 전파 시간도 같이 바뀐다 |
| 세션 미사용 만료 | 30일 | 마지막 요청 뒤 30일이 지나면 만료. 30일째까지는 유지 |
| 세션 최대 기간 | 90일 | 로그인한 때부터 90일이 지나면 쓰는 중이어도 다시 로그인 |
| 계정 합치기 | 하지 않음 | 로그인 방식(Google, GitHub)과 외부 계정 ID 한 쌍이 계정 하나 |
| 로그아웃 명령 | `로그아웃` (영문 `signout`) | `login`·`logout`은 기존 터미널 명령이라 쓰지 않는다(명령어 설명서 1절 원칙 2) |

## 예외

없음. 데모도 로그인 화면에서 시작한다.

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 로그인 화면 | 없음 | `그렙 ~ $ 로그인 필요` | `Google로 계속` · `GitHub로 계속` |
| 사용자가 로그인 취소 | 없음 | `✗ 로그인 취소됨` | 로그인 화면 버튼 그대로 |
| 외부 로그인 실패 | 없음 | `✗ 로그인 실패: <이유>` (이유는 `연결 끊김`, `응답 없음`, `권한 거부` 중 하나) | 로그인 화면 버튼 그대로 |
| 로그인 만료 | 없음 | `! 로그인 만료 → 다시 로그인` | 로그인 화면 버튼 그대로 |
| 로그아웃 | 없음 | `✓ 로그아웃됨` | 없음 |

## 근거

- PO 결정(2026-11-26): 처음부터 로그인 필수, 로그인 방식은 Google과 GitHub, 데모 필수 범위에 로그인을 넣고 동기화는 P1로 둔다
- ADR-BCK-006(인증은 Supabase, 자체 `users` 테이블에 외부 인증 ID만 저장)
- 기획서 F6, 백엔드 설계 10. 보안
- 구현: 웹 로그인 화면과 로그인 모듈 `web/features/logged-out/view.tsx`, `web/auth/supabase-auth.ts`(#31 진행 중). 서버·코어는 아직 없음

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 토큰 없는 요청이 모든 API에서 401인지. 요청 본문의 사용자 ID를 무시하는지 |
| 자동 테스트 | 같은 이메일로 Google·GitHub 로그인 시 서로 다른 계정이 되는지 |
| 자동 테스트 | 30일 미사용, 90일 경과 세션이 갱신되지 않고 로그인 만료로 가는지 |
| 수동 확인 | 로그인 만료 뒤 다시 로그인하면 입력 중이던 줄이 남아 있는지 |

## 비고

- 계정 삭제(탈퇴)는 발표 뒤 정한다([열린 질문](open-questions.md)).
- 로그인 방식 추가(카카오 등)는 이 정책을 수정해 정한다.
- 개발 확인: Supabase는 같은 이메일의 계정을 자동으로 이어 붙이는 동작이 있어 끄는 설정이 필요할 수 있다. 미사용·최대 기간 세션 설정이 쓰는 요금제에서 되는지도 확인한다. 안 되면 서버에서 세션 시작 시각과 마지막 요청 시각으로 판정한다.
- 계정을 하나로 합치는 기능(본인 확인 뒤 연결)은 두지 않는다. 필요하면 이 정책을 수정한다.
- 2026-11-26 수정은 외부 전문가 검토 세 건의 공통 지적(같은 이메일 자동 병합의 계정 탈취 위험, 무기한 세션)을 PO가 받아들인 것이다.
- Google·GitHub 동의 화면에서 취소·거부를 누르면(OAuth `access_denied`) 사용자가 그만둔 것으로 보고 `✗ 로그인 취소됨`을 보여 준다. `권한 거부`는 그 밖의 인가 오류에만 쓴다(개발자 결정 2026-11-26, ADR-WEB-012).
