# ACC-002 기기 수는 제한하지 않고, 모든 기기 로그아웃과 AI 도구 연결별 끊기를 제공한다
- 상태: 확정
- 적용 범위: 로그인한 모든 기기(웹 브라우저, 나중의 앱)와 AI 도구 연결(MCP, F7). 연결 부분은 F7을 만들 때부터 적용한다

> **요약** 한 계정으로 로그인할 수 있는 기기 수는 지금은 제한하지 않고 기기 목록 화면도 두지 않는다. 대신 이 기기만 로그아웃하거나 모든 기기에서 한 번에 로그아웃할 수 있다. AI 도구 연결은 하나씩 보고 끊을 수 있다. 기기 수 제한은 나중에 건다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 기기 | 그렙에 로그인한 브라우저나 앱 하나. 세션 하나와 같다(ACC-001) |
| AI 도구 연결 | AI 도구가 OAuth로 받은 그렙 읽기 권한 하나. 기기 세션과 따로 발급한다 |
| 모든 기기에서 로그아웃 | 계정의 모든 세션과 모든 AI 도구 연결을 끊는 일 |

## 규칙

1. 한 계정으로 로그인할 수 있는 기기 수는 제한하지 않는다.
2. 기기 목록 화면과 기기를 하나씩 끊는 기능은 두지 않는다.
3. `로그아웃`을 치면, 클라이언트는 이 기기의 세션만 끝낸다. 다른 기기와 AI 도구 연결은 그대로 둔다.
4. `로그아웃 모든기기`를 치면, 클라이언트는 확인을 받은 뒤 서버에 계정의 모든 갱신 토큰과 모든 AI 도구 연결을 끊게 한다.
5. 모든 기기에서 로그아웃하면, 이 기기는 바로 로그아웃된다. 다른 기기는 가지고 있던 접근 토큰이 만료될 때 로그아웃된다.
6. AI 도구 연결을 끊으면, 서버는 다음 요청부터 그 연결을 거부한다. 접근 토큰 만료를 기다리지 않는다.
7. `연결`을 치면, 클라이언트는 연결 주소 안내와 함께 지금 있는 AI 도구 연결 목록(번호, AI 도구 이름, 연결한 날, 마지막으로 읽은 날)을 보여 준다.
8. `연결 끊기 <번호>`를 치면, 클라이언트는 확인을 받은 뒤 그 연결 하나를 끊는다.
9. 같은 연결을 두 기기에서 동시에 끊어도 오류로 다루지 않는다. 이미 끊긴 연결이면 끊김으로 알린다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 기기 수 상한 | 없음 | 나중에 건다. 값은 [열린 질문](open-questions.md) |
| AI 도구 연결 수 상한 | 없음 | 기기 수 상한을 정할 때 같이 정한다 |
| 다른 기기 로그아웃까지 걸리는 시간 | 최대 접근 토큰 수명(1시간, ACC-001) | 즉시 끊기는 두지 않는다 |
| AI 도구 연결 끊기 반영 | 다음 요청부터 | 서버가 요청마다 연결이 살아 있는지 확인한다 |

## 근거

- PO 결정(2026-11-26): 기기 수 제한 없음, 기기 목록 없이 모든 기기 로그아웃만, AI 도구 연결은 연결별로 끊기. 모든 기기 로그아웃은 최대 1시간 안에 반영되고 AI 도구 연결도 끊는다. "나중엔 제한을 건다"
- ADR-BCK-006(인증은 Supabase), 백엔드 설계(MCP 연결 토큰 엔티티, AI 도구는 OAuth로 로그인)
- 구현: 아직 없음

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 모든 기기 로그아웃 뒤 다른 세션의 갱신 토큰이 거부되는지, 모든 AI 도구 연결이 다음 요청에서 거부되는지 |
| 자동 테스트 | 연결 하나를 끊으면 그 연결만 거부되고 다른 연결과 기기 세션은 그대로인지 |

## 비고

- **나중에 기기 수를 제한한다**(PO, 2026-11-26). 제한 값, 넘었을 때 가장 오래된 기기를 끊을지 새 로그인을 막을지, 기기 목록 화면을 함께 둘지는 그때 이 정책을 수정해 정한다. 제한을 걸 때 이미 상한을 넘은 계정을 어떻게 할지도 함께 정한다.
- 연결 명령(`연결`, `연결 끊기`)은 F7(P1)을 만들 때 명령어 설명서에 반영한다.
