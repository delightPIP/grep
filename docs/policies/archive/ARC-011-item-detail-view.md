# ARC-011 자료 하나는 `열기`로 자세히 보기를 열어 요약·출처·태그·묶음·본문·원본을 한 화면에 보여 준다
- 상태: 확정
- 구현 시점: 발표 뒤. 데모 범위 밖이다(2026-11-26 PO 결정, STATE 12절)
- 적용 범위: 모든 플랫폼(웹, 데스크톱, 모바일)의 자세히 보기. 터미널의 `열기` 명령, 목록·보관함에서 자료를 눌러 여는 경우

> **요약** 자료 하나를 보고 싶으면 `열기 <번호>`를 치거나 목록의 제목을 누른다. 자세히 보기는 제목, 출처, 저장 시각, 처리 상태, AI 요약, 태그, 들어 있는 묶음, 접힌 본문, 원본 미리보기를 이 차례로 보여 주고, 다음에 할 명령(`고르기`·`묶음`·`고치기`·`버리기`)을 칩으로 둔다. 화면에서 한 동작은 모두 같은 명령으로 터미널 기록에 남는다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 자세히 보기 | 자료 하나의 모든 정보를 보여 주는 화면. 목록 한 줄보다 많은 것을 보여 준다 |
| 본문 | 그렙이 가져오거나 읽은 글 전체(웹 본문, PDF 글자, 이미지 속 글자, 붙여 넣은 글). 요약과 구분한다 |
| 원본 | 사용자가 저장한 그 자체. 링크면 원래 페이지, 파일이면 저장한 파일 |
| 원본 미리보기 | 원본이 이미지·PDF일 때 자세히 보기 안에 그려 주는 그림 |
| 자세히 보기 칸 | 넓은 웹·데스크톱의 보관함 화면에서 목록 오른쪽에 자세히 보기를 띄우는 자리. 터미널 화면에는 두지 않는다 |

## 규칙

1. `열기 <번호>`(영문 `peek`)를 치면, 클라이언트는 그 자료의 자세히 보기를 연다. 번호는 자료 번호(ARC-001)다.
2. `열기`는 번호 하나만 받는다. 번호가 없거나 둘 이상이면 실패로 알리고 아무것도 열지 않는다.
3. 휴지통·영구 삭제한 자료의 번호이거나 없는 번호이면, 실패로 알린다(ARC-001 규칙 10).
4. 목록(터미널의 `찾기`·`최근`·묶음 결과, 보관함)에서 자료의 제목을 누르면 `열기 <번호>`가 입력줄에 찍히고 엔터로 실행한다(명령 칩은 찍기만, 2026-11-26 PO 결정). 번호를 누르면 지금처럼 `고르기 <번호>`다(명령어 설명서 6절).
5. 모바일 터미널 탭에서는 결과 줄을 누르면 고르고(모바일 시안 M3), 자세히 보기는 `⋯` 메뉴의 `열기`로 연다. 모바일 보관함 탭에서는 줄을 누르면 열고, 줄 왼쪽 선택 칸으로 고른다.
6. 자세히 보기는 아래 차례로 보여 준다. 값이 없는 줄은 빼고, 이유가 있으면 이유를 쓴다.
   1. 머리줄: 자료 번호와 제목
   2. 출처: 링크면 호스트(누르면 원래 페이지를 새 탭에서 연다), 링크가 아니면 `직접 넣음`과 형식(ARC-007 값)
   3. 저장 시각: `저장 <날짜 시각>`(ARC-004 규칙 7)
   4. 처리 상태: `ready`가 아니면 ARC-005 문구
   5. 요약: `AI 요약` 또는 `요약 (직접 고침)` 이름표를 붙인다(ARC-004 규칙 1)
   6. 태그: `태그 (AI 추정)` 이름표(ARC-004 규칙 2). 태그를 누르면 `찾기 #<태그>`가 실행된다
   7. 묶음: 이 자료가 들어 있는 묶음 이름. 누르면 `묶음 <이름>`(묶음 안 자료 보기)이 실행된다
   8. 본문: 접어 두고 글자 수와 `펼치기`만 보인다. 글 자료(붙여 넣은 글)는 본문이 곧 원본이라 펼쳐 둔다
   9. 원본 미리보기: 이미지는 그림을, PDF는 첫 쪽 그림과 `원본 열기`를 보여 준다. 링크에는 미리보기 그림을 두지 않는다
   10. 다음 명령: `→ 고르기 <번호> 또는 묶음 <이름> 또는 고치기 <번호> 또는 버리기 <번호>`
7. 이미지에서 읽은 본문은 본문 머리에 `(이미지에서 읽음)`을, 일부만 읽었으면 ARC-004 규칙 8 문구를 붙인다.
8. 터미널 화면에서는 폭과 상관없이 자세히 보기를 출력 블록으로 보여 준다. 터미널은 창 하나이고 패널을 나누지 않는다(디자인 시스템 "그렙 터미널" 1절 원칙 1).
   보관함 화면에서는 넓은 웹(1008px 이상)·데스크톱 본창이면 목록 오른쪽 자세히 보기 칸에, 그보다 좁으면 새 화면으로 연다. 이때 터미널 기록에는 `열기 <번호>`만 남는다.
9. 자세히 보기 칸과 새 화면은 열려 있는 동안 처리가 끝나면 그 자리만 새로 그린다. 터미널 출력 블록은 연 때 모습 그대로 둔다.
10. 자세히 보기에서 누른 동작(고르기, 묶음, 고치기, 버리기, 태그, 묶음 이름)은 같은 명령이 입력줄에 찍히고 엔터로 실행하며, 터미널 기록에 그 명령으로 남는다(명령 칩은 찍기만, 2026-11-26 PO 결정).
11. 자세히 보기는 자료를 고치지 않는다. 제목·요약을 고치는 것은 `고치기`(F14)가 맡는다.
12. 자세히 보기를 열어도 선택(ARC-003)은 바뀌지 않는다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 명령 | `열기`(peek) | 영문 이름은 기존 터미널 명령과 겹치지 않는다(2026-11-26 PowerShell·bash 확인, 맥은 시안 때 확인) |
| 한 번에 여는 자료 | 1건 | 0건·2건 이상은 실패 |
| 본문 기본 상태 | 접힘 | 글 자료만 펼침 |
| 원본 미리보기 | 이미지: 그림 / PDF: 첫 쪽 그림 / 링크·글: 없음 | 미리보기 크기와 PDF 첫 쪽을 그리는 방법은 개발자가 정한다 |
| 자세히 보기 칸을 쓰는 곳 | 보관함 화면, 웹 1008px 이상과 데스크톱 앱 본창 | 폭 값은 개발자가 정한다(사용자 흐름도 12-3절). 터미널 화면에는 두지 않는다 |

## 예외

- 데스크톱 빠른 창(DSK-003)에는 보관함이 없다. `열기`는 출력 블록으로만 보여 준다.

## 근거

- PO 결정(2026-11-26): 저장된 자료를 보는 흐름과 화면이 비어 있다는 점검 결과를 받고 기본안으로 진행(자세히 보기 [P0], 명령 `열기`, 본문 접힘, 이미지·PDF 원본 미리보기, 동작은 터미널 기록에 남김)
- 이 화면을 전제하던 문서: ARC-004 적용 범위(자세히 보기 이름표), 기획서 F2(목록·자세히 보기에 태그), 모바일 시안 M3(`⋯` 메뉴의 `열기`), [플랫폼별 UI/UX 학습 노트](../../planning/platform-ui-study.md) 3.2절(보관함 자세히 보기, 보관함 동작을 터미널 기록에 남김)
- 링크에 미리보기 그림을 두지 않는 이유: 서버가 남의 페이지 그림(`og:image`)을 가져오면 SSRF 방어 범위가 넓어진다(학습 노트 6절, ARC-006)
- [사용자 흐름도](../../planning/user-flow.md) 12절(저장된 자료 보기)
- 구현: 서버 `GET /items/{number}`(#131), 웹 뷰 `web/features/logged-in/view.tsx`, 코어 `열기`(PR #171)

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | `열기`에 번호 0개·2개·없는 번호·휴지통 번호를 주면 실패하고 아무것도 열리지 않는지 |
| 자동 테스트 | 요약 출처에 따라 `AI 요약`/`요약 (직접 고침)`, 태그에 `태그 (AI 추정)`이 붙는지 |
| 자동 테스트 | 자세히 보기에서 누른 동작이 같은 명령으로 터미널 기록에 남는지, 열어도 선택이 바뀌지 않는지 |
| 수동 확인 | 링크·글·이미지·PDF 자료와 `processing`·`blocked`·`failed` 자료의 자세히 보기 |
| 리뷰 | 시안에 자세히 보기 안에서 바로 고치는 칸이나 링크 미리보기 그림이 없는지, 터미널 화면에 자세히 보기 칸이 없는지 |

## 비고

- 자세히 보기 안에서 이전·다음 자료로 넘기는 동작은 두지 않는다. 필요하면 시안 검증 뒤 더한다.
- 본문 안에서 찾은 낱말을 표시(하이라이트)할지는 시안에서 정한다.
- 개발 답(2026-11-27): 구현할 수 있다. 원본 열기는 서버가 만든 서명 URL로 열고 유효시간은 10분이다.
