# ARC-005 저장 성공과 AI 처리 성공은 따로 다루고, 처리에 실패해도 저장한 자료는 남는다
- 상태: 확정
- 적용 범위: 모든 저장 경로(COM-001과 같음)와 저장 뒤 처리(본문 가져오기, 글자 읽기, 요약, 태그). 서버와 모든 클라이언트

> **요약** 서버는 자료와 원본이 모두 기록된 뒤에만 "저장됨"이라고 답한다. 본문 가져오기·글자 읽기·요약·태그는 그 뒤에 따로 하고, 실패해도 자료는 지우지 않고 제목과 출처만으로 찾고 넘길 수 있게 둔다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 저장 성공 | 자료 레코드와, 파일이면 원본 파일까지 서버에 기록된 것 |
| 처리 | 저장 뒤 서버가 하는 본문 가져오기, 글자 읽기, 요약, 태그 |
| 처리 상태 | `received`(받음), `processing`(처리 중), `ready`(완료), `blocked`(본문 못 가져옴), `failed`(처리 실패) |

## 규칙

> **주의** "저장됨"을 보고 사용자가 원본을 지울 수 있다. 원본이 기록되지 않았는데 "저장됨"을 보이면 자료를 잃는다.

1. 자료 레코드와 원본(파일이면 파일 저장소의 원본)이 모두 기록되면, 서버는 저장 성공으로 답한다. 하나라도 실패하면 저장 실패로 답하고 남은 조각을 지운다.
2. 저장에 실패하면, 클라이언트는 실패를 알리고 사용자가 넣으려던 링크·글을 입력줄에 남긴다. 기다리는 동안 사용자가 새 글을 쳤으면 입력줄을 덮지 않고, 다음 줄에 `→ 다시: <넣으려던 명령>`을 보인다. 끌어다 놓은 파일은 원본이 사용자 기기에 있으니 입력줄에 남기지 않고 실패한 파일 이름을 보인다. 여러 파일 중 하나가 실패해도 나머지는 저장한다(COM-004).
3. 처리는 저장 성공 뒤에 따로 한다. 처리 실패는 저장 성공을 되돌리지 않는다.
4. 본문을 가져올 수 없는 자료(로그인 필요, 접근 거부, ARC-006으로 열지 않는 주소)는 `blocked`로 두고 다시 시도하지 않는다.
5. 일시적인 오류(시간 초과, 외부 LLM 장애 등)만 자동으로 다시 시도한다. 횟수와 간격은 개발자가 정한다. 다 써도 안 되면 `failed`로 둔다.
6. 외부 LLM 제공사 장애 때는 다른 제공사로 바꾸지 않는다(COM-002 규칙 4).
7. 자료가 지워졌으면, 서버는 그 자료의 처리를 멈추고 다시 시도하지 않는다. 처리 중에 지워졌으면 결과를 버린다.
8. `blocked`·`failed` 자료도 목록, `찾기`(제목·출처로), `고르기`, `넘기기`, 묶음에서 다른 자료와 똑같이 쓴다. 넘길 글에는 요약 대신 없는 이유를 쓴다(ARC-004).
9. 사용자가 처리를 다시 시키는 명령은 지금은 두지 않는다.
10. 처리가 끝나면, 클라이언트는 이미 찍힌 `· 요약 생성 중` 줄을 그 자리에서 결과로 바꾼다(`ready`면 흐린 한 줄 요약, `blocked`·`failed`면 각 문구). 새 줄을 더 찍지 않고, 상태줄의 `요약 생성 중 N`을 줄인다. 결과를 전하는 방식은 개발자가 정한다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 자동 재시도 대상 | 일시적인 오류만 | 본문 못 가져옴(`blocked`)은 재시도하지 않음 |
| 재시도 횟수·간격 | 개발자가 정함 | 구현 후 이 칸에 적는다 |
| 상태 이름 | `received`, `processing`, `ready`, `blocked`, `failed` | 이 다섯 가지만 |
| 처리 결과를 화면에 전하는 방식(규칙 10) | 2초마다 `GET /items/status`로 폴링 | 처리 중(`received`·`processing`) 자료가 화면 줄에 있을 때만. 연결이 끊겨 있으면 묻지 않는다(개발자 결정 2026-11-26, 08 6절 13번) |

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 저장 실패 | 없음 | `✗ 저장 안 됨: <이유>  입력은 남겨 둠` (이유는 `연결 끊김`, `응답 없음`, `서버 오류` 중 하나) | 없음 |
| 저장 실패, 그새 새 글을 침 | 없음 | `✗ 저장 안 됨: <이유>` 다음 줄 `→ 다시: <넣으려던 명령>` | 없음 |
| 놓은 파일 저장 실패 | 없음 | `✗ 저장 안 됨: <이유> (<파일 이름>)`. 크기·형식 거절은 COM-004 문구 그대로 | 없음 |
| `담기`만 침 | 없음 | `✗ 저장할 것 없음  예: 담기 https://…` | 없음 |
| 처리 중 | 없음 | 요약 자리에 회색 `· 요약 생성 중`(경고 색을 쓰지 않음), 상태줄에 `요약 생성 중 N` | 없음 |
| 처리 끝남 | 없음 | 같은 줄이 그 자리에서 흐린 한 줄 요약으로 바뀜. 새 줄 없음 | 없음 |
| 목록에서 본문 못 가져옴 | 없음 | `! 본문 못 가져옴 → 고치기 <번호>` | 없음 |
| 본문 못 가져옴 | 없음 | `! 본문 못 가져옴: <이유>  제목·링크만 저장` (이유는 `로그인 필요`, `접근 거부`, `열지 않는 주소`) | 없음 |
| 처리 실패 | 없음 | 요약 자리에 `! 요약 못 만듦  제목·출처만 넘김` | 없음 |
