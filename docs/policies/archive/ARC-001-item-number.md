# ARC-001 자료마다 사용자별 고유 번호를 붙이고, 모든 명령이 그 번호 하나로 자료를 가리킨다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 자료 목록, 자료를 번호로 받는 모든 명령(`고르기`, `고치기`, `버리기`, `묶음 <이름> 빼기`), 알림 문구(COM-001), AI 도구 연결(MCP). 번호는 서버가 매긴다

> **요약** 서버는 자료를 새로 만들 때 그 사용자 안에서 1부터 하나씩 늘어나는 번호를 붙인다. 지운 자료의 번호는 다시 쓰지 않는다. 화면 목록의 위치 번호는 따로 두지 않고, 어디서든 이 번호 하나로 자료를 가리킨다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 자료 번호 | 한 사용자 안에서 자료 하나를 가리키는 양의 정수. 화면에 `131`처럼 숫자만 쓴다 |

## 규칙

1. 자료를 새로 만들면, 서버는 그 사용자의 가장 최근에 발급한 번호에 1을 더한 번호를 붙인다. 첫 자료는 1이다.
2. 번호 발급과 자료 생성은 한 트랜잭션이다. 저장이 실패하면 번호도 발급되지 않는다.
3. 같은 사용자가 여러 기기에서 동시에 저장해도, 서버는 번호가 겹치지 않게 사용자 단위로 차례를 지켜 발급한다.
4. 같은 자료를 다시 저장해 기존 자료를 돌려주면(COM-001), 서버는 번호를 새로 발급하지 않는다.
5. 북마크 가져오기로 여러 자료가 생기면, 서버는 파일에 적힌 순서대로 번호를 발급한다. 건너뛴 항목은 번호를 받지 않는다.
6. 자료를 지워도, 서버는 그 번호를 다른 자료에 다시 쓰지 않는다. 그래서 번호 사이에 빈 곳이 생길 수 있다.
7. 자료 번호는 바뀌지 않는다. 제목·요약을 고쳐도 같다.
8. 모든 자료 목록(`최근`, `찾기`, 묶음 안 자료)은 각 줄 앞에 자료 번호를 보여 준다. 목록 안 위치 번호(1, 2, 3 …)는 쓰지 않는다.
9. 번호를 받는 명령은 바로 앞 목록에 없는 번호도 받는다. 그 사용자의 지워지지 않은 자료이면 된다.
10. 받은 번호가 그 사용자에게 없거나 휴지통·영구 삭제한 자료의 번호이면(`되살리기`는 예외, ARC-008), 클라이언트는 실패로 알리고 아무것도 바꾸지 않는다. 여러 번호 중 하나라도 그렇다면 명령 전체를 실행하지 않는다.
11. 번호가 양의 정수가 아니면(0, 음수, 소수, 글자), 클라이언트는 잘못된 번호로 알린다.
12. 자료 번호 앞에 `#`을 붙이지 않는다. `#`은 태그에 쓴다(ARC-002).

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 첫 번호 | 1 | 사용자마다 따로 센다 |
| 증가 | 1 | 지운 번호는 다시 쓰지 않는다 |
| 최댓값 | 64비트 정수 범위 | 상한을 따로 두지 않는다 |
| 한 명령에서 받는 번호 개수 | 제한 없음 | 같은 번호를 두 번 써도 한 번으로 본다 |

## 예외

없음

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 없는 번호 또는 지운 자료의 번호 | 없음 | `✗ 없는 번호: <번호>` (여러 개면 쉼표로 이어 씀) | 없음 |
| 양의 정수가 아님 | 없음 | `✗ 잘못된 번호: <입력>  예: 고르기 131 140` | 없음 |
| 번호를 빠뜨림 | 없음 | `✗ 번호 없음  예: <명령> 131` | 없음 |

## 근거

- PO 결정(2026-11-26): "고유 번호 하나만". COM-001의 `! 이미 저장됨 → N번`과 명령어 설명서의 "바로 앞 목록에서 번호로 선택"이 서로 다른 번호를 뜻하던 것을 이 정책으로 정리

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 동시에 두 번 저장할 때 번호가 겹치지 않는지, `UNIQUE(user_id, 번호)` |
| 자동 테스트 | 같은 자료 재저장, 저장 실패, 북마크 가져오기 건너뜀에서 번호가 발급되지 않는지 |
| 자동 테스트 | 지운 번호를 넣으면 `✗ 없는 번호`이고, 여러 번호 중 하나만 틀려도 아무것도 바뀌지 않는지 |

## 비고

- 번호 범위 입력(`고르기 3-7`)은 두지 않는다. 필요하면 이 정책을 수정한다.
- 명령어 설명서의 옛 문구 `✗ 없는 번호  범위: 1~4`는 이 정책의 문구로 바꿨다.
