# 자료 영역 열린 질문

정책으로 확정하기 전에 답이 필요한 질문을 적는다. 답이 정해지면 정책 파일로 옮기고 이 목록에서 지운다.

| 질문 | 발급 예정 번호 | 제기한 날 |
|---|---|---|
| 사용자당 묶음 수와 묶음 하나의 자료 수, 저장한 찾기 수(ARC-012)에 상한을 둘 것인가(발표 뒤 결정) | ARC-003·ARC-012 수정 | 2026-11-26 |
| ARC-001의 적용 범위에 MCP가 있는데, MCP 응답의 식별자는 UUID로 하고 자료 번호는 표시용으로만 둘 것인가 | ARC-001 수정 | 2026-11-26 |
| 사용자가 처리(요약·글자 읽기)를 다시 시키는 명령을 둘 것인가(ARC-005 비고) | ARC-005 수정 | 2026-11-26 |
| 서버가 링크를 열 때 robots.txt를 따를 것인가(ARC-006 비고) | ARC-006 수정 | 2026-11-26 |
| `최근`·`찾기` 뒤의 시점(F22)과 `최근`의 숫자가 아닌 인자를 어떻게 할 것인가. 지금 `최근`은 기본 10건으로, `찾기`는 검색어로 본다(F22 데모 포함 결정 대기) | 미정 | 2026-11-27 |
| 처리 중에 휴지통으로 간 자료의 `· 요약 생성 중` 줄을 어떻게 보일 것인가. 지금은 상태줄 건수에서만 뺀다(삭제 구현 때 결정) | ARC-005·ARC-008 수정 | 2026-11-27 |
| 글자 없는 이미지(S07 같은 `blocked/no_text`)의 목록 꼬리표를 `! 본문 못 가져옴 → 고치기 N` 대신 `! 이미지에 글자 없음`으로 할 것인가(PO 안, 개발 의견 대기, PR #70 코멘트) | ARC-005 수정 | 2026-11-27 |
| 찾기 일치 위치를 고를 때 이미지 자료는 요약보다 이미지 속 글자를 먼저 볼 것인가. 지금은 제목→출처→요약→태그→본문 순이라 `찾기 반값`(S28)에 `이미지 속 글자`가 안 나온다 | ARC-002 수정 | 2026-11-27 |
| 찾기 대상에 출처(URL·호스트)를 넣을 것인가. 서버는 넣고 있고 commands 3절·ARC-002 규칙 7에는 없다 | ARC-002 수정 | 2026-11-27 |
| 처리 전(`received`·`processing`) 자료도 제목·출처로는 찾히게 할 것인가. `blocked`·`failed`는 처리 때 `search_text`를 채우지만(#59), 처리 전 자료는 아직 찾히지 않는다 | ARC-002 수정 | 2026-11-27 |
| `최근` 0건일 때 문구, `최근 0`·`최근 abc` 같은 인자와 50건 상한을 넘는 `최근 100`의 문구. 지금은 0건이면 아무 줄이 없고, 인자는 조용히 10건·50건이 된다 | commands 6절 | 2026-11-27 |
| 상태줄 `요약 생성 중 N`은 계정 전체의 처리 중 자료 수인가, 화면에 보이는 줄의 수인가. 지금은 화면 줄만 센다 | ARC-005 수정 | 2026-11-27 |
| `찾기` 0건 뒤 최근 3건을 받지 못하면 0건 줄만 보인다. 연결 문제를 알리는 줄을 더할 것인가 | COM-010 수정 | 2026-11-27 |
| `https://한글.kr` 같은 한글 도메인 링크를 글로라도 저장할 것인가. 지금은 400으로 `✗ 저장 안 됨: 서버 오류`가 되풀이된다(COM-001 비고) | COM-001 수정 | 2026-11-27 |
