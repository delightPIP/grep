# ARC-004 AI가 만든 요약과 태그는 화면, 넘길 글, AI 도구 연결 어디서나 AI 생성물로 구분해 보여 준다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 자세히 보기, 넘길 글(`넘기기`), AI 도구 연결(MCP) 응답. 목록 한 줄 요약은 예외(아래)

> **요약** 요약과 태그는 서버가 외부 AI로 만든 것이라 원문과 다를 수 있다. 그렙은 사용자가 이것을 원문이나 사실로 오해하지 않게, 요약이 나가는 모든 곳에서 "AI 요약"과 "직접 고친 요약"을 구분하고 없는 내용을 지어 채우지 않는다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| AI 요약 | 서버가 외부 LLM으로 만든 요약(COM-002) |
| 직접 고친 요약 | 사용자가 `고치기`로 고친 요약. AI 요약보다 우선한다 |
| AI 생성 표시 | 요약·태그가 어디서 왔는지 알리는 이름표 |

## 규칙

1. 자세히 보기에서는 요약 앞에 `AI 요약` 또는 `요약 (직접 고침)`을 붙인다.
2. 자세히 보기에서 태그 줄 앞에는 `태그 (AI 추정)`을 붙인다(ARC-002).
3. 넘길 글의 요약 칸 이름은 AI 요약이면 `AI 요약`, 직접 고친 요약이면 `요약(직접 고침)`이다.
4. 넘길 글의 안내 줄에는 AI 요약이 원문과 다를 수 있다는 문장을 넣는다.
5. AI 도구 연결의 응답에는 요약마다 출처 값(`ai` 또는 `user`)을 함께 보낸다.
6. 요약이 없으면, 그렙은 지어낸 요약·저자·발행일을 채우지 않고 없는 이유를 쓴다(넘길 글 형식 3절).
7. 저장 시각은 `저장`으로 적고 한국 시간 기준이다. 글의 발행일로 쓰지 않는다.
8. 글자 읽기나 본문 추출이 일부만 되었으면, 요약에 일부만 읽었다고 적는다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 자세히 보기 이름표 | `AI 요약`, `요약 (직접 고침)`, `태그 (AI 추정)` | 이 셋만 쓴다 |
| 넘길 글 칸 이름 | `AI 요약`, `요약(직접 고침)` | 영문 명령(`handoff`)으로 넘겨도 같다 |
| 넘길 글 안내 줄에 더할 문장 | `AI 요약은 자동으로 만든 것이라 원문과 다를 수 있다.` | 고정 문장 |
| 연결 응답의 출처 값 | `ai`, `user` | 요약이 없으면 값 없음 |

## 예외

- 목록의 한 줄 요약에는 이름표를 붙이지 않는다. 터미널 목록 한 줄이 너무 길어지기 때문이다. 대신 자세히 보기와 넘길 글에는 반드시 붙인다.

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 자세히 보기 요약 | 없음 | `AI 요약  <요약>` 또는 `요약 (직접 고침)  <요약>` | 없음 |
| 자세히 보기 태그 | 없음 | `태그 (AI 추정)  #결제 #위젯` | 없음 |
| 일부만 읽음 | 없음 | 요약 끝에 `(앞 N쪽만 읽음)` 또는 `(본문 일부만 가져옴)` | 없음 |

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 넘길 글의 요약 칸 이름이 요약 출처에 따라 `AI 요약`/`요약(직접 고침)`으로 나오는지 |
| 자동 테스트 | 요약이 없는 자료에 지어낸 요약이 들어가지 않는지 |
| 수동 확인 | 자세히 보기의 이름표 세 가지 |

## 비고

- 웹에는 자세히 보기가 발표 뒤에 생긴다(2026-11-26 PO 결정, AI 제안 수용). 그때까지 웹에서 `AI 요약`·`요약(직접 고침)` 이름표는 넘길 글과 그 미리보기에서 보인다. 규칙 1·2는 자세히 보기가 생기면 그대로 적용한다.
- 약관·도움말의 비보증 문구("요약·태그는 원문과 다를 수 있고 정확성을 보증하지 않는다")는 공개 출시 전 약관 작업에서 정한다([공통 열린 질문](../common/open-questions.md)).
