# ARC-007 보관함은 자동 묶음과 사용자 묶음, 저장한 찾기로만 자료를 보여 주고, 따로 폴더를 두지 않는다
- 상태: 확정
- 적용 범위: 모든 플랫폼(웹, 데스크톱, 모바일)의 보관함 화면. 모바일은 탭, 웹·데스크톱은 사이드바처럼 들어가는 길만 다르다

> **요약** 보관함은 서비스가 형식·출처·날짜·태그로 나눈 자동 묶음, 사용자가 만든 묶음(ARC-003), 저장한 찾기만 보여 준다. 묶음 말고는 사용자가 만드는 폴더가 없고, 자동 묶음은 사용자가 고칠 수 없다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 보관함 | 저장한 자료를 명령 없이 훑어보는 화면 |
| 자동 묶음 | 서비스가 자료의 속성(형식, 출처, 날짜, 태그)으로 나눈 묶음. 사용자는 만들거나 고치지 않는다 |
| 묶음 | 사용자가 이름을 붙여 자료를 모아 둔 것. 폴더 역할을 한다(ARC-003) |
| 저장한 찾기 | 사용자가 저장해 둔 검색어. 그 검색어에 맞는 자료가 저절로 모인다 |

## 규칙

1. 보관함은 자료를 자동 묶음, 묶음, 저장한 찾기 세 가지로만 나눠 보여 준다. 이 밖의 폴더는 두지 않는다(ARC-003 규칙 1).
2. 자동 묶음의 기준은 "값"의 네 가지(형식, 출처, 날짜, 태그)다.
3. 사용자는 자동 묶음을 만들거나, 이름을 바꾸거나, 자료를 자동 묶음 사이로 옮길 수 없다.
4. 태그 자동 묶음은 ARC-002의 태그로 만든다. 사용자는 태그를 붙이거나 고치거나 숨길 수 없다(ARC-002 규칙 2). 태그 묶음 이름에는 ARC-004의 AI 생성 표시를 붙인다.
5. 묶음의 목록, 넣기, 빼기, 지우기는 ARC-003을 따른다. 보관함에서 한 넣기·빼기도 같은 규칙이다.
6. 한 자료는 해당하는 모든 자동 묶음, 묶음, 저장한 찾기에 동시에 보인다.
7. 자료가 0건인 자동 묶음과 저장한 찾기는 보여 주지 않는다. 묶음은 0건이어도 보여 준다(ARC-003 규칙 9).
8. 지운 자료는 어디에도 보이지 않는다.
9. 각 묶음 안의 자료는 자료 번호가 큰 순서(최근 저장 순, ARC-001)로 보여 준다.
10. 저장한 찾기는 검색어만 저장한다. 모이는 자료는 그 검색어로 `찾기`를 한 결과와 같다. `#태그` 검색어(ARC-002)도 저장할 수 있다.
11. 사용자가 터미널에 폴더를 만들려는 입력을 하면, 알 수 없는 명령으로 처리하지 않고 "사용자 문구"의 안내를 보여 준다. 이 입력은 그렙의 명령이 아니다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 형식 | 저장한 자료의 형식(링크, 글, 이미지, 파일. 받는 파일 형식은 COM-004) | 형식은 저장할 때 정해지고 바뀌지 않는다 |
| 출처 | 링크의 호스트(COM-001 정규화 주소 기준) | 링크가 아닌 자료(글, 이미지, 파일)는 "직접 넣음" 하나로 묶는다 |
| 날짜 | 오늘 · 이번 주 · 이번 달 · 그 전 | 저장 시각 기준, 사용자 기기의 시간대. 각 구간은 시작 시각 0시 이상 |
| 태그 | 자료에 붙은 태그 하나가 자동 묶음 하나 | 태그가 아직 없는 자료는 태그 묶음에 나오지 않는다(ARC-002 규칙 8) |
| 폴더를 만들려는 입력 | `폴더`, `mkdir`로 시작하는 입력 | 그 뒤에 무엇이 와도 같은 안내 |
| 페이지당 건수, 묶음별 건수 집계 방식 | 개발자가 정한다 | — |

## 예외

- 묶음(ARC-003)과 저장한 찾기는 사용자가 만든다. 묶음은 폴더 역할을 하는 유일한 단위이고, 저장한 찾기는 자료를 옮기지 않으므로 규칙 3의 예외다.

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 터미널에서 폴더를 만들려고 함 | 없음 | `· 폴더 없음: 묶음이 폴더 역할  → 고르기 <번호> · 묶음 <이름>` | 없음 |

## 근거

- ARC-002(태그 자동, 사용자 편집 없음), ARC-003(폴더 없이 한 단계 묶음), ARC-004(AI 생성 표시)
- 기획서 F1 "분류를 요구하지 않는다", 7절 "하지 않는 것"(사용자가 태그를 직접 관리하는 것, 하위 폴더가 있는 폴더 구조)
- [플랫폼별 UI/UX 학습 노트](../../planning/platform-ui-study.md) 4절(자동 묶음 보관함)
- PO 결정(2026-11-26): 보관함은 자동 묶음 중심, 묶는 기준은 형식·출처·날짜·자동 태그, 저장한 찾기 넣음, 이번 단계에서 태그 편집 없음
- 구현: 아직 없음

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 보관함 API가 0건 자동 묶음과 저장한 찾기를 빼고, 0건 묶음은 남기는지 |
| 자동 테스트 | 지운 자료가 어느 묶음에도 나오지 않고, 순서가 자료 번호 큰 순인지 |
| 자동 테스트 | 링크가 아닌 자료가 "직접 넣음" 출처로 묶이는지 |
| 자동 테스트 | `폴더`, `mkdir 자료` 입력 시 안내 문구가 나오고 알 수 없는 명령으로 처리되지 않는지 |
| 리뷰 | 보관함 시안에 자동 묶음 편집, 태그 편집, 하위 폴더 컨트롤이 없는지 |

## 비고

- 자동 태그를 사용자가 고치거나 숨기는 기능은 이번 단계에서 두지 않는다. 잘못 붙은 태그를 신고하거나 지우는 경로는 자료 영역 열린 질문에 있다.
- 자동 태그 기능이 나오기 전에 저장한 자료는, 기능이 나오면 태그를 붙인다. 그전에는 형식·출처·날짜 묶음에만 보인다. 시점과 방식은 개발자가 정한다.
- 저장한 찾기의 명령 이름과 화면은 명령어 설명서와 시안에서 정한다.
