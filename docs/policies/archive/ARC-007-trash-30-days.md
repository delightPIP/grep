# ARC-007 지운 자료는 휴지통에 30일 두고, 그동안 되살릴 수 있다
- 상태: 검토 중 (개발자 확인 대기)
- 적용 범위: `버리기`, 모든 플랫폼의 자료 목록·`찾기`·`넘기기`·묶음, AI 도구 연결(ARC-008), 같은 자료 판정(COM-001)

> **요약** `버리기`는 자료를 바로 없애지 않고 휴지통으로 옮긴다. 휴지통 자료는 찾기·넘기기·AI 연결에서 바로 빠지고, 30일 안에 `되살리기`로 돌릴 수 있다. 30일이 지나거나 휴지통을 비우면 영구 삭제한다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 휴지통 | `버리기`한 자료가 영구 삭제 전까지 머무는 곳 |
| 영구 삭제 | 자료와 그에 딸린 것(원본 파일, 가져온 본문, 이미지 글자, 요약, 태그, 검색 색인, 중복 판정 값, 묶음 연결)을 모두 지우는 것 |

## 규칙

1. `버리기 <번호...>`를 치면, 서버는 그 자료를 휴지통으로 옮긴다. 2건 이상이면 클라이언트는 건수를 보여 주고 확인을 받는다.
2. 휴지통 자료는 `최근`, `찾기`, `고르기`, `넘기기`, 묶음, AI 도구 연결에 나오지 않는다.
3. 휴지통 자료는 묶음 연결을 남겨 둔다. 되살리면 원래 묶음에 다시 보인다.
4. `되살리기 <번호...>`를 치면, 서버는 그 자료를 휴지통에서 돌려놓는다. 번호는 바뀌지 않는다(ARC-001).
5. `휴지통`을 치면, 클라이언트는 휴지통 자료를 지운 날 최신순으로 보여 준다.
6. `휴지통 비우기`를 치면, 클라이언트는 건수를 보여 주고 확인을 받은 뒤 휴지통 자료를 모두 영구 삭제한다.
7. 휴지통에 들어간 지 30일이 지나면, 서버는 그 자료를 영구 삭제한다.
8. 휴지통에 있는 자료와 같은 링크·파일을 다시 저장하면, 서버는 새로 만들지 않고 휴지통에 있다고 알린다(COM-001).
9. 영구 삭제한 번호는 다시 쓰지 않는다(ARC-001 규칙 6).

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 휴지통 보관 | 30일 | 30일째까지 되살릴 수 있다 |
| 확인을 받는 건수 | 2건 이상 | 1건은 확인 없이 휴지통으로 |
| 명령 | `버리기`(drop), `되살리기`(revive), `휴지통`(bin), `휴지통 비우기`(bin empty) | 영문 이름은 기존 터미널 명령과 겹치지 않는 것(명령어 설명서 1절 원칙 2). 개발자 확인 |

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |

| 휴지통으로 옮김 | 없음 | `✓ 휴지통 N건 (30일 뒤 삭제, 되살리기 <번호>)` | 없음 |
| 2건 이상 버리기 확인 | 없음 | `휴지통으로? N건` | `1 취소 · 2 버리기` |
| 되살림 | 없음 | `✓ 되살림 N건` | 없음 |
| 휴지통 비우기 확인 | 없음 | `영구 삭제? N건 (되돌릴 수 없음)` | `1 취소 · 2 삭제` |
| 휴지통 자료와 같은 자료 저장 | 없음 | `! 휴지통에 있음 → N번. 되살리기 N` | 없음 |

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 휴지통 자료가 `찾기`·`넘기기`·AI 연결에 나오지 않는지, `되살리기` 뒤 같은 번호·같은 묶음으로 돌아오는지 |
| 자동 테스트 | 30일이 지난 자료와 `휴지통 비우기` 자료에 딸린 것이 모두 지워지는지 |

## 비고

- 개발자 확인할 것: 30일 뒤 영구 삭제를 무료로 돌릴 방법(예약 작업 등, COM-005). 어렵다면 데모 기간에는 자동 삭제를 미루고 `휴지통 비우기`만 둬도 된다. 명령 이름이 정해지면 명령어 설명서에 더한다.
- 백업에서 언제 사라지는지는 실제 사용자를 받을 때 정한다.
