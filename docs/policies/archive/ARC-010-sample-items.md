# ARC-010 첫 화면의 샘플 8건은 실제 자료로 저장하고 버리기로 치운다
- 상태: 검토 중 (개발자 확인 대기)
- 적용 범위: 자료 0건인 첫 화면(모든 플랫폼), 샘플 자료의 번호(ARC-001)·버리기(ARC-008)

> **요약** 자료가 0건일 때 첫 화면의 `→ 샘플 8건으로 해 보기`를 누르면, 서버는 샘플 8건을 그 사용자의 자료로 저장하고 다음 번호 8개를 준다(새 계정이면 1~8번). 치울 때는 새 명령 없이 받은 번호 범위로 `버리기 <a>-<b>`를 쓴다.

## 규칙

1. 샘플 안내 `→ 샘플 8건으로 해 보기`는 자료가 0건일 때만 보인다. 휴지통 자료는 건수에 넣지 않는다.
2. 누르면, 서버는 샘플 8건을 그 사용자의 자료로 저장한다. 번호는 그 사용자의 다음 번호부터 저장 순서대로 8개다(ARC-001). 새 계정이면 1~8이고, 자료를 모두 버린 계정이면 지운 번호를 다시 쓰지 않으므로 그 뒤 번호다.
3. 8건은 한꺼번에 저장한다. 하나라도 실패하면 아무것도 저장하지 않고 실패를 알린다.
4. 저장이 끝나면, 클라이언트는 실제로 받은 번호 범위를 넣은 완료 줄과 치우는 방법을 한 줄씩 보여 주고 `최근`과 같은 목록을 띄운다.
5. 샘플은 일반 자료와 똑같이 `찾기`·`고르기`·`넘기기`·묶음·`고치기`·`버리기`를 쓸 수 있다. 샘플 표시는 따로 두지 않는다.
6. 치울 때는 받은 번호 범위로 `버리기 <a>-<b>`를 쓴다(새 계정이면 `버리기 1-8`). `버리기`는 `a-b` 꼴의 번호 범위를 받는다. 버린 샘플은 다른 자료처럼 휴지통으로 간다(ARC-008).
7. 샘플은 계정당 한 번만 받는다. 이미 받은 계정이 다시 누르면 새로 저장하지 않고 처음 받은 번호 범위로 완료 문구를 다시 보여 준다. 받은 샘플이 휴지통에 있든 영구 삭제됐든 같다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 샘플 건수 | 8건 | 마케터 캠페인 이야기 7건 + 그렙 사용법 1건 |
| 받는 번호 | 다음 번호부터 8개 | 새 계정은 1~8. 휴지통을 빼고 0건인 계정은 지운 번호 뒤부터(ARC-001 규칙 6) |
| 번호 범위 꼴 | `a-b` | a ≤ b. 없는 번호가 섞이면 명령 전체를 실행하지 않는다(ARC-001 규칙 10) |

## 근거

- PO 결정(2026-11-26): 샘플은 실제 아카이브에 넣는다, `버리기 1-8`로 치운다, 내용은 마케터 이야기 7건 + 그렙 사용법 1건
- PO 결정(2026-11-26, AI 제안 수용): 실제로 받은 번호 범위를 알린다. 위 "`버리기 1-8`"을 대체한다. AI 추천 이유: 자료를 모두 버린 계정(리허설 뒤 데모 계정 A)에서도 안내 문구가 맞는다
- 명령어 설명서 6절 첫 화면 문구, 자료 영역 열린 질문(이 정책으로 닫음)
- 구현: 서버 `server/src/main/kotlin/com/unwrap/grep/features/samples/`(`POST /samples`, 목록 `db/seed/samples/samples.json`), 코어 `core/Features/Terminal/Sources/Terminal+Samples.swift`(#102, PR #155)

## 비고

- 개발 안(개발자 확인 전): 샘플은 미리 만든 요약·태그를 함께 넣어 하루 AI 처리 한도(COM-005)를 쓰지 않는다.
- 샘플 8건의 내용은 데모 시드(`docs/planning/demo-seed.md`)의 마케터 이야기에서 고른다.
- 규칙 7로 다시 누를 때 완료 문구 아래 목록은 휴지통을 뺀 `최근`이라 비어 있을 수 있다. 지금 동작 그대로 두기로 했다(2026-11-28 PO 결정, [QA 검수 보고](../../planning/qa-2026-11-28-demo-readiness.md) Q-3).
- 데모 시드와 같은 내용의 자료가 휴지통에 있는 계정에서 처음 누르면 저장 전체가 실패할 수 있다(같은 보고 BUG-01, 개발 확인).
