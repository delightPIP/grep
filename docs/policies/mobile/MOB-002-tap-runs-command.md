# MOB-002 모바일에서는 번호·명령을 누르면 바로 실행하고, 확인 질문은 낱말 버튼으로 답한다
- 상태: 검토 중 (PO 확인 대기)
- 적용 범위: iOS·Android 앱의 터미널 탭. 웹(모바일 웹 포함)과 데스크톱은 이 정책 밖이고 지금처럼 누르면 입력줄에 찍기만 한다(commands 5절)

> **요약** 휴대폰 터미널에서는 목록의 자료 번호나 화면에 찍힌 명령을 누르면 그 명령을 바로 실행한다. 웹은 누르면 입력줄에 찍기만 하고 엔터로 실행하므로 둘의 동작이 다르다. 5건 초과 확인 같은 확인 질문은 실행 낱말과 같은 이름의 버튼으로 답한다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 누르기 | 화면의 자료 번호, 명령 칩, 결과 행을 손가락으로 탭하는 일 |
| 확인 질문 | 답을 기다리는 줄. 예: 5건 초과 넘기기의 `→ 앞10 · 전부`(COM-008), 여러 건 버리기 확인(ARC-008) |
| 낱말 버튼 | 확인 질문의 실행 낱말(`앞10`, `전부`, `버리기` 등)을 이름으로 단 버튼 |

## 규칙

1. 모바일 터미널에서 목록의 결과 행이나 자료 번호를 누르면, 앱은 `고르기 <번호>`를 바로 실행한다.
2. 화면에 찍힌 명령 칩(예: `→ 넘기기`, `→ 고치기 33`)을 누르면, 앱은 그 명령을 바로 실행한다. 다만 인자가 더 필요한 명령(예: `묶음 _`)은 입력줄에 찍고 커서를 둔다.
3. 누른 명령도 친 명령과 똑같이 출력 기록에 프롬프트 줄로 남긴다(COM-009).
4. 확인 질문은 실행 낱말과 같은 이름의 버튼과 `취소` 버튼으로 답한다. 낱말 버튼은 COM-007의 실행 낱말을 친 것과 같고, `취소`는 다른 입력과 같다(`· 취소됨`).
5. 입력줄에 직접 쳐서 실행하는 길은 그대로 둔다. 친 명령의 결과는 웹과 같다.
6. 웹과 데스크톱은 누르면 입력줄에 찍기만 한다. 이 차이는 웹이 키보드로 고쳐 치기 쉬워 찍고 엔터 치는 쪽이 실수를 줄이고, 휴대폰은 고쳐 치기가 불편해 누르는 것 자체를 의도로 보기 때문이다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 누르면 바로 실행하는 것 | 결과 행·자료 번호(`고르기 <번호>`), 인자가 다 찬 명령 칩 | 인자가 모자란 칩은 찍기만 |
| 확인 질문 버튼 | 실행 낱말 버튼 + `취소` | 터치 목표 44px 이상(MOB-001 값) |

## 예외

| 상황 | 처리 |
| :--- | :--- |
| 이미 고른 자료의 행을 다시 누름 | 선택에서 뺀다. `고르기 빼기 <번호>`를 실행한 것과 같고 기록에 남는다(규칙 3). 마지막 하나를 빼면 `✓ 선택 비움` |

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 5건 초과 확인 | 없음 | COM-008 문구 그대로 | `앞10` · `전부` · `취소` |

## 근거

- 명령어 설명서 8절 "명령을 버튼으로 누르는 방식(휴대폰 US-7)은 모바일 앱 단계에서 정한다", 5절(웹은 누르면 입력줄에 찍기만, 2026-11-26 PO 결정)
- 개발 결정(2026-11-27): iOS 터미널 #62 화면(PR #152)에서 결과 행을 누르면 `고르기 <번호>`를 바로 실행하고, 5건 초과 확인을 `앞10`·`전부`·`취소` 버튼으로 받게 만들었다. PO 확인을 기다린다
- 모바일 시안 M3·M5(`UiChoiceList`, `MPickBar`)
- 구현: iOS `ios/Features/Terminal/UI/TerminalView.swift`(PR #152). Android는 아직 없음
