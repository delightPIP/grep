# COM-007 확인과 선택을 기다릴 때는 실행 낱말 하나만 실행 답으로 받고, 그 밖의 입력은 취소한 뒤 명령으로 실행한다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 터미널 화면(웹, 모바일, 데스크톱 빠른 창)에서 확인 질문(`버리기?`, `지우기?`, `비우기?`, `로그아웃?`, `끊기?`)과 이어 쓰기 선택지(`앞10`, `전부`, COM-008)를 보인 뒤의 다음 입력

> **요약** 확인이나 선택을 기다리는 동안, 명령 이름이나 선택지 낱말 하나를 치면 실행하고, 다른 것을 치면 확인을 취소한 뒤 그 입력을 새 명령으로 바로 실행한다. 같은 명령을 두 번 치지 않아도 된다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 확인 대기 | 확인 질문이나 선택지를 보이고 다음 입력을 기다리는 상태 |
| 실행 낱말 | 확인 질문의 명령 이름(한글 또는 영문, 예: `버리기`·`drop`)이나 선택지 낱말(`앞10`, `전부`) |

## 규칙

1. 확인 대기는 한 번에 하나다. 확인 대기 중 다음 입력 한 번이 답이다.
2. 답이 실행 낱말 하나이면(앞뒤 빈칸은 무시), 클라이언트는 기다리던 동작을 실행한다. 한글과 영문은 같은 답이다(명령어 설명서 1절).
3. 답이 실행 낱말 하나가 아니면, 클라이언트는 확인을 취소하고 `· 취소됨`을 찍은 뒤 그 입력을 새 명령으로 실행한다. 예: `버리기? 3건` 뒤 `찾기 텀블러`를 치면 `· 취소됨` 다음에 찾기 결과가 나온다.
4. 명령 이름 뒤에 다른 낱말이 붙은 입력(예: `버리기 64`)은 실행 낱말이 아니다. 규칙 3대로 앞 확인을 취소하고 새 명령으로 실행한다.
5. 빈 입력(엔터만)이면 확인을 취소하고 `· 취소됨`만 찍는다.
6. 모바일에서 선택지는 같은 낱말의 버튼으로 보이고, 버튼 밖을 누르거나 다른 것을 입력하면 규칙 3·5와 같다.
7. 확인 대기 중 로그인이 만료되면, 다시 로그인한 뒤 그 확인은 취소된 것으로 본다(ACC-001, COM-009).

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 실행 답 | 실행 낱말 하나 | 앞뒤 빈칸 무시. 낱말이 둘 이상이면 실행 답이 아니다 |
| 취소 표시 | `· 취소됨` | 취소한 뒤 입력을 실행할 때도 먼저 찍는다 |

## 근거

- PO 결정(2026-11-26, AI 제안 수용): "그 외 입력"은 취소하고 그 명령도 실행한다. 실행 답은 한글·영문 낱말 하나. [처음부터 끝까지 사용자 흐름과 빈칸](../../planning/flow-inventory.md) 8절 P4

- 구현: 코어 확인 대기 `core/Features/Terminal/Sources/Terminal+Pipe.swift`(5건 초과 넘기기, #66), `core/Features/Terminal/Sources/Terminal+Trash.swift`(버리기·비우기, #96), 로그아웃 모든기기(#111)

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | `버리기? 3건` 뒤 `버리기`·`drop`·` 버리기 `는 실행, `찾기 텀블러`는 `· 취소됨` 다음 찾기 결과, `버리기 64`는 앞 확인 취소 뒤 64만 휴지통, 빈 입력은 취소만 |
| 자동 테스트 | 이어 쓰기 선택지에서 `전부`·`앞10`은 실행, 그 밖의 입력은 취소 뒤 실행 |

## 비고
