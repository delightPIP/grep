# COM-006 한 사용자의 자료는 그 사용자만 보고, 다른 사용자의 자료에 닿는 길을 두지 않는다
- 상태: 검토 중 (개발자 확인 대기)
- 적용 범위: 서버 API 전부, AI 도구 연결(MCP), 파일 내려받기, 검색 색인, 중복 판정(COM-001), 태그(ARC-002), 묶음(ARC-003)

> **요약** 자료 번호(ARC-001)는 1부터 차례로 붙어 추측하기 쉽다. 그래서 모든 조회는 접근 토큰의 사용자와 자료를 함께 확인한다. 한 곳이라도 빠지면 번호만 바꿔 남의 자료를 읽을 수 있다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 소유자 확인 | 요청한 자료의 사용자 ID가 접근 토큰의 사용자 ID와 같은지 서버가 확인하는 것 |

## 규칙

> **주의** 번호가 1, 2, 3 …으로 붙으므로 소유자 확인이 한 곳만 빠져도 다른 사용자의 자료가 보인다.

1. 서버는 사용자 ID를 접근 토큰에서만 읽는다(ACC-001 주의).
2. 자료·묶음·파일을 읽고 바꾸고 지우는 모든 요청은 "사용자 ID + 번호(또는 이름)"로만 찾는다. 번호만으로 찾는 길을 두지 않는다.
3. 검색, 중복 판정(COM-001), 태그 찾기, 묶음은 그 사용자의 자료 안에서만 한다.
4. AI 도구 연결도 연결을 승인한 사용자의 자료만 돌려준다(ARC-009).
5. 파일은 추측할 수 없는 주소로만 내려준다. 주소는 정해진 시간 뒤 만료된다.
6. 다른 사용자의 자료이거나 없는 자료이면 같은 응답을 돌려준다. "있지만 남의 것"을 알리지 않는다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 파일 주소 만료 | 5분 (가정값, 개발자 확인) | Supabase 서명 주소 기본 기능으로 된다면 그 값 |
| 남의 자료·없는 자료 응답 | 같은 "없음" 응답 | ARC-001 규칙 10의 문구를 그대로 쓴다 |

## 예외

없음

## 사용자 문구

없음. 없는 번호 문구는 ARC-001을 따른다.

## 근거

- 외부 전문가 검토(2026-11-26): 순차 번호와 조회 누락이 만나면 타인 자료 노출(OWASP API Security 2023 API1, OWASP Top 10 2021 A01). 사용자 간 중복 제거는 "누가 이 파일을 갖고 있다"를 드러냄
- ACC-001 주의, ADR-BCK-002(`UNIQUE(user_id, ...)`)
- 구현: 아직 없음

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 수동 확인 | 데모 전 계정 두 개로 서로의 자료 번호·파일 주소·묶음 이름·AI 연결 읽기를 시도해 모두 "없음"이 나오는지 |
| 자동 테스트 | 다른 사용자 토큰으로 자료 조회·수정·삭제 요청 시 "없음"이 오는지 |

## 비고

- 개발자 확인할 것: Supabase 행 수준 보안(RLS)으로 규칙 2·3을 지킬지 서버 코드로 지킬지, 파일 주소 만료 값. 돈이 드는 방식은 쓰지 않는다(COM-005).
