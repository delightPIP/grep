# COM-010 서버에 닿지 못하면 명령 실패를 알리고 상태줄에 표시하며, 끊긴 동안 친 명령은 저절로 다시 하지 않는다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 터미널 화면(웹, 모바일 터미널 탭, 데스크톱 빠른 창)에서 서버가 필요한 명령. 저장은 ARC-005, 넘기기는 COM-008, 로그인은 ACC-001이 먼저다

> **요약** 서버에 닿지 못하면 명령을 실행하지 않고 `✗ <명령> 안 됨: <이유>`와 다시 칠 명령을 보인다. 끊겨 있는 동안 상태줄에 `연결 끊김`을 두고, 다시 연결되면 `✓ 연결됨`을 한 줄 찍는다. 끊긴 동안 친 명령은 저절로 다시 하지 않는다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 서버에 닿지 못함 | 연결이 끊겼거나, 서버가 정해진 시간 안에 답하지 않았거나, 서버가 오류로 답한 경우 |
| 이유 | 서버에 닿지 못한 까닭을 나타내는 낱말 셋 중 하나 |

## 규칙

1. 명령이 서버에 닿지 못하면, 클라이언트는 그 명령을 실행하지 않고 `✗ <명령> 안 됨: <이유>`와 다음 줄 `→ 다시: <친 명령>`을 보인다.
2. 이유는 `연결 끊김`, `응답 없음`, `서버 오류` 중 하나다.
3. 연결이 끊겨 있는 동안, 클라이언트는 상태줄에 `연결 끊김` 칸을 둔다.
4. 다시 연결되면, 클라이언트는 `✓ 연결됨` 한 줄을 찍고 상태줄의 `연결 끊김` 칸을 뺀다.
5. 끊긴 동안 친 명령은 다시 연결돼도 저절로 다시 하지 않는다. 사용자가 `→ 다시` 칩을 누르거나 다시 친다.
6. 저장 실패는 ARC-005, 넘기기 실패는 COM-008, 로그인 실패는 ACC-001의 문구를 따른다. 데스크톱 두더지에 놓았을 때는 DSK-002를 따른다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 이유 | `연결 끊김`, `응답 없음`, `서버 오류` | 이 셋만 |
| `응답 없음`으로 보는 대기 시간 | 개발자가 정한다 | 구현 후 이 칸에 적는다 |
| 끊김과 다시 연결을 알아내는 방법·주기 | 개발자가 정한다 | 구현 후 이 칸에 적는다 |
