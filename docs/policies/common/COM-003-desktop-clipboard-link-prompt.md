# COM-003 데스크톱 앱은 복사한 링크를 사용자가 켰을 때만 알리고, 묻기 전에는 저장하지 않는다
- 상태: 검토 중 (데스크톱 실험 뒤 확정)
- 적용 범위: Windows 데스크톱 상주 앱(데스크톱 두더지). 웹과 모바일에는 적용하지 않는다

> **요약** 복사한 링크 알림은 기본으로 꺼져 있다. 켜면 링크 하나를 복사할 때마다 "담기?"를 한 번 묻고, 사용자가 "담기"를 누를 때만 저장한다. 그 전에는 복사한 내용을 서버로 보내지 않는다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 복사한 링크 알림 | 다른 앱에서 링크를 복사했을 때 두더지 옆에 뜨는 "담기?" 카드 |
| 링크 | 앞뒤 공백을 뺀 클립보드 글 전체가 `http://` 또는 `https://`로 시작하는 주소 하나인 것 |

## 규칙

> **주의** 클립보드에는 비밀번호, 개인 메시지 같은 민감한 내용이 들어간다. "담기"를 누르기 전에는 복사한 내용을 서버로 보내거나 기기에 저장하지 않는다.

1. 복사한 링크 알림은 기본으로 꺼져 있고, 설정에서 사용자가 켤 때만 동작한다.
2. 켜져 있으면, 링크를 복사할 때 앱은 알림을 한 번 띄운다.
3. 클립보드 글이 링크가 아니면(글 속에 링크가 섞여 있어도) 알리지 않는다.
4. OS가 "기록하지 않음"으로 표시한 복사(비밀번호 관리자 등)는 알리지 않는다.
5. 이미 저장한 링크면 알리지 않는다. 같은 링크인지는 COM-001(같은 링크 판정)을 따른다.
6. "무시"했거나 그냥 사라진 링크는 앱이 켜져 있는 동안 다시 묻지 않는다. 앱을 다시 켜면 이 목록은 비워진다. 목록은 메모리에만 두고 저장하지 않는다.
7. 알림이 떠 있는 동안 다른 링크를 복사하면 알림 내용이 새 링크로 바뀌고, 앞 링크는 무시한 것으로 본다. 알림은 한 번에 하나만 뜬다.
8. "담기"를 누를 때만 저장한다. 저장 결과와 실패 처리는 일반 저장(F1)과 같다.
9. 클립보드는 OS의 변경 알림이 올 때만 읽고, 주기적으로 읽지 않는다.

## 비고

데스크톱 앱은 아직 PRD 기능 목록에 없다. 범위에 들어가면 이 정책을 따른다.
- 개발 답(2026-11-27): 셸은 Tauri(ADR-WEB-007 결정 5)이고 클립보드 감시(사용자가 켰을 때만)은 Tauri 기능·플러그인으로 할 수 있다고 본다. 데스크톱 착수(#140) 첫 실험에서 확인한 뒤 확정한다.
