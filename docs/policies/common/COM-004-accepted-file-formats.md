# COM-004 저장할 수 있는 파일은 PDF, md, txt, docx와 PNG, JPEG, WebP, HEIC 이미지다
- 상태: 검토 중 (개발자 확인 대기)
- 적용 범위: 파일을 저장하는 모든 경로(끌어다 놓기, 파일 선택, 공유 시트, 데스크톱 두더지)와 모든 플랫폼. 판정은 서버가 한다(ADR-0001)

> **요약** 서버는 문서 4종(PDF, md, txt, docx)과 이미지 4종(PNG, JPEG, WebP, HEIC)만 파일로 받는다. HEIC는 원본을 두고 JPEG를 만들어 글자 읽기와 미리보기에 쓴다. 그 밖의 파일은 저장하지 않고 항목마다 알린다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 받는 형식 | 아래 "값" 표의 파일 형식. 서버가 앱에 이 목록을 알려 준다 |
| 내용 판별 | 확장자가 아니라 파일 앞부분의 바이트(시그니처)로 형식을 판정하는 것 |

## 규칙

1. 서버는 받는 형식의 파일만 저장한다. 링크와 붙여 넣은 글은 이 정책과 상관없이 저장한다.
2. 형식은 내용 판별로 정한다. 확장자와 내용이 다르면 내용을 따른다. md와 txt는 UTF-8 글자 파일이면 받는다.
3. 받는 형식이 아닌 파일은 저장하지 않고, 그 항목만 ✗로 알린다. 함께 보낸 다른 항목은 저장한다.
4. 앱은 서버가 알려 준 목록으로 미리 걸러 보내기 전에 알린다(DSK-002 등). 최종 판정은 서버가 한다.
5. HEIC는 원본을 보관하고, 서버가 JPEG를 만들어 글자 읽기(F16)와 미리보기에 쓴다. 같은 파일 판정(COM-001)은 원본 바이트로 한다.
6. 암호가 걸렸거나 글자를 꺼내지 못한 PDF와 docx는 파일로 저장하되, `본문 못 가져옴`으로 표시한다.
7. 파일 크기 상한은 공통 영역 열린 질문(임시 20MB)을 따른다.
8. 파일이 크기 상한(COM-005)을 넘으면, 그 항목은 저장하지 않고 파일 이름과 크기를 넣어 ✗로 알린다. 나머지 항목은 저장한다.

## 값

| 종류 | 형식 | 본문 처리 |
| :--- | :--- | :--- |
| 문서 | PDF | 글자 추출 |
| 문서 | md, txt | 그대로 본문 |
| 문서 | docx | 글자 추출(Tika, 한국어 품질은 스파이크로 확인) |
| 이미지 | PNG, JPEG, WebP | 글자 읽기(F16, LLM 비전) |
| 이미지 | HEIC | JPEG로 바꿔 글자 읽기 |
| 받지 않음 | 그 밖의 모든 형식(GIF, zip, hwp, pptx, xlsx, 영상, 음성 등) | 저장하지 않는다. 영상·음성 등은 이후(F10) |

## 사용자 문구

| 상황 | 제목 | 본문 | 버튼 |
| :--- | :--- | :--- | :--- |
| 받지 않는 형식 | 없음 | `✗ 저장 안 됨: 받지 않는 형식 (.zip)` | 없음 |
| 끌어 오기 안내 | 없음 | `링크 · 글 · 이미지 · PDF · md · docx` | 없음 |
| 글자를 꺼내지 못함 | 없음 | `! 본문 못 가져옴: 암호 걸린 PDF` 또는 `! 본문 못 가져옴: 글자 없음` | 없음 |
| 크기 상한을 넘음 | 없음 | `✗ 저장 안 됨: 20MB 넘음 (<파일 이름> · <크기>)` | 없음 |

## 검증 방법

| 종류 | 확인할 것 |
| :--- | :--- |
| 자동 테스트 | 형식별로 저장되거나 막히는지. 확장자를 바꾼 파일이 내용대로 판정되는지. 받지 않는 형식이 섞인 여러 파일에서 나머지만 저장되는지. 구현 후 기입 |
| 자동 테스트 | HEIC가 원본으로 보관되고 JPEG로 글자 읽기가 되는지. 암호 걸린 PDF가 "본문 못 가져옴"으로 저장되는지. 구현 후 기입 |

## 비고

- 형식 범위는 PRD 14절 4번에 따라 개발자가 확인해야 한다. docx는 Tika 한국어 추출 품질이 부족하면 이후(F10)로 뺄 수 있다.
- 서버 테스트 폴더가 정해지면 `Scripts/check-policy-acceptance.sh`에 이 정책의 형식 목록 규칙을 더한다.
