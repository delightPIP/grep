# COM-008 넘기기는 이어 쓰기 결과가 5건을 넘으면 묻고, 복사에 성공하면 선택을 풀고, 실패하면 선택을 남기고 직접 복사할 길을 보인다
- 상태: 확정
- 적용 범위: 모든 플랫폼의 `넘기기`(웹·데스크톱은 클립보드 복사, 모바일은 공유 시트와 복사)와 이어 쓰기 `찾기 … | 넘기기`

> **요약** 이어 쓰기 결과가 5건 이하면 바로 복사하고, 6~10건이면 `전부`만, 11건 이상이면 `앞10`·`전부`를 묻는다. 선택한 자료를 `넘기기`로 복사하는 데 성공하면 선택을 푼다. 복사에 실패하면 `복사됨`을 보이지 않고 선택을 남기며, 클립보드가 막힌 경우에는 넘길 글을 펼쳐 직접 복사하게 한다.

## 용어

| 용어 | 뜻 |
| :--- | :--- |
| 넘길 글 | `넘기기`가 만드는 글([넘길 글 형식](../../planning/handoff-format.md)) |
| 클립보드 거부 | 브라우저나 OS가 클립보드 쓰기를 막은 경우 |

## 규칙

1. 이어 쓰기 결과가 5건 이하이면, 클라이언트는 묻지 않고 바로 복사한다.
2. 6건 이상 10건 이하이면, 클라이언트는 복사하지 않고 `전부`만 선택지로 묻는다.
3. 11건 이상이면, 클라이언트는 복사하지 않고 `앞10`과 `전부`를 선택지로 묻는다.
4. 선택지의 답은 COM-007을 따른다. 모바일의 선택 버튼도 같은 경계를 따른다.
5. 넘기기가 실패하면, 클라이언트는 `✓ 복사됨`을 보이지 않고 실패 줄을 보인다. 선택은 풀지 않고, 넘기기로 세지 않는다.
6. 실패 이유가 `클립보드 거부`이면, 클라이언트는 넘길 글 미리보기를 펼쳐 전체를 선택해 두고 직접 복사하는 키를 안내한다.
7. 실패 이유가 그 밖의 것이면, 다시 하는 명령 `→ 넘기기`만 안내한다.
8. 선택한 자료를 `넘기기`로 복사하는 데 성공하면, 클라이언트는 선택을 모두 푼다. 따로 줄을 찍지 않고, 상태줄의 `선택 N`과 입력줄 위 선택 줄이 사라진다. 실패하면 규칙 5대로 선택을 남긴다.
9. 이어 쓰기 `찾기 … | 넘기기`는 찾기 결과를 넘기고, 이미 고른 선택은 건드리지 않는다.

## 값

| 항목 | 값 | 경계 |
| :--- | :--- | :--- |
| 바로 복사 | 5건 이하 | 5건까지 바로 복사 |
| `전부`만 묻기 | 6~10건 | 10건은 `전부`만 |
| `앞10`·`전부` 묻기 | 11건 이상 | 11건부터 `앞10`이 나온다 |
| 실패 이유 | `연결 끊김`, `응답 없음`, `서버 오류`, `클립보드 거부` | 이 넷만 |
| 직접 복사 키 안내 | `Ctrl+C` | macOS는 `⌘C`, 터치 기기는 `길게 눌러 복사`(AI 제안, PO 확인 전) |

## 근거

- PO 결정(2026-11-26, AI 제안 수용): 6~10건은 `전부`만(STATE 결정 로그, PR #24), 넘기기 실패 문구와 이유·선택 유지(STATE 결정 로그, PR #24), 클립보드 거부면 미리보기 전체 선택과 직접 복사 안내를 더함([흐름 점검표](../../planning/flow-inventory.md) 8절 P2·P3)
- PO 결정(2026-11-27): 규칙 8·9. 넘기기에 성공하면 선택을 풀고 새 줄은 찍지 않는다. 이어 쓰기는 선택을 건드리지 않는다. 선택 빼기·비우기(`고르기 빼기`·`고르기 비우기`)가 발표 뒤라서(흐름 점검표 P8), 데모에서 넘기기를 두 번 하면 앞 자료까지 넘어가는 것을 막는다(PR #84 리뷰)
- US-5, 명령어 설명서 4절·6절
- 구현: 아직 없음

## 비고

- 넘기기 횟수는 북극성 지표(주간 넘기는 사용자)에 쓰인다. 실패는 세지 않는다(규칙 5).
