### ADR-BCK-017 가져온 자료도 백그라운드에서 요약하되, 직접 저장한 자료보다 뒤에 처리한다
- 상태: 채택
- 날짜: 2026-11-28
- 영역: 백엔드

> **요약** ADR-BCK-008 결정 2(북마크로 가져온 자료는 처음 열거나 넘길 때 요약)를 대체한다. 가져온 자료도 저장한 자료처럼 처리 대기열에 넣어 백그라운드에서 요약한다. 우선순위를 낮춰 직접 저장한 자료가 늘 먼저 처리된다. 하루 한도와 직접 저장 몫은 설정값이다.

#### 배경

그렙의 기본 약속은 "저장하면 백그라운드에서 알아서 요약된다"다. ADR-BCK-008은 비용이 한 번에 몰리는 것을 막으려고 가져온 자료의 요약을 열거나 넘길 때로 미뤘다. 그 결과 가져온 자료만 요약이 없는 채로 남았고, 화면은 처리 중으로 잘못 보였다(#127 통합 실측, 2026-11-28). 지금의 비용 제약은 무료 등급 하루 한도(COM-005)이고, 실배포에서는 바뀌거나 없어질 수 있다.

#### 결정

1. 가져온 자료도 저장 때 처리 작업을 만든다. 처리를 미루는 표시(`processing_deferred`)는 쓰지 않는다.
2. 작업에 우선순위를 둔다. 직접 저장(붙여 넣기·끌어다 놓기·공유·샘플·시드)은 보통, 가져오기는 낮음이다. 워커는 보통 작업을 먼저 집는다.
3. 하루 한도(COM-005)와 직접 저장 몫은 설정값이다(`GREP_DAILY_AI_LIMIT` 기본 50, 0이면 제한 없음. `GREP_DIRECT_SAVE_RESERVE` 기본 10). 낮은 우선순위 작업은 하루에 "한도 − 직접 저장 몫"까지만 처리하고, 남으면 다음 날 이어서 한다. 한도를 없애면 가져온 자료도 쉬지 않고 처리한다.
4. 가져온 자료를 `열기`나 `넘기기`로 쓰면 그 작업을 보통 우선순위로 올린다.
5. 화면 표시는 다른 자료와 같다(`요약 생성 중`). 별도 상태를 두지 않는다(ARC-005의 다섯 상태 그대로).
6. 임베딩(ADR-BCK-016)도 같은 순서로 가져온 자료를 나중에 처리한다.

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| 그대로(열거나 넘길 때만 요약) | 저장하면 알아서 요약된다는 약속이 가져온 자료에서 깨지고, 찾기·뜻 찾기에도 덜 걸린다 |
| 가져올 때 같은 우선순위로 한꺼번에 요약 | 무료 한도를 가져온 자료가 먼저 다 써서 직접 저장한 자료가 그날 요약되지 않는다 |
| 미룬 자료 표시(`deferred`)를 더해 화면만 고치기 | 화면은 사실대로 되지만 요약이 생기지 않는 문제는 그대로다 |

#### 결과

- 얻는 것: 모든 자료가 결국 요약된다. 실배포에서 한도를 없애면 설정만 바꾸면 된다.
- 비용: 무료 한도 아래서는 200건을 다 요약하는 데 며칠 걸리고, 그동안 상태줄에 `요약 생성 중 N`이 크게 보인다. 작업 큐에 우선순위 칸이 늘어난다(마이그레이션 V7).
