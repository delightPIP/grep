### ADR-BCK-005 이미지 글자 읽기(F16)는 서버가 LLM 비전으로 하고, 앱이 기기에서 읽은 글자는 함께 받는다
- 상태: 채택
- 날짜: 2026-11-25
- 영역: 백엔드

> **요약** 이미지·스크린샷 안의 글자는 서버 처리 워커가 LLM 비전으로 읽어 검색에 걸리게 한다. 모바일 앱이 기기 안 글자 인식으로 읽은 글자를 저장 요청에 함께 보내면, 서버는 그 글자를 쓰고 LLM 호출을 생략한다.

#### 배경

클라이언트는 웹부터 만든다. 웹 브라우저에는 쓸 만한 기본 글자 인식 기능이 없다(Shape Detection API의 `TextDetector`는 Chrome에서도 플래그 뒤에 있다). iOS(Vision)와 Android(ML Kit)는 기기 안에서 한국어 글자를 읽을 수 있다. 설문에서 이미지·스크린샷은 링크만큼 많이 저장되었다([설문 결과](../../planning/survey-result.md)).

#### 결정

1. 이미지가 저장되면 서버 처리 워커가 LLM 비전으로 글자를 읽어 본문으로 저장하고 검색 대상에 넣는다. 요약을 서버 LLM으로 하게 되면 같은 호출에서 함께 처리할 수 있다.
2. 저장 API는 클라이언트가 기기 안에서 읽은 글자를 선택 필드로 받는다. 이 값이 있으면 서버는 그 글자를 쓰고 LLM 호출을 생략한다.
3. 글자가 없거나 읽지 못한 이미지는 기획서 10절대로 저장 시각과 출처로만 찾을 수 있다고 알린다.

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| 서버 Tesseract (무료 OCR) | 비용은 0이지만 한국어 스크린샷 품질이 불안정하고, 서버 컨테이너에 네이티브 프로그램과 언어 데이터를 설치해야 한다 |
| 브라우저 Tesseract.js | 언어 데이터가 무겁고 웹에만 해당한다. 결과가 서버 판정(ADR-0001)이 아니다 |
| 기기 안 글자 인식만 사용 | 웹에서 할 수 없고, 플랫폼마다 결과가 다르다 |
| 클라우드 OCR (Google, Azure 등) | 요약과 별개인 제공사 계약과 키가 하나 더 생긴다 |

#### 결과

- 얻는 것: 한국어 스크린샷도 높은 품질로 읽고, 구현은 API 호출 한 번이다. 웹을 포함한 모든 클라이언트가 같은 결과를 얻는다. 모바일에서는 외부 호출 없이 처리할 수 있다.
- 비용: 이미지마다 소액이 든다(Haiku급 기준 1장에 약 $0.0003). 웹에서 올린 이미지는 외부 LLM 제공사로 보내므로, 열린 질문의 "외부 LLM으로 보낼 수 있는 범위"에 답이 필요하다. LLM이 장애일 때는 글자 읽기가 늦어진다.

#### 관련

ADR-0001, ADR-BCK-002, ADR-BCK-004
