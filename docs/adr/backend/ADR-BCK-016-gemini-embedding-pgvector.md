### ADR-BCK-016 뜻이 가까운 찾기는 Gemini 임베딩을 처리 워커에서 만들고 pgvector에 둔다
- 상태: 채택
- 날짜: 2026-11-27
- 영역: 백엔드

> **요약** F15(뜻이 가까운 자료 찾기)의 임베딩은 처리 워커가 요약을 만든 뒤 Gemini 임베딩 모델 무료 등급으로 만들고, 768차원으로 줄여 `items.embedding`(pgvector)에 둔다. 찾기 결과가 0건이거나 적을 때만 뜻 검색 결과를 보탠다.

#### 배경

ADR-BCK-002 결정 4는 의미 검색을 pgvector로 붙인다고 정했지만 임베딩을 어디서 무엇으로 만들지는 정하지 않았다. COM-005는 무료 플랜만 허용한다. 요약에는 이미 Gemini 무료 등급을 쓴다(ADR-BCK-014).

#### 결정

1. 처리 워커가 요약을 만든 뒤 Gemini 임베딩 모델(`gemini-embedding-001`, 설정값 `GEMINI_EMBEDDING_MODEL`)로 임베딩한다. 입력은 제목·요약·본문 앞부분이다.
2. 임베딩은 768차원으로 줄여 `items.embedding vector(768)`에 둔다(Supabase pgvector 확장).
3. 찾기 결과가 0건이거나 적을 때만 뜻이 가까운 자료를 보탠다(user-flow 5절 표 4번). 휴지통 자료는 빼고, 같은 사용자 자료만 본다(COM-006).
4. 임베딩 호출 수는 요약 하루 한도(COM-005)와 따로 센다. 한도를 넘으면 임베딩만 미루고 저장·요약은 그대로 한다.
5. 무료 키에서 일괄(batch) 호출이 막힌다는 보고가 있어 한 건씩 부른다. 실제 무료 한도는 착수 때 AI Studio에서 확인하고 값 칸에 적는다.

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| 서버 안에서 작은 다국어 임베딩 모델(ONNX) 실행 | 호출 비용은 없지만 무료 소형 서버(ADR-0011)에서 JVM과 함께 메모리를 많이 쓴다(ADR-BCK-003 비용) |
| 유료 임베딩 API | 비용이 든다(COM-005) |
| PGroonga 부분 일치만 | 낱말이 다르면 찾지 못한다(F15를 채우지 못함) |

#### 결과

- 얻는 것: 호출 비용 없이 낱말이 달라도 찾는다. 요약과 같은 제공사·키를 쓴다.
- 비용: 무료 등급 한도가 공식 표에 분명하지 않다(커뮤니티 답변 기준 하루 약 1,000회). 입력이 Google 학습에 쓰일 수 있어 COM-002 규칙 3(팀 자료만)을 그대로 따른다. 이미 저장된 자료는 한도 안에서 나눠 채운다.

#### 관련

ADR-BCK-002(결정 4 구체화), ADR-BCK-014, ADR-0011, COM-002, COM-005, COM-006, #128
