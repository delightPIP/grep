### ADR-BCK-015 AI 도구 연결(MCP)은 그렙 서버가 OAuth 인가 서버가 되어 연결마다 토큰을 준다
- 상태: 채택
- 날짜: 2026-11-27
- 영역: 백엔드

> **요약** 원격 MCP 서버의 사용자 인증은 그렙 서버가 직접 OAuth 2.1 인가 서버를 제공해서 한다. 로그인은 기존 Supabase 로그인을 쓰고, 승인하면 연결마다 토큰을 발급해 `connections` 표에 해시로 둔다. 도구는 읽기 전용 두 개(검색, 읽기)다.

#### 배경

F7(AI 도구 연결)은 AI 도구가 그렙 자료를 검색하고 읽게 한다. 원격 MCP 서버는 사용자별 인증이 필요하고, MCP 인가 사양은 토큰을 주소에 넣는 것을 금지해 OAuth나 요청 헤더를 쓰게 한다. ACC-002는 연결을 하나씩 보고 끊고, 모든 기기 로그아웃 때 모두 끊게 한다. ARC-009는 연결 승인 화면을 무료로 띄울 수 있는지 개발 확인을 요구했다. ADR-BCK-003은 MCP를 공식 Kotlin SDK로 만들기로 했지만 원격 OAuth 지원은 확인이 필요하다고 남겼다.

#### 결정

1. 그렙 서버가 OAuth 2.1 인가 서버를 제공한다. 동적 클라이언트 등록, PKCE, 보호 자원 메타데이터(`/.well-known/oauth-protected-resource`)와 인가 서버 메타데이터를 둔다.
2. 승인 화면에서 로그인은 기존 Supabase 로그인(ACC-001)을 쓴다. 승인 화면의 도구·계정 줄과 문구는 ARC-009를 따른다.
3. 승인하면 연결 토큰을 발급한다. 토큰은 `connections` 표에 해시로만 저장하고, 연결 이름(AI 도구)·만든 시각·마지막 사용 시각을 둔다. 연결 목록과 하나씩 끊기, 모든 기기 로그아웃 때 전부 끊기(ACC-002)는 이 표로 한다.
4. MCP 도구는 읽기 전용 두 개다. 검색은 요약을, 읽기는 본문 텍스트를 돌려주고 원본 파일은 주지 않는다(ARC-009). 넘길 글은 앱의 `넘기기`와 같은 서버 함수를 쓴다(ADR-0001 결정 4). 응답의 식별자는 자료 번호다(ARC-001).
5. 착수 첫 단계에서 Claude·ChatGPT 커넥터로 실제 연결이 되는지 실험한다. 공식 Kotlin SDK가 원격 OAuth를 받쳐 주지 못하면 인가 엔드포인트는 Spring으로 직접 만들고 SDK는 도구 처리에만 쓴다.

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| 앱에서 개인 토큰을 발급해 요청 헤더로 넣기 | 가장 쉽지만 OAuth만 받는 커넥터(claude.ai, ChatGPT)에 붙지 않는다 |
| Supabase Auth를 OAuth 인가 서버로 쓰기 | 연결 단위로 끊기와 승인 화면을 그렙이 다루기 어렵고 Supabase 기능에 묶인다(ADR-BCK-006) |
| 외부 인증 서비스(WorkOS 등) | 무료 범위가 불확실하고 의존이 하나 늘어난다(COM-005) |

#### 결과

- 얻는 것: 비용 없이 어느 AI 도구에나 붙는다. 연결 목록과 끊기를 그렙 표 하나로 관리한다.
- 비용: OAuth 엔드포인트와 토큰 수명 관리를 직접 해야 한다. 커뮤니티에는 claude.ai 커넥터의 OAuth 흐름이 등록 뒤 멈추거나 토큰 만료 뒤 끊긴다는 보고가 있어, 결정 5의 실험에서 함께 확인한다.

#### 관련
