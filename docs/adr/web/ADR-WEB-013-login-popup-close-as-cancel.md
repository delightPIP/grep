### ADR-WEB-013 웹 로그인 창 닫힘은 그렙 창이 포커스를 되찾는 것으로 알고, 바로 취소로 처리한다
- 상태: 채택
- 날짜: 2026-11-26
- 영역: 웹

> **요약** 로그인 팝업을 닫아 그렙 창이 포커스를 되찾고 1.5초 안에 결과가 없으면 `✗ 로그인 취소됨`으로 끝낸다. 2분 `응답 없음`은 포커스 신호가 없을 때의 안전망으로만 둔다. ADR-WEB-012의 결정 3을 대체한다.

#### 배경

ADR-WEB-012는 Google 로그인 페이지의 `Cross-Origin-Opener-Policy` 때문에 팝업 닫힘을 알 수 없어서, 2분 뒤 `✗ 로그인 실패: 응답 없음`으로 끝냈다. 그러면 창을 닫았을 때 ACC-001 규칙 8(`✗ 로그인 취소됨`)과 다르고, 그동안 버튼이 잠긴다. 데모에서 창을 닫는 실수가 나면 2분을 기다려야 한다.

#### 결정

1. 그렙 창의 `focus`와 `visibilitychange`(visible)를 로그인 창에서 돌아온 신호로 본다.
2. 돌아온 뒤 1.5초 안에 콜백 결과가 없으면 취소로 끝낸다. 결과가 그 안에 오면 정상 처리한다.
3. 취소로 끝난 뒤 늦게 온 결과는 버린다(세션으로 바꾸지 않는다). 사용자는 다시 누른다.
4. 2분 시간 초과는 안전망으로 남긴다. ADR-WEB-012의 나머지 결정(팝업, BroadcastChannel 콜백, 로그인 모듈 한 곳)은 그대로다.

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| 전체 페이지 이동(Supabase 기본) | 가장 안정적이지만 코어 계약에 "돌아온 뒤 결과 읽기"가 필요하고, 만료 때 치던 줄을 따로 저장해야 해서 코어와 웹을 모두 고친다. 데모 일정에 비해 크다 |
| 버튼을 잠그지 않고 같은 이름의 창을 재사용 | 다시 누를 수는 있지만 닫았을 때 문구가 없어 ACC-001 규칙 8을 지키지 못한다 |
| 2분 대기 유지(ADR-WEB-012) | 배경의 문제가 그대로 남는다 |

#### 결과

- 얻는 것: 창을 닫으면 1~2초 안에 정책 문구가 나온다. 코어 계약을 바꾸지 않는다.
- 비용: 로그인 도중 사용자가 그렙 창을 직접 누르면 취소로 오판한다. 그때 늦게 온 결과는 버려져 다시 로그인해야 한다. 포커스 신호가 실제 브라우저(Chrome, Safari)에서 바로 오는지는 브라우저에서 확인해야 한다.

#### 관련

ADR-WEB-012(결정 3 대체), ACC-001 규칙 8·9, ADR-BCK-006 결정 7, 이슈 #31
