### ADR-0016 데모 배포에서 웹은 서버가 함께 내보내고, 무료 서버는 외부 핑으로 깨워 둔다
- 상태: 채택
- 날짜: 2026-11-28
- 영역: 공통

> **요약** ADR-0011 결정 2(웹은 Cloudflare Pages)를 대체한다. 서버 Docker 이미지에서 웹(Swift Wasm 브리지 + Vite)을 함께 빌드해 Spring이 정적 파일로 내보내고, Render 서비스 하나로 웹·API를 같은 주소에서 연다. 무료 인스턴스가 잠들지 않게 외부 무료 핑이 `/health`를 10분마다 부른다.

#### 배경

ADR-0011은 웹을 Cloudflare Pages에 올리기로 했다. Pages 빌드 환경에는 Swift가 없어 Wasm을 GitHub Actions에서 빌드해 올려야 하는데, 그러려면 레포 비밀값(Cloudflare 토큰)이나 호스팅 서비스의 GitHub 앱 설치가 필요하고 둘 다 레포 관리자 권한이 있어야 한다. 개발자 계정은 push 권한만 있다. 또 Render 무료 인스턴스는 15분 동안 요청이 없으면 잠들어 웹·iOS·Android 모두 첫 요청이 약 1분 걸린다.

#### 결정

1. `server/Dockerfile`에 웹 빌드 단계를 더한다. Swift 이미지에서 Wasm 브리지를 만들고, Node로 `web/dist`를 만들어 Spring 정적 자원으로 넣는다.
2. 웹은 서버와 같은 주소에서 열고, API는 같은 출처로 부른다(`VITE_API_BASE_URL`은 비워 두면 같은 출처). CORS 허용 출처(`WEB_ORIGIN`)는 로컬 개발용으로만 남긴다.
3. 외부 무료 핑 서비스가 `/health`를 10분마다 불러 인스턴스를 깨워 둔다. Render 무료 750시간/월 안에서 서비스는 하나만 둔다.
4. 웹을 따로 호스팅으로 옮길 때는 같은 `web/dist`를 올리고 `VITE_API_BASE_URL`·`WEB_ORIGIN`만 바꾼다(ADR-0011 이식 규칙 그대로).

#### 고려한 대안

| 대안 | 기각 이유 |
| :--- | :--- |
| Cloudflare Pages 자동 배포(ADR-0011 원안) | 레포 비밀값을 넣으려면 관리자 권한이 있어야 한다 |
| Cloudflare Pages·Vercel에 손으로 올리기 | 배포마다 로컬에서 Wasm 빌드와 업로드를 해야 하고 계정이 하나 더 든다. Vercel Hobby는 비상업용만 된다 |
| Render 정적 사이트를 따로 둠 | 무료 시간 750시간을 두 서비스가 나눠 써 둘 다 깨워 둘 수 없다. 빌드 환경에 Swift가 없는 것도 같다 |
| GitHub Pages | 켜려면 관리자 권한이 있어야 한다 |

#### 결과

- 얻는 것: 계정 하나(Render), 비밀값·관리자 권한 불필요, 같은 출처라 CORS·쿠키 설정이 단순, 서버를 깨워 두면 웹도 빠름
- 비용: 서버 이미지 빌드가 길어진다(Swift·Node 단계). 서버를 다시 배포하지 않으면 웹도 바뀌지 않는다. 핑 서비스가 멈추면 다시 잠든다
