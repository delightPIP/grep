# PO 전문가 첨삭 요청 프롬프트

그렙을 전혀 모르는 PO 전문가(사람이든 AI든)에게 그대로 붙여 넣어 쓰는 글이다. 2026-11-26 기준 [기획서](PRD.md) 0.7과 [명령어 설명서](commands.md)를 바탕으로 썼다. 기획이 바뀌면 이 글도 고친다.

---

```text
당신은 B2C 서비스 기획 경험이 많은 시니어 PO입니다. 아래 서비스 기획을 처음 보는 사람의 눈으로 첨삭해 주세요.
칭찬보다 약한 고리를 찾는 데 집중해 주시고, 우리가 이미 정한 것과 아직 열려 있는 것을 구분해서 봐 주세요.

# 1. 상황
- 서비스 이름: 그렙(grep). 팀: 2명(PO 1, 개발 1).
- 성격: 실제 출시가 아니라 프로젝트성 과제. 범위는 기획 → 개발 → 발표(2026-12-01)까지.
- 개발 기간: 나흘(11/26~29). 첫 플랫폼은 웹.
- 사용자 인터뷰·일지 연구는 하지 않기로 했습니다. 근거는 설문 12명, 경쟁 서비스 공개 자료, 팀의 직접 사용뿐입니다. 그래서 문제·원인은 모두 가설이고, 발표에서 한계로 밝힐 예정입니다.

# 2. 한 줄 요약
SNS·유튜브·웹 등에서 저장해 둔 자료를 한 아카이브에 모아 두고, Claude·ChatGPT 같은 AI 도구에 일을 시킬 때 그 자료를 골라 요약과 함께 넘겨주는 서비스.
화면은 "터미널 느낌"이고 쉬운 한글 명령어 몇 개로 씁니다(진짜 명령줄 도구는 아님).

# 3. 누구의 어떤 문제인가 (가설)
- 누가: AI 도구로 주 3회 이상 작업(코드, 문서, 조사 등)을 하고, 레퍼런스를 2곳 이상의 저장 수단(스레드 저장, 유튜브 나중에 볼 동영상, 브라우저 북마크, 캡처 등)에 나눠 저장하는 "AI 활용자". 직군 무관.
- 언제: 프로젝트 중 AI 도구에 일을 시킬 때.
- 무엇이 문제: 저장해 둔 자료가 떠오르지 않거나, 떠올라도 여러 곳에 흩어져 있어 모아 넘기지 못한다.
- 그래서: 자료 없이 묻거나 같은 검색을 다시 하고, 결과물이 평범해지며, 저장한 자료는 쓰이지 않는다. 대화가 바뀌면 같은 자료를 또 넣는다.

원인 가설(모두 미검증)
- N1 흩어짐: 자료가 여러 저장 수단에 나뉘어 한 번에 못 모은다.
- N2 못 찾음: 넣고 싶은 자료를 저장 수단에서 찾아내지 못한다.
- N3 형식: 로그인 필요한 링크, 영상, 스크린샷, 긴 PDF라 그대로 못 넣는다.
- N4 양: 관련 자료가 많아 골라 줄이는 데 시간이 든다.
- N5 다시 넣기: 새 대화·다른 AI 도구로 옮기면 같은 자료를 또 넣어야 한다.
- N6 회사 자료 제약: 업무 자료를 AI에 넣어도 되는지 몰라서 안 넣는다.
- N7(후보) 떠올리지 못함: 잊은 사람은 잊은 줄 모른다.
우리 차별점은 N1과 N5를 겨냥합니다.

# 4. 근거: 설문 12명 (방향만 봄)
- 지난 4주, 저장해 둔 걸 모르고 또 찾거나 또 저장한 적 2번 이상: 6명 (모르겠다 4, 없다 2)
- "검색하면 대체로 바로 찾는다" 동의: 2명 (비동의 6, 보통 4)
- 저장 이유: "언젠가 쓸 것 같아서" 8명, "곧 작업에 쓰려고" 0명
- 저장 형식: 링크 9명, 이미지·캡처 7명
- 못 찾았을 때 8건 중 7건이 비슷한 자료를 새로 찾아 씀. 8건 중 6건은 대략 언제 저장했는지는 기억함
- 한계: 경력 1년 미만이 12명 중 7명. AI 사용 여부는 묻지 않음(설문이 이전 문제 정의 기준).

# 5. 해결 방향 (PO가 고정한 것)
- 해결: 여러 곳의 자료를 한 아카이브에 저장하고, AI 도구가 쓸 수 있게 요약해 넘긴다.
- 원칙: AI와 경쟁하지 않는다. 앱 안에서 답변 생성·대화를 하지 않고 "넘기는 쪽"에 선다.
- 컨셉: 터미널 느낌 화면 + 한글 명령어. 입문자에게는 "개발자가 된 듯한 경험"을 준다. 화면 문구도 진짜 터미널처럼 건조하게(`저장됨`, `4건`).
- 차별점: AI가 알아서 찾아 읽는 연결형 서비스와 달리, 사용자가 명령어로 자료를 직접 골라 묶어 어떤 AI 도구에든 넘긴다.
- 넘기는 방식 순서: ① 붙여 넣을 글로 복사(주) ② AI 도구에 직접 연결(MCP, 읽기 전용).
- 첫 시장: 국내, 한국어.
- 북극성 지표: 주간 넘기는 사용자(한 주에 넘기기를 한 날이 하루 이상인 사용자 수). 기준값·목표값은 없음.

사용 예
  그렙 ~ $ 찾기 결제        → 결제 관련 저장 자료 4건
  그렙 ~ $ 고르기 1 3       → 1번, 3번 선택
  그렙 ~ $ 넘기기           → AI 도구에 붙여 넣을 글(요약+링크) 복사
  그렙 ~ $ 찾기 결제 | 넘기기   (한 줄로 이어 쓰기)
명령: 담기, 최근, 찾기, 고르기, 넘기기, 묶음(이름 붙여 다시 넘기기), 고치기, 버리기, 가져오기(북마크), 연결, 도움말. 모두 영문판이 있음.

# 6. 경쟁 (공개 자료 기준, 직접 써 보지 않음)
- AI 도구 안에 자료를 올려 둠: ChatGPT 프로젝트, Claude 프로젝트 → 다른 회사 AI로 못 넘김
- 저장 수단 하나를 AI에 연결: Raindrop, Readwise, Notion 등 → 저장 수단마다 따로 연결, AI 요금제 제약
- 여러 출처를 모아 여러 AI에 연결: Supermemory, MyMemory → 국내 저장 수단은 확인 못 함
- AI 입력창에 저장 자료를 끼워 넣는 브라우저 확장: Supermemory, MemoryPlugin → 우리 차별점과 겹칠 수 있음(미확인)

# 7. 범위
데모에서 반드시 되는 것(개발자 확정)
1. 로그인(Google·GitHub)
2. 붙여 넣기·끌어다 놓기로 저장, 같은 링크면 "이미 저장됨 → N번" 알림, 요약 자동 생성
3. 단어로 다시 찾기
4. 골라서 붙여 넣을 글로 복사
+ 첫 화면 도움말
- 핵심 성공 기준: 저장해 둔 한국어 자료를 찾아 붙여 넣을 글로 복사하기까지 1분 안.
- 되면 보여 줄 것: 이름 붙인 묶음 → 스크린샷 속 글자로 찾기 → AI 도구 연결(MCP)
- MVP 안의 나머지: 기기 동기화, 북마크 가져오기, 뜻으로 찾기, 시점으로 찾기(`찾기 결제 지난달`), 잘못 친 명령 고쳐 주기
- 이후: 다른 앱(노트 앱, 카톡 나에게 보내기 등)에서 가져오기, 영상 내용, 브라우저 확장, 작업에 맞춘 요약
- 안 함: 앱 안 AI 대화, 팀 공유 공간, 화면 자동 기록, 사용자가 직접 붙이는 태그·하위 폴더
- 수익 구조·가격은 이번 범위 밖.

# 8. 우리가 알고 있는 약점
- MVP는 "앞으로 저장할 자료"만 받고 기존 저장 수단의 자료는 못 가져온다. 저장 수단이 하나 더 늘어 흩어짐이 오히려 커질 수 있다.
- "직접 골라 넘긴다"는 차별점과 "잊은 사람은 잊은 줄 모른다"는 문제 인식이 충돌할 수 있다(잊었으면 직접 고를 수도 없다).
- 비개발자가 터미널 느낌 화면을 반길지 꺼릴지 모른다.
- 저장할 때 한 번 만든 요약을 넘긴다. 작업에 맞는 요약은 아니다.
- 사용자가 자료를 서버에 올리고 요약을 위해 외부 LLM으로 보내는 것을 받아들일지 모른다.

# 9. 첨삭해 주셨으면 하는 것
아래 질문에 답해 주시고, 질문 밖이라도 치명적이라고 보이는 것이 있으면 먼저 말해 주세요.
1. 문제 정의: "누가·언제·무엇을 못 해서·어떤 손해"가 하나의 이야기로 이어지나요? 대상이 너무 넓거나 흐리지 않나요?
2. 문제와 해결의 연결: 문제는 "떠올리지 못함"을 강조하는데 해결은 "직접 골라 넘기기"입니다. 이 간극을 어떻게 메우거나 설명하는 게 좋을까요?
3. 차별점: 경쟁 서비스 대비 "직접 골라 어떤 AI에든 넘긴다"가 사용자에게 이유가 되는 차별점인가요, 아니면 기능 차이에 그치나요?
4. 컨셉: 터미널 느낌 + 한글 명령어가 대상(개발자와 비개발자 AI 활용자 모두)에 맞나요? 대상을 좁혀야 할까요?
5. 범위: 4일·1인 개발에서 데모 필수 범위가 문제를 보여 주기에 충분하고 적절한가요? 빼거나 더할 것은?
6. 지표: 북극성 "주간 넘기는 사용자"가 이 서비스의 가치를 잘 대표하나요? 더 나은 대안이 있다면?
7. 근거: 인터뷰 없이 설문 12명뿐인 상황에서, 발표 때 근거의 한계를 어떻게 정직하면서도 설득력 있게 말할 수 있을까요?
8. 발표 관점: 심사자가 가장 먼저 찌를 질문 3개와, 그에 대한 좋은 답의 방향은?
```
