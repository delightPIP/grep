# 페르소나 초안

작성일 2026-11-24. [기획 상태 문서](STATE.md)의 1단계 범위(대상: 개발자·PO·디자이너, 자료 형식: 모든 형식, 원인은 열어 둠)를 기준으로 만들었다. 원래 5단계 산출물을 앞당겨 쓴 초안이며, 비평 1회를 반영했다.

> **주의** 아래 모든 인물은 가상 인물이다. 인터뷰로 검증해야 한다. 장면은 팀의 가정이며, 근거 ID가 붙은 부분만 근거 레지스트리(STATE 7절)의 연구·사용자 목소리와 닮은 부분이다. 근거 ID가 붙어도 그 근거가 이 장면을 증명하지는 않는다.

## 설계 원칙

- 페르소나 하나에 주 원인 후보(STATE 6절 A~H) 하나를 둔다. 인터뷰에서 어떤 원인이 실제로 많은지 가르기 위해서다.
- 후보 E(분류를 건너뜀)는 대상 페르소나가 아니라 반례 R3으로 시험한다. 분류하는 사람도 실패하는지가 E의 반증 조건이기 때문이다.
- 모든 대상 페르소나는 스크리너 본 트랙 조건(아래)을 통과하도록 저장 수단 수, 주당 저장 횟수, 다시 찾기 시점을 적었다.
- 모든 장면의 손해는 STATE 2절 손해 세 가지(웹 다시 검색, 포기, 작업에 쓰이지 않음) 중 하나로 끝난다.
- 열어 둔 브라우저 탭은 저장 수단으로 보지 않는다(STATE 4절 저장 수단 정의).

## 인터뷰 모집 구성 (초안)

- 본 트랙 6~8명, 비교 트랙 2~4명. 총 8~12명
- 반례 유형 R1~R4 각 1명 이상
- 직군별 최소 2명(개발자, PO, 디자이너)
- 주 자료 형식이 링크가 아닌 사람(이미지·스크린샷·PDF·영상·로컬 파일)을 절반 이상
- 스크리너 탈락자는 탈락 사유(Q1~Q4)별로 수를 따로 기록한다. Q4 탈락 비율은 STATE 5-1 반증 조건 2의 선택 편향 확인에, Q2 탈락 비율은 원인 후보 B의 표본 확인에 쓴다

## 인터뷰에서 쓸 질문 방향 (요약)

자세한 인터뷰 가이드는 5단계에서 만든다. 지금 정한 원칙만 적는다.

- 과거 행동만 묻는다. "최근에 저장해 둔 걸 다시 찾으려 했던 때를 하나 떠올려 주세요."
- 떠올린 단서를 유도하지 않는다. "무슨 조사 중이었는지 기억나세요?" 대신 "그때 무엇을 기억하고 찾기 시작하셨어요?"
- 실패 사례와 성공 사례를 각각 하나 이상 받는다(STATE 2절 원인 지표).
- 찾지 못한 뒤 무엇을 했는지 묻는다(웹 다시 검색, 포기, 동료에게 질문 등). 저장 수단을 먼저 찾아봤는지도 묻는다(STATE 5-1 반증 조건 3).
- 해결책 질문은 맨 마지막에 둔다.
