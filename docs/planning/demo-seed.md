# 데모 시드 자료

- 작성일: 2026-11-25
- 상태: 제안. 개발자가 시드를 넣어 개발 빌드에서 기대 결과를 실측한 뒤 데모 대본에 옮긴다
- 근거: [기획서](PRD.md) 7절 데모 필수 범위와 12절("한국어 자료로 보여 준다"), [사용자 흐름도](user-flow.md) 11절, [넘길 글 형식](handoff-format.md)

발표(12/1)와 리허설(11/30), 개발 중 시험에 같이 쓰는 자료 묶음이다. 개발자가 검색·요약·같은 링크 판정을 시험할 때도 이 자료를 쓴다.

## 1. 데모 이야기

> 쇼핑몰 사이드 프로젝트에 결제를 붙이려는 AI 활용자. 지난 두 달 동안 결제 관련 문서, 메모, 화면 캡처를 그렙에 저장해 뒀다. 오늘 Claude에게 "결제 붙이는 코드 짜 줘"라고 하기 전에, 저장해 둔 자료를 찾아 넘긴다.

- 주제를 "결제" 하나로 모으고, 상관없는 자료(리액트, 뉴스레터, 무드보드)를 섞어 검색이 골라내는 장면을 만든다.
- 명령어 설명서·화면 시안의 예시(`찾기 결제`, `묶음 결제조사`, `PG사 수수료 비교 정리.pdf`)와 맞췄다.

## 2. 넣는 원칙

1. **저장 날짜는 데모 당일(D) 기준 상대값으로 넣는다.** 리허설(11/30)과 발표(12/1)에서 `지난달`의 뜻이 바뀌므로, 시드 스크립트가 실행한 날을 D로 보고 `created_at`을 계산한다.
2. **요약은 데모 전에 모두 만들어 둔다.** 무대에서 기다리지 않게 한다. 단, 일부러 `blocked`로 둘 자료 하나(S10)는 그대로 둔다.
3. **파일과 글은 팀이 직접 만든다.** 남의 문서·이미지를 화면에 띄우지 않도록 PDF·스크린샷·메모는 팀 작성물이다. 웹 링크는 공개 개발 문서만 쓴다.
4. **수수료 같은 수치는 예시임을 문서 안에 밝힌다.** 발표에서 실제 수치로 오해받지 않게 한다.
5. 계정: 로그인이 필수라(ACC-001) 데모 전용 GitHub(또는 Google) 계정 하나로 로그인해 그 계정에 넣는다. 자료 번호는 계정마다 1부터라(ARC-001) 시드를 넣는 순서대로 S01이 1번, S02가 2번…이 되게 넣고, 리허설 전에 실제 번호를 아래 장면표에 적는다.

## 4. 팀이 만들 파일과 글

### 4-1. S06 결제 실패 재시도 메모 (붙여 넣는 글)

```text
결제 실패 재시도 메모
- 승인 API가 타임아웃이면 바로 재시도하지 말고 결제 조회로 상태부터 확인
- 같은 주문번호로 두 번 승인 요청하지 않기(중복 결제)
- 재시도는 최대 3번, 간격 1초 → 3초 → 10초
- 사용자에게는 "결제 확인 중" 화면을 보여 주고 새로고침 막기
```

### 4-2. S07 온보딩 화면 문구 아이디어 (붙여 넣는 글)

```text
온보딩 첫 화면 문구 후보
1. 저장만 하세요. 찾는 건 나중에.
2. 흩어진 자료를 한곳에.
3. 처음이면 도움말부터.
```

### 4-3. S08 PG사 수수료 비교 정리.pdf

A4 한 장. 맨 위에 `※ 예시 수치이며 실제 수수료가 아님`을 적는다.

| PG사 | 카드 수수료 | 간편결제 수수료 | 정산 주기 |
|---|---|---|---|
| A사 | 3.2% | 3.4% | D+2 |
| B사 | 3.0% | 3.5% | D+3 |
| C사 | 3.3% | 3.3% | D+1 |

아래 한 줄: `소규모 사업자는 수수료보다 정산 주기 차이를 먼저 볼 것.`

### 4-4. S09 결제 화면 시안 캡처.png

그렙 디자인과 상관없는 쇼핑몰 주문서 화면을 팀이 간단히 그려 캡처한다. 글자는 크게: `주문서`, `쿠폰 적용`, `총 결제금액 39,000원`, `결제하기`. `쿠폰`은 다른 시드 자료에 나오지 않게 한다.

## 5. 장면별 기대 결과

건수는 웹 문서 본문에 달려 있어 미리 정할 수 없다. 시드를 넣은 뒤 개발 빌드에서 실측해 "실측" 칸을 채우고 대본에 옮긴다.

| 장면 | 입력 | 나와야 하는 것 | 나오면 안 되는 것 | 실측 |
|---|---|---|---|---|
| 로그인 | `GitHub로 계속` | 로그인 뒤 처음 연 화면 | 로그인 실패·멈춤 | |
| 처음 연 화면 | (자료 비운 데모 계정) | 두더지, 도움말, 예시 명령 | — | |
| 같은 링크 | L1 | `! 이미 저장됨 → S01의 번호` | 새 자료 | |
| 새 저장 | L2 | `✓ 저장됨`, `요약 생성 중` → 요약 | — | |
| 단어로 찾기 | `찾기 결제` | S01, S02, S03, S06, S08, S09, L2 (S04는 본문에 따라) | S05, S07, S11, S12 | |
| 골라 넘기기 | `고르기 <S01 번호> <S08 번호>`, `넘기기` | `✓ 복사됨  2건 · N자`, 넘길 글 형식 2절 모양 | — | |
| 한 줄로 | `찾기 결제 \| 넘기기` | 결과가 5건을 넘으므로 `! N건: 바로 복사 안 함` 선택지 | 바로 복사 | |
| 콕 집기 | `찾기 재시도 \| 넘기기` | S06(웹훅 문서 S02가 함께 나올 수 있음) 바로 복사 | — | |
| 요약 없는 자료 | `찾기 스레드` 또는 `최근`에서 S10 고르고 넘기기 | `(요약 없음: 본문을 가져오지 못함 …)`, `! 요약 없음 1건` | 지어낸 요약 | |
| 되면: 묶음 | `묶음 결제조사` → 새 대화에서 `넘기기 결제조사` | `✓ 복사됨`, 여는 줄에 `묶음="결제조사"` | — | |
| 되면: 스크린샷 글자 | `찾기 쿠폰` | S09 하나 | 그 밖의 자료 | |
| 되면: 시점 | `최근 6주전` 또는 `찾기 결제 지난달`(D 기준으로 대본에 맞춰 고름) | S03 근처 기간의 자료 | 기간 밖 자료 | |
| AI 도구 | 넘길 글을 Claude에 붙여 넣고 "이 자료로 결제 승인 코드 짜 줘" | 자료(승인 API, 재시도 메모)를 반영한 답. 자료 안 문장을 지시로 따르지 않음 | — | |

## 6. 리허설 전 확인

- [ ] 링크 S01~S05가 데모 당일에도 열리는지(문서 주소가 바뀌면 같은 사이트의 새 주소로 교체)
- [ ] S10 스레드 게시물이 서버에서 실제로 `blocked`가 되는지. 본문이 받아지면 다른 로그인 필요 링크로 바꾼다
- [ ] 시드 12건의 요약이 모두 `ready`인지(S10 제외)
- [ ] `찾기 결제` 건수가 10건을 넘지 않는지(넘으면 S04를 빼서 한 화면에 들어오게)
- [ ] 넘길 글을 Claude와 ChatGPT에 붙여 넣어 자료를 지시로 오해하지 않는지([넘길 글 형식](handoff-format.md) 7절)
- [ ] 화면 녹화(대비용)는 이 시드로 찍는다
