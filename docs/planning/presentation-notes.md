# 발표 메모

- 작성일: 2026-11-26
- 근거: 외부 PO 첨삭(2026-11-26, [첨삭 요청 프롬프트](po-expert-review-prompt.md)로 받음)을 PO가 추천안대로 받아들인 것. 기획서 3·4·6·7·11·12절에 같은 날 반영했다
- 쓰는 곳: 12/1 발표 슬라이드와 데모 대본. 숫자와 문장은 설문 결과([survey-results.md](survey-results.md))에서 그대로 옮긴 것만 쓴다

## 1. 발표의 뼈대

첨삭의 핵심 지적: 근거가 있는 곳(N2 못 찾음, N7 떠올리지 못함), 데모가 잘 보여 주는 곳(N2), 차별점이 걸린 곳(N1 흩어짐, N5 다시 넣기)이 서로 다르다. 그래서 발표는 아래 순서로 이 간극을 직접 말한다.

1. 불리한 숫자를 먼저 꺼낸다(2절).
2. 문제를 "검색으로 다시 안 나오는 자료"로 좁힌다(3절).
3. 그렙이 푸는 범위와 풀지 않는 범위를 나눈다(4절).
4. 데모: 자료 없이 시킨 결과 → 그렙으로 넘긴 결과 → 새 대화에 다시 넘기기(5절).
5. 차별점은 사용자가 얻는 이유로 말한다(6절).
6. 근거의 한계를 세 칸으로 보여 준다(7절).
7. 예상 질문에 답한다(8절).

## 2. 불리한 숫자 먼저

- 못 찾은 8건 중 7건은 비슷한 자료를 새로 찾아 해결했다. "못 찾아도 큰 손해가 아니다"로 읽힐 수 있다.
- 저장 이유에서 "곧 작업에 쓰려고"는 0명이다(12명 중 "언젠가 쓸 것 같아서" 8명).
- 12명이라 비율로 바꾸지 않고 "몇 명 중 몇 명"으로 말한다.

## 3. 문제를 좁힌 문장

> 새로 검색하면 비슷한 자료는 나옵니다. 하지만 내가 골라 둔 예시, 내가 찍은 캡처는 검색으로 다시 나오지 않습니다. 그렙은 그 자료에 겁니다. (가설)

- 주된 손해: 내가 골라 둔 자료가 빠진 채 AI가 답해 결과물이 평범해진다(가설, 팀 자체 비교로 보여 줌).
- 부수 손해: 같은 자료를 다시 찾고 다시 넣는 시간.
- 이 문장을 말하려면 데모에서 캡처 저장과 캡처 속 글자로 찾기(F16)가 실제로 되어야 한다. 안 되면 "캡처" 대신 "내가 골라 둔 예시"만 말한다.

## 4. 푸는 것과 풀지 않는 것

| 잊은 정도 | 예 | 그렙이 푸나 |
|---|---|---|
| 어디에 뒀는지 모름 | "스레드였나 북마크였나" | 푼다(그렙에 담은 자료에 한해) |
| 무엇이 있었는지 모름, 주제는 기억 | "결제 관련 뭔가 저장했는데" | 푼다(주제어로 찾고 목록에서 알아봄) |
| 저장한 사실 자체를 잊음(N7) | 찾아볼 생각을 안 함 | 풀지 않는다 |

- 말할 문장: "그렙은 잊은 자료를 대신 떠올려 주지 않습니다. 떠올려야 할 것을 '자료 하나하나와 그 위치'에서 '주제어 하나'로 줄입니다. 찾아 주는 것은 그렙, 고르는 것은 사용자입니다."
- "이미 저장됨" 알림은 같은 링크만 잡는다. N7의 해결책으로 소개하지 않는다.
- 회사 자료 제약(N6)도 풀지 않는다. 그렙도 자료를 서버와 외부 LLM으로 보낸다.
- 이미 다른 앱에 저장해 둔 자료는 이번에 가져오지 않는다. "데모는 모인 뒤의 경험만 보여 주고, 모으는 과정은 풀지 못했다"고 말한다.

## 5. 데모 대본 순서

1. 로그인 화면 → 첫 화면 `도움말`.
2. **자료 없이** AI에 과제를 시킨 결과를 먼저 보여 준다(미리 준비한 화면).
3. 3개 이상 출처(웹 글, 캡처, 붙여 넣은 글)의 자료가 한 목록에 있는 것을 `최근`으로 보여 준다.
4. `찾기 <주제어>` → `고르기 <번호> <번호>` → `넘기기`. 한 줄 이어 쓰기(`찾기 … | 넘기기`)는 "고르지 않고 전부 넘긴다"로 읽혀 차별점과 어긋나므로 주 장면에서 쓰지 않는다.
5. AI 입력창에 붙여 넣고 결과를 2번과 나란히 놓는다.
6. **새 대화(가능하면 다른 AI 도구)** 에 같은 자료를 다시 넘긴다. 묶음(F12)이 되면 `넘기기 <묶음 이름>` 한 줄로, 안 되면 `고르기`로 다시. N5 장면이다.
7. 같은 링크를 다시 붙여 넣어 `! 이미 저장됨` 을 보여 준다.

## 6. 차별점을 이유로 말하기

차별점 문장(기획서 6절)은 바꾸지 않는다. 말로 풀 때는 아래 둘을 쓴다.

- "AI가 무엇을 읽을지 내가 정합니다. 저장함 전체를 열어 주지 않습니다."
- "연결 설정도 요금제 조건도 없이, 지금 쓰는 AI 입력창에 바로 붙입니다."

AI 도구 연결(F7)은 보관함 전체를 검색하는 방식이라 첫 문장과 어긋난다. 보여 준다면 "이미 연결해 쓰는 사람을 위한 보조 경로"로 소개한다. "개발자가 된 듯한 경험"은 근거가 없으므로 터미널 화면의 주된 이유로 쓰지 않는다.

## 7. 근거 장표: 세 칸

| 확인한 것 | 추론한 것 | 모르는 것 |
|---|---|---|
| 12명 중 6명이 지난 4주에 저장한 걸 모르고 다시 찾거나 다시 저장한 적이 2번 이상 | "AI에 넘기는 순간"이 문제라는 것(설문 위에 얹은 가설) | 응답자가 AI 도구를 쓰는지(묻지 않음) |
| "검색하면 바로 찾는다" 동의 2명(비동의 6명) | 흩어짐(N1)과 다시 넣기(N5)가 주된 원인이라는 것 | 사람들이 "직접 골라 넘기기"를 원하는지 |
| 못 찾은 8건 중 7건은 새로 찾아 해결, "곧 쓰려고" 저장 0명 | 넘기면 결과가 나아진다는 것(팀 자체 비교 3건, 참고용) | 비개발자가 터미널 느낌 화면을 반기는지 |

- 한계: 12명 중 7명이 경력 1년 미만. "모르겠다" 4명은 증거로 세지 않는다.
- 맺음 문장: "데모는 '만들 수 있고 1분 안에 된다'까지만 보여 드립니다. '사람들이 원한다'는 보여 드리지 못합니다."

## 8. 예상 질문과 답의 방향

| 질문 | 답의 방향 |
|---|---|
| 링크를 AI에 그냥 붙이거나 프로젝트 기능에 올리면 되지 않나요? | 인정으로 시작한다: "공개 링크 한두 개를 AI 하나에 넣을 때는 지금 방식이 낫습니다." 그렙이 필요한 경우를 셋으로 좁힌다: 여러 출처의 여러 건, AI가 직접 못 여는 자료(캡처), 같은 자료를 여러 대화·여러 AI에 되풀이해 넣을 때. 데모에서 안 되는 경우는 말하지 않는다 |
| 저장하는 곳이 하나 더 느는 것 아닌가요? 이미 쌓인 자료는요? | 인정한다. 저장의 수고(링크 복사, 그렙 열기, 붙여 넣기)도 인정한다. 출시한다면 저장 수고를 줄이는 것(북마크 가져오기, 브라우저 확장)이 먼저이고, "쌓기만 하는 사용자 비율"을 경고 지표로 본다(기획서 4절). 담는 순간 돌아오는 것(요약, "이미 저장됨")을 옮겨 올 이유로 든다 |
| 왜 터미널인가요? 비개발자가 명령어를 칩니까? | 취향이 아니라 기능으로 답한다: 행동이 찾기·고르기·넘기기 세 동사로 끝나 화면보다 명령이 짧고, 넘기는 곳(AI 입력창)도 글로 시키는 곳이라 손의 흐름이 이어진다. 반길지는 검증하지 못했다고 말하고, 안전장치(누르면 입력되는 명령 버튼, 다음 행동을 알려 주는 실패 문구)를 보여 준다 |
| 프로그래머스 운영사 이름도 그렙(Grepp) 아닌가요? | 확인해 둘 것. 답: 프로젝트 이름이며 출시한다면 상표를 확인하고 바꿀 수 있다 |
