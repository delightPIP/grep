# 백엔드 설계

- 작성일: 2026-11-25
- 근거: [기획서](PRD.md), [명령어 설명서](commands.md), 데이터 중심 백엔드 설계 가이드라인(10축)
- 결정 기록: ADR-0001, ADR-BCK-002, ADR-BCK-003, ADR-BCK-004, ADR-BCK-005, ADR-BCK-006, ADR-BCK-008([ADR 목록](../adr/README.md)), 정책 COM-001, COM-002, COM-004

이 문서는 기획서를 백엔드 관점에서 풀어, 다룰 데이터의 특성과 서버가 맡을 일을 정리한다. 대안을 비교해 고른 결정은 ADR에 있고, 여기서는 그 근거가 된 분석과 아직 정하지 않은 것을 적는다.

## 1. 서버가 받는 유저 플로우

| # | 플로우 | 서버에서 일어나는 일 |
|---|---|---|
| 1 | 저장: 링크 붙여 넣기, 글 붙여 넣기, 파일(COM-004: PDF·md·txt·docx, PNG·JPEG·WebP·HEIC) 여러 개 던지기, 공유 시트 | 항목마다 즉시 저장 응답. 같은 링크·같은 파일이면 기존 자료를 돌려준다. 나머지는 뒤에서 처리 |
| 2 | 저장 뒤 처리(사용자는 모름) | 본문 가져오기(웹), 텍스트 추출(PDF, docx), 이미지 글자 읽기(ADR-BCK-005), 요약, 태그, (P1) 임베딩. 실패와 막힘이 흔하다 |
| 3 | 다시 찾기 `찾기 검색어`, `최근` | 사용자 범위 안의 한국어·영어 부분 문자열 검색, 최신순 10건과 전체 건수 |
| 4 | 골라 넘기기 `고르기`, `넘기기` | 고른 자료로 넘길 글을 만든다. 북극성 지표용 이벤트를 기록한다 |
| 5 | 이름 붙인 묶음 `묶음` | 묶음과 자료의 N:M 관계. 지운 자료가 있으면 알린다 |
| 6 | AI 도구가 직접 읽기(MCP) | AI 도구가 OAuth로 로그인한 뒤 검색·읽기 도구를 부른다. 읽기 전용, 본문은 요청할 때만 |
| 7 | 북마크 일괄 가져오기 | 수천 건을 한 번에 넣고 진행률을 보여 준다. 2번 처리가 한꺼번에 몰린다 |
| 8 | 여러 기기에서 쓰기 | 계정과 동기화. 다른 기기의 변경과 삭제를 받는다 |
| 9 | 삭제·수정 | 원본 파일, 본문, 요약, 임베딩까지 지운다 |

본문을 가져올 수 없는 경우가 흔하다. 로그인이 필요한 SNS 게시물은 서버에서 본문을 가져오기 어려우므로, 클라이언트가 함께 보낸 텍스트와 이미지(붙여 넣은 글, 스크린샷, 공유 시트로 받은 글)가 있으면 그것을 본문의 1차 소스로 저장하고 서버에서 가져오는 것은 보조로 둔다. 다만 공유 시트로 무엇이 오는지는 보내는 앱이 정하고 SNS 앱은 대개 링크만 넘기므로(ADR-IOS-009), 텍스트 없이 링크만 오는 경우를 기본으로 보고 "본문 못 가져옴" 상태를 처리한다.

## 2. 클라이언트와의 경계

클라이언트와 서버는 OpenAPI 계약으로만 연결하고, 서비스 규칙은 서버가 최종 판정한다(ADR-0001).

| 영역 | 엔드포인트 예시 | 서버가 보장하는 것 |
|---|---|---|
| 저장 | `POST /items`, `POST /uploads`(서명 URL 발급) | 멱등성 키, 중복 판정, 형식·용량 검증, 항목별 결과 |
| 조회·검색 | `GET /items`, `GET /items/search?q=` | 사용자 범위, 최신순, 커서 페이징, 전체 건수 |
| 수정·삭제 | `PATCH /items/{id}`, `DELETE /items/{id}` | 사용자가 고친 요약은 따로 보관. 삭제는 파생 데이터까지 지우고 삭제 표시를 남김 |
| 묶음 | `POST /bundles`, `PUT /bundles/{name}` | 이름 유일성, 빠진 자료 알림 |
| 넘길 글 | `POST /handoff` | 형식을 한 곳에서 정의. 앱의 `넘기기`와 MCP가 같은 결과 |
| 동기화 | `GET /sync?cursor=` | 단조 증가 커서, 변경분과 삭제 표시 |
| MCP | `/mcp` | 검색·읽기 도구, 읽기 전용, OAuth |
| 이벤트 | `POST /events` | 지표용 이벤트. 자료 내용은 받지 않음 |

엔드포인트 이름과 모양은 예시이며 OpenAPI 스펙을 쓸 때 정한다.

## 3. 데이터 프로파일 (10축)

핵심 엔티티: 자료(링크·글·파일), 자료 내용(본문, 요약, 태그), 원본 파일, 묶음, 처리 작업, 이벤트, MCP 연결 토큰.

| 축 | 그렙의 답 | 설계 결정 |
|---|---|---|
| 1. 생명주기·규모 | 사용자당 주 수십 건, 누적 수천 건. 북마크 가져오기 때만 수천 건이 한 번에 들어온다. 본문은 추출 뒤 거의 바뀌지 않고, 제목·요약·상태는 바뀐다. 이벤트는 추가만 되며 계속 는다 | 자료 삭제는 내용을 물리 삭제하고, 동기화용 삭제 표시(ID와 삭제 시각)만 일정 기간 남긴다 |
| 2. 타입 | ID가 URL과 MCP 응답으로 외부에 나간다. 다국어 텍스트, 파일 해시 | UUIDv7, `TIMESTAMPTZ`, 상태 값은 `CHECK` 제약, 정규화한 URL과 SHA-256 해시 컬럼 |
| 3. 읽기·쓰기 | 사용자 단위로 작고 핫키가 없다. 몰리는 곳은 여러 파일 던지기와 북마크 가져오기 | 캐시와 읽기 복제본 없이 큐와 외부 호출 속도 제한으로 흡수 |
| 4. 조회 패턴 | 최근 목록, 부분 문자열 검색, 중복 판정, 묶음 이름 조회, MCP 검색, 작업 꺼내기, 주간 지표 | 검색은 `search_text`(제목·요약·본문)에 PGroonga 인덱스, `(user_id, created_at DESC)` 인덱스와 커서 페이징, `UNIQUE(user_id, normalized_url)`, `UNIQUE(user_id, content_hash)`, `UNIQUE(user_id, name)`, 작업은 `(status, run_at)` 부분 인덱스, 지표는 일 단위 사전 집계 |
| 5. 일관성 | 동기: 저장 응답, 중복 판정, 삭제(MCP에서 바로 사라져야 함), 묶음 수정. 비동기: 추출, 요약, 태그, 임베딩, 지표 | 처리 상태 `received → processing → ready / blocked / failed`를 화면에 그대로 보여 준다 |
| 6. 동시성 | 같은 저장이 두 번 옴, 사용자가 요약을 고치는 사이 워커가 덮어씀, 워커 둘이 같은 작업을 집음, 처리 중 삭제 | 유일 제약과 멱등성 키, 자동 요약과 사용자 요약을 별도 컬럼으로, `SKIP LOCKED`와 리스, 워커는 조건부로 결과를 씀. 외부 호출은 트랜잭션 밖에서 하고 상태 전이로만 기록 |
| 7. 장애 | 웹 본문, LLM, OCR, 스토리지에 의존 | 저장은 어떤 의존성이 죽어도 성공. 자료와 작업을 같은 트랜잭션에 넣어 Outbox 불필요. 타임아웃, 지수 백오프와 지터, 최대 재시도 후 `failed`, LLM 장애 시 서킷 브레이커로 큐만 멈춤 |
| 8. 사후 검증 | 외부 원장 대사는 없다. 고아 파일과 멈춘 작업이 생긴다 | 고아 파일 정리 배치, 오래 멈춘 작업 재투입 배치. 지표: 큐 길이, 출처 도메인별 실패율, LLM 지연과 비용 |
| 9. 스키마 변경 | 테이블은 작지만 요약 프롬프트와 모델이 바뀐다 | 요약에 모델과 프롬프트 버전 컬럼, 임베딩은 모델별 테이블, API는 필드 추가만 |
| 10. 보안 | 전부 개인 비공개, 업무 자료 포함 | 사용자 ID는 토큰에서만, RLS. 서버가 URL을 가져오므로 SSRF 차단(사설 IP, 리다이렉트 재검사, 크기·시간 상한). 추출은 격리된 워커에서 메모리·시간 제한. MCP 토큰은 읽기 전용·해시 저장·폐기 가능. 넘길 글에 출처 자료 구분 표시(프롬프트 인젝션 대비) |

## 4. 서버 구조

- 저장소: Postgres(자료, 묶음, 작업 큐, 이벤트)와 오브젝트 스토리지(ADR-BCK-002)
- 언어: Kotlin, Spring Boot(ADR-BCK-003)
- 구조: 기능별 모듈러 모놀리스, 모듈 안은 포트와 어댑터(ADR-BCK-004)

```
features/ ingest · archive · processing · bundle · sync · mcp · metrics
          각 모듈: interface / domain / adapters / testing
shared/kernel   app(조립 지점, 진입점: API 서버 · 워커 · MCP 서버)
```

다른 언어로 옮길 수 있도록 지키는 것: 스펙 우선, 순수 SQL 마이그레이션, 서버 언어 밖의 API 테스트와 테스트 벡터, 버전이 붙은 JSON 작업 페이로드, 프레임워크와 분리한 도메인 로직.

## 5. 운영비 추정

2026-11-25에 공개 가격으로 계산한 추정이다. 가격과 무료 한도는 일부가 2차 출처 기준이라 결제 전에 각 회사의 공식 가격 페이지에서 다시 확인한다.

가정: 사용자 1명이 월 약 85건 저장, 요약 1건에 입력 약 4천 토큰과 출력 약 300 토큰, 저장의 30%가 평균 1MB 파일.

| | 비공개 베타 | 공개, 약 100명 | 약 1,000명, 소형 모델 요약 | 약 1,000명, 중형 모델 요약 |
|---|---|---|---|---|
| 인프라 | 무료 플랜 조합 시 0 | 월 약 $35~40 | 월 약 $60~80 | 월 약 $60~80 |
| 서버 LLM 요약 | 0 | 월 약 $5 | 월 약 $50 | 월 약 $935 |

비용을 좌우하는 것은 요약 방식이다. 북마크 가져오기는 가져올 때 다 요약하지 않고 처음 열거나 넘길 때 요약하는 것이 안전하다.

## 6. 정하지 않은 것

| 항목 | 선택지 | 비고 |
|---|---|---|
| LLM 제공사 | Anthropic(ADR-BCK-003 기본), Gemini(유튜브 영상 이해 F10 고려) | 요약 방식은 서버 소형 LLM으로 정했다(ADR-BCK-008). 제공사는 처리 워커 구현 전에 정한다 |
| 호스팅 | 무료 플랜 조합, 관리형 Postgres와 소형 서버 | 비공개 베타는 무료, 공개 출시 때 유료로 올리는 안 |
| 정책 값 | 용량 한도, 삭제 유예, 삭제 표시 보존, 이벤트 보존, 외부 LLM 전송 범위, RPO·RTO, 가져오기 한도 | [공통 영역 열린 질문](../policies/common/open-questions.md) |

## 7. 스파이크

1. MCP Kotlin SDK로 원격 MCP 서버와 OAuth를 만들 수 있는지
2. Apache Tika 4.x로 한국어 PDF·docx·HTML 추출 품질이 충분한지
3. ~~Postgres에서 한국어 부분 검색(PGroonga, pg_trgm)이 관리형 서비스에서 되는지~~ 확인함(2026-11-25)
   - 조건: 로컬 Docker, Postgres 17, PGroonga 4.1.0, pg_trgm 1.6. 사용자 5명 × 1만 건(1건 약 2KB, 한국어·영어 혼합). 사용자 한 명 범위에서 "최신 10건 + 전체 건수" 쿼리 두 개의 평균
   - 결과: 인덱스 없는 `ILIKE`는 약 1.8초(쿼리당 약 0.9초). pg_trgm은 3글자 이상에서 약 20ms이지만 2글자("결제", "회의")는 인덱스를 못 써 약 1.8초. PGroonga(`&@`)는 모든 검색어에서 1.4~4.3ms. 찾은 건수는 세 방법이 모두 같았다
   - 대체 경로: 같은 검색을 `strpos`로 하면 약 65ms
   - Supabase는 PGroonga를 공식 지원한다. Supabase 서버에서 다시 재지는 않았다. 한 글자 검색은 시험하지 않았다
4. 요약을 서버에서 한다면, 한국어 자료 요약을 소형 모델로 해도 품질이 충분한지
