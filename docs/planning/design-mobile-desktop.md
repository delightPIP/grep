# 모바일과 데스크톱 두더지 화면 시안

- 작성일: 2026-11-25
- 상태: (제안) PO 확인 전
- 시안: [그렙 웹 화면 시안](https://claude.ai/artifact/J6XT7UcSDvuPC2quoSsaRm)의 "모바일", "데스크톱 두더지" 페이지
- 디자인 시스템: [그렙 터미널](https://claude.ai/artifact/WuyaZyTfEBCMsaTr9ntbEU). 새 색·글꼴은 만들지 않고 이 시스템의 토큰과 컴포넌트(`Window`, `Prompt`, `Line`, `Hint`, `ResultList`, `Chip`, `Input`, `Confirm`, `Mascot`, `Burrow`)를 그대로 썼다.

첫 플랫폼은 웹이다(PRD 14절). 이 문서는 그다음 단계인 모바일 앱과 Windows 데스크톱 앱의 화면을 미리 정한다. 웹 시안과 같은 터미널 로그 화면을 유지하고, 기기마다 입력 방법만 바꾼다.

## 모바일

| 화면 | 내용 | 근거 |
|---|---|---|
| M1 첫 화면 | 배너 두더지, 공유 시트에 그렙 꺼내 두기 안내(처음 한 번, iOS), 명령 다섯 개 설명, 맨 아래 명령 버튼 4칸과 입력줄 | US-6, US-7 |
| M2 입력창을 누르면 | 명령 전체가 3열 격자로 펼쳐진다. 인자 없는 명령은 바로 실행, `…` 붙은 명령은 입력줄에 들어간다 | US-7 |
| M3 찾기와 고르기 | 결과 줄(56px, 두 줄)을 눌러 고른다. 오른쪽 `⋯` 또는 길게 누르면 메뉴 시트(열기, 고르기, 이것만 공유, 버리기). 고르면 아래가 고른 칩(×로 빼기)과 `공유 N건 · 복사 · 묶음…`으로 바뀐다 | US-3, US-4, US-11 |
| M4 공유로 저장 | OS 공유 시트에서 그렙을 고르면 묻는 것 없이 저장한다. 2초 뒤 닫히되 시트에 손대면 멈춘다. 이미 저장됨은 저절로 닫지 않는다. 본문은 보내는 앱이 글을 함께 넘길 때만 저장하고(Safari는 페이지 본문을 넘김), 링크만 오면 `! 본문 못 가져옴: 공유된 것이 링크뿐`을 보여 준다. 변형 4개: 본문 옴, 링크만, 이미 저장, 여러 건 | US-1, US-12, 10절 엣지 케이스 |
| M5 넘기기 | `공유`를 누르면 넘길 글을 OS 공유 시트로 AI 앱에 보낸다. `복사`는 둘째 방법. 5건 초과 확인(44px 선택지). 땅굴에서 두더지가 문서를 던진다 | US-4, US-5 |

규칙:

1. 웹과 같은 로그 화면이다. 바뀌는 것은 맨 아래(명령 버튼, 입력줄, 실행 버튼)뿐이다.
2. 명령 버튼은 4칸 고정(`최근 · 찾기… · 고르기… · 더보기`)이고 가로로 스크롤하지 않는다. 나머지 명령은 `더보기` 또는 입력창을 누르면 나온다. 한글만 쓰고, 영문 명령은 쳐도 된다.
3. 안전 영역을 비운다: 머리줄 위 `max(47px, env(safe-area-inset-top))`, 맨 아래 `max(34px, env(safe-area-inset-bottom))`. 입력줄과 버튼이 홈 표시줄과 겹치지 않게 한다.
4. 입력칸 글자는 16px 이상이다(iOS가 입력칸을 누를 때 화면을 확대하지 않게). 디자인 시스템 `Input`이 터치 기기와 560px 이하 화면에서 알아서 16px(`input-touch`)로 바꾼다. 확대를 막으려고 `maximum-scale=1`이나 `user-scalable=no`를 쓰지 않는다.
5. 본문은 모바일에서도 14px 아래로 내리지 않는다. 고정폭 글꼴의 한글은 같은 크기의 일반 글꼴보다 작게 보인다.
6. 모바일 넘기기의 기본은 OS 공유 시트다. 복사는 둘째 방법으로 둔다.
7. 숨은 제스처만으로 할 수 있는 일은 없다. 길게 누르기로 여는 메뉴는 `⋯` 버튼으로도 연다.
8. 버튼이 있는 시트는 저절로 닫힐 때 손대면 멈춘다.
9. 터치 목표는 44px 이상(시트 버튼 48px)이다. 웹의 `ResultList`, `Confirm`, `Chip`은 모바일에서 터치용으로 바꿔 그렸다. 디자인 시스템에 터치 변형을 더할지는 열린 질문이다.
10. 두더지는 한 화면에 하나다(배너, 공유 시트, 땅굴 중 하나).

### iOS 공유 시트 구현 (개발자용)

받기와 보내기는 서로 다른 iOS 기능이다. 이유와 대안은 [ADR-IOS-009](../adr/ios/ADR-IOS-009-share-sheet.md)에 있다.

| | 받기: 다른 앱 → 그렙 (M4) | 보내기: 그렙 → AI 앱 (M5) |
|---|---|---|
| iOS 기능 | 앱 안의 공유 확장(Share Extension) | `UIActivityViewController` |
| 받는·보내는 것 | `NSExtensionActivationRule`로 링크·글·이미지·PDF | 넘길 글(텍스트), 필요하면 `.md` 파일 |
| 화면 | SwiftUI로 직접 그린다. 시스템 작성 화면(`SLComposeServiceViewController`)은 쓰지 않는다. 시트를 띄우는 방식, 손잡이, 뒤 배경은 iOS가 정하므로 시안의 배경·손잡이는 참고용이다 | 바꿀 수 없다. 시안의 점선 칸은 시스템 시트 자리다. 특정 앱을 미리 고를 수 없고 항목을 빼는 것만 된다 |
| 저장·전송 | 확장 안에서는 앱 그룹 공용 폴더 대기열에 넣고, 업로드는 백그라운드 `URLSession`에 맡긴다. 로그인은 공용 키체인. 시트가 닫혀도, 오프라인이어도 저장이 이어진다 | 없음(글을 만들어 넘기기만 한다) |
| 주의 | 무엇이 넘어오는지는 보내는 앱이 정한다. SNS 앱은 대개 링크만 넘긴다. Safari는 JavaScript 전처리 파일로 페이지 제목과 본문을 받을 수 있다. 처음에는 그렙이 공유 시트의 "더 보기" 안에 있어 M1에서 한 번 안내한다 | AI 앱이 공유로 텍스트를 받는지는 앱·버전마다 다르다(확인 안 함). 그래서 `복사` 버튼을 함께 둔다. iPad는 시트를 띄울 기준 버튼(`popoverPresentationController`)이 없으면 앱이 꺼진다 |
| 웹으로는 | 안 된다. iOS는 Web Share Target을 지원하지 않는다 | Safari `navigator.share()`로 같은 시트를 연다 |

기획서와 다른 점: PRD 10절의 "휴대폰 공유 시트에서 받은 글을 본문으로 쓰는 것은 모바일 앱 단계"는 로그인이 필요한 SNS 본문 문제를 공유 시트로 풀 수 있다고 읽힌다. 실제로는 보내는 앱이 글을 넘길 때만 되므로, SNS 본문은 여전히 스크린샷 공유(F16 글자 읽기)나 글 붙여 넣기로 받는다. PRD 문구 수정은 PO 확인이 필요하다.

## 데스크톱 두더지 (Windows 상주 앱)

| 화면 | 내용 |
|---|---|
| D1 상주 | 작업 표시줄 위 오른쪽 아래에 땅굴 띠(200×100)와 두더지(48px). 마우스를 올리면 자료 수와 단축키 한 장 |
| D2 끌어 오기 | 파일을 두더지 쪽으로 끌어 오면 점선 영역과 "놓으면 저장", 두더지는 만세 |
| D3 저장됨 | 놓으면 두더지가 받아서 땅에 묻고, 옆에 로그 카드(`✓ 저장됨 3건`, 요약 생성 중)가 3초 뜬다 |
| D4 빠른 창 | 두더지를 누르거나 `Ctrl+Shift+G`로 웹과 같은 터미널 창(420×548)을 연다. `Esc`로 닫는다 |
| D5 직접 해 보기 | 끌어다 놓기, 링크 복사 알림, 찾기, 넘기기, 틀림, 두더지 누르기를 직접 해 볼 수 있는 시안 |

규칙:

1. 항상 위에 뜨고, 전체 화면 앱이 있으면 숨는다. 끌어서 옮기면 화면 가장자리에 붙는다.
2. 두더지는 말하지 않는다. 글은 로그 카드와 빠른 창에만 쓴다(디자인 시스템 9절).
3. 동작은 디자인 시스템 `Burrow` 그대로다: 끌어 오기는 만세, 놓기는 받아서 묻기, 찾기는 파고 들어가 `!`, 넘기기는 문서 던지기, 틀림은 고개 흔들기와 `?`.
4. 트레이 아이콘은 두더지 `mark` 16px. 우클릭 메뉴는 숨기기 1시간, 설정, 종료.
5. 복사한 링크 알림은 [COM-003](../policies/common/COM-003-desktop-clipboard-link-prompt.md)을 따른다(2026-11-25 PO 결정): 기본 꺼짐, 켜면 `담기?`를 한 번 묻고 8초 뒤 닫힌다. 담기 전에는 서버로 보내지 않는다.

## 열린 질문

정책이 없거나 기획서와 부딪히는 것이다. 정해지면 정책 또는 ADR로 옮긴다.

1. 데스크톱 앱은 PRD 기능 목록(F1~F21)에 없다. 범위에 넣을지, 넣으면 우선순위는 무엇인지 정해야 한다.
2. 빠른 창 단축키 `Ctrl+Shift+G`가 다른 앱과 겹치는지 확인하지 않았다. 설정에서 바꿀 수 있게 할지 정해야 한다.
3. 모바일 터치용 결과 줄과 확인 선택지를 디자인 시스템 컴포넌트로 올릴지.
4. 공유 시트 저장 뒤 자동으로 닫히는 시간(2초)과 데스크톱 로그 카드 시간(3초)은 임의 값이다.
