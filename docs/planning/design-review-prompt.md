## 복사할 부분

```text
당신은 제품 UI/UX 디자인 전문가입니다. 우리 서비스를 처음 보신다는 전제로 배경을 먼저 설명드리고, 첨부한 화면 시안의 첨삭을 부탁드립니다.

# 1. 서비스 한 줄
그렙(grep)은 SNS·유튜브·웹에서 저장해 둔 자료를 한곳에 모아 두었다가, Claude·ChatGPT 같은 AI 도구에 일을 시킬 때 그 자료를 요약과 함께 골라 넘겨 주는 웹 서비스입니다. 화면은 "터미널 느낌"이고, 쉬운 명령어 몇 개로 씁니다. 진짜 명령줄 도구는 아니고, 터미널처럼 보이고 움직이는 웹 화면입니다.

# 2. 누구의 어떤 문제인가 (가설)
- 대상: AI 도구로 주 3회 이상 작업하는 사람. 개발자와 비개발자(기획자, 디자이너, 마케터 등)를 모두 포함합니다.
- 상황: 링크·캡처·PDF를 "언젠가 쓸 것 같아서" 여러 앱(스레드 저장, 유튜브 나중에 볼 동영상, 북마크, 사진첩)에 흩어 저장합니다.
- 문제: AI에게 일을 시킬 때 저장해 둔 자료가 떠오르지 않거나, 떠올라도 흩어져 있어 찾아 넣기 번거롭습니다. 그래서 자료 없이 묻고 결과물이 평범해집니다.
- 근거는 약합니다. 소규모 설문(12명)에서 방향만 봤고 인터뷰는 하지 않았습니다.

# 3. 해결 방식
1) 저장: 보던 링크를 입력줄에 붙여 넣거나 이미지·PDF를 끌어다 놓으면 끝. 폴더·태그를 묻지 않습니다. 요약과 태그는 서버가 알아서 만듭니다.
2) 찾기: `찾기 결제`처럼 검색하거나 `최근`으로 목록을 봅니다. 자료마다 번호가 붙습니다(131번 등).
3) 고르기·넘기기: `고르기 131 140` → `넘기기` 하면 AI 도구에 붙여 넣을 글(제목·출처·요약)이 클립보드에 복사됩니다. 이어 쓰기도 됩니다: `찾기 결제 | 넘기기`.
4) 묶음: 자주 넘기는 자료에 이름을 붙여 두면 다음부터 `넘기기 결제조사` 한 줄로 다시 넘깁니다.
5) 같은 링크를 또 저장하면 "이미 저장됨 → 131번"이라고 알려 줍니다.
원칙: AI와 경쟁하지 않습니다. 서비스 안에서 AI 대화나 답변 생성은 하지 않고, 자료를 넘기는 쪽에만 섭니다.

# 4. 화면 컨셉과 이미 정한 것
- 터미널 느낌의 웹 화면. 프롬프트 `그렙 ~ $`, 입력줄 한 줄, 명령마다 결과 덩어리가 아래로 쌓임, 맨 아래 상태줄(`자료 131 · 선택 2 · 묶음 결제조사 · 요약 생성 중 1`).
- 명령은 한글이 기본이고 영문판이 같이 있습니다(담기/keep, 최근/recent, 찾기/seek, 고르기/pick, 넘기기/handoff, 묶음/pack, 고치기/revise, 버리기/drop, 도움말/guide, 설명/about 등 13개). 정식 이름은 진짜 터미널 명령(grep, ls, cp 등)과 겹치지 않게 했습니다. 다만 같은 일이 분명한 진짜 명령은 입력을 받아 실행합니다(`grep`·`find` → 찾기, `ls` → 최근, `help`·`man`·`?` → 도움말. `rm`·`copy` 같은 것은 안내만).
- 화면 문구는 진짜 터미널처럼 건조한 로그체입니다. 예: `✓ 저장됨  결제위젯 연동 가이드 (docs.tosspayments.com)`, `! 이미 저장됨 → 131번 (새로 만들지 않음)`, `✗ 없는 명령: 찻기`. 해요체·이모지·느낌표를 쓰지 않습니다. 기호: ✓ 성공, · 안내, ! 알림(실패 아님), ✗ 실패, → 다음에 칠 명령.
- 화면의 숫자는 자료 번호 한 가지 뜻만 씁니다. 그래서 확인 질문은 숫자 선택지 대신 명령 이름을 다시 치는 낱말로 받습니다(`버리기? <제목>` → `버리기`를 다시 치면 실행, 그 외 입력은 취소. 5건 초과 넘기기는 `앞10`·`전부`).
- 명령은 가장 빠른 길이되 유일한 길은 아닙니다. 다음에 칠 명령은 누를 수 있는 칩으로 보이고, 화면의 명령·번호를 누르면 입력줄에 찍힙니다. 입력은 너그럽게 받습니다(오타 제안을 엔터로 실행, 흐린 다음 명령을 Tab으로 채우기, 영문 자판으로 친 한글 명령 알아듣기).
- 처음 쓰는 사람을 위해: 첫 화면은 두더지 마스코트, 한 문장 소개(`저장해 둔 링크·캡처·PDF를 찾아 AI 도구에 붙여 넣을 글로 복사`), 표어 `담기 → 찾기 → 넘기기`, 그리고 `샘플 8건으로 해 보기` 하나입니다. 명령 전체 목록은 `도움말`로 뺐습니다. 샘플은 실제 자료로 저장되고 `버리기 1-8`로 치웁니다.
- 글꼴: 명령·번호·로그는 고정폭, 요약처럼 읽는 문장은 가변폭(Noto Sans KR)으로 나눴습니다. 입력줄은 화면 아래에 고정입니다.
- 넘기기 결과에는 넘긴 자료 목록, 복사된 글 미리보기(접기 가능), "AI 도구 입력창에 붙여 넣기" 안내가 나옵니다.
- 어두운 테마가 기본이고 밝은 테마도 있습니다. 로그인은 Google·GitHub.
- 첫 플랫폼은 데스크톱 웹입니다. 휴대폰 공유로 저장하기는 나중 단계입니다.
- 일정: 12월 초 발표용 데모. 데모 핵심 흐름은 "로그인 → 링크 저장 → 찾기 → 고르기 → 넘기기(복사)"이고, 30건 넘게 저장된 상태에서 원하는 자료를 찾아 복사하기까지 1분 안이 목표입니다. 데모는 비개발자인 마케터가 캠페인을 준비하는 이야기로 보입니다. 시안의 결제 관련 예시 자료는 화면 예시일 뿐입니다.

# 5. 이미 한 번 받은 검토
다른 디자이너 한 분께 같은 시안의 앞선 버전을 검토받았고, 4절의 숫자 대신 낱말 확인, 진짜 명령 받아 주기, 첫 화면 단순화, 다음 명령 칩, 글꼴 분리, 넘기기 미리보기, 입력 받아 주기, 찾기 0건 뒤 최근 3건에 `(검색 결과 아님)` 머리줄, 목록 두 줄 행·폭 제한·`더 보기`가 그 결과로 들어갔습니다. 같은 지적을 되풀이하기보다, 이렇게 바뀐 결과가 실제로 나아졌는지, 새로 생긴 문제는 없는지 봐 주시면 좋겠습니다. 이 결정에 반대하신다면 그 의견도 환영합니다.
첨부 가운데 웹 화면에는 이 반영이 들어 있습니다. 모바일·데스크톱 화면은 아직 반영 전이라(목록 위치 번호, 숫자 선택지 등) 참고로만 봐 주세요.

# 6. 저희가 가장 걱정하는 것
1) 비개발자가 터미널 느낌의 화면을 반길지, 겁낼지. "개발자가 된 듯한 재미"와 "명령어를 외워야 하는 부담" 사이의 균형.
2) 개발자에게는 "터미널처럼 생겼지만 진짜가 아닌 화면"이 장식이나 흉내로 보이지 않을지. 진짜 명령을 받아 주는 것이 오히려 흉내를 키우지 않을지.
3) 칩·누르기·자동 완성을 더한 지금, 명령을 쳐서 쓰는 방식과 눌러서 쓰는 방식이 섞여 어느 쪽도 어정쩡해지지 않았는지.
4) 고정폭(명령·로그)과 가변폭(읽는 문장)을 나눈 경계가 맞는지, 어두운 바탕에서 한글 요약의 가독성.
5) 자료 목록(번호·제목·출처·저장 시각·한 줄 요약·꼬리표)이 터미널 텍스트 안에서 훑어보기 쉬운지.

# 7. 부탁드리는 것
첨부한 시안을 보시고 아래 순서로 답해 주세요.
1) 첫인상: 이 서비스가 무엇을 하는지 화면만 보고 5초 안에 알 수 있는지, 무엇이 먼저 눈에 들어오는지.
2) 문제점 목록: 화면(또는 영역)마다 "무엇이 문제인지 → 왜 문제인지 → 어떻게 고치면 좋을지"를 적고, 심각도를 높음·중간·낮음으로 표시해 주세요.
3) 6절의 걱정 다섯 가지에 대한 의견.
4) 터미널 컨셉을 지키면서 입문자 진입 장벽을 낮출 구체적인 방법 3가지 이내.
5) 발표 데모 전(며칠 안)에 꼭 고칠 것과, 이후로 미뤄도 되는 것 구분.

참고로 컨셉(터미널 느낌, 한글 명령어, 건조한 로그체 문구, AI와 경쟁하지 않음)은 이미 정한 것이라 바꾸기 어렵습니다. 다만 컨셉 자체가 사용자에게 크게 불리하다고 보시면 그 의견도 솔직하게 말씀해 주세요. 추측과 확실한 판단은 구분해 주시면 좋겠습니다.

[첨부: 화면 시안 이미지 또는 링크]
```
