### 질문 1. 데모에서 "담기" 장면을 찾기 앞에 둘까, 뒤에 둘까? (01 G1)

- 왜: 세 문서의 대본이 다르다. 발표 메모 5절에는 새 저장·요약 장면이 없고 같은 링크 장면이 맨 끝(8번)이다. 흐름도 11절과 시드 5절은 저장 → 같은 링크 → 찾기 순서다. 흐름도는 "한국어 링크 + PDF"를 새로 저장하지만 시드에는 새 링크가 없다(L1은 같은 링크, L2는 PDF)
  - presentation-notes:58 "8. 같은 기사 링크를 꼬리표를 붙여 다시 붙여 넣어 `! 이미 저장됨` 을 보여 준다."
  - user-flow:311 "**저장** | 한국어 링크 붙여 넣기, PDF 끌어다 놓기"
  - demo-seed:74 "무대에서 새로 저장할 자료(시드에 넣지 않음, 계정 B)" — L1, L2 둘뿐
- 이전 결정: 발표 메모의 순서는 외부 PO 첨삭을 PO가 추천안대로 받아들인 것(presentation-notes:4, 2026-11-26, 김태인). 첨삭의 뼈대는 "자료 없이 시킨 결과 → 그렙으로 넘긴 결과 → 새 대화에 다시 넘기기"(presentation-notes:15)였고, 새 저장 장면을 빼라는 말은 없다

| 선택지 | 내용 |
|---|---|
| A (추천) | 계정 전환 뒤 `최근` 다음에 "새 저장 L2 → 같은 링크 L1"을 넣고 그 뒤 찾기·고르기·넘기기. 새 저장은 시드에 있는 L2(PDF) 하나. 흐름도 11절·시드 5절·발표 메모 5절을 이 순서 하나로 맞춘다 |
| B | 발표 메모 순서를 두고 끝(8번)에 L2 새 저장을 더한다. 흐름도·시드를 발표 메모 순서로 고친다 |
| C | 지금 그대로(새 저장 장면 없음). 필수 흐름 1의 "요약"은 시드 자료의 한 줄 요약으로만 보인다 |

- 추천 이유: 표어 `담기 → 찾기 → 넘기기`와 데모 필수 1번(저장·알림·요약)의 순서가 같아진다. 요약이 만들어지는 몇 초를 찾기 장면이 벌어 준다. 디자이너도 동의(06 3절).
- 포기하는 것: 첨삭이 짠 "자료 없이 → 그렙으로" 대비가 저장 장면으로 한 번 끊긴다.
- **결정: 김태인 (AI 제안 수용), 2026-11-26.** 추천안(A)을 골랐다. 이유는 위 AI 추천 이유이고 PO는 따로 말하지 않았다. 결정 로그 [STATE](../STATE.md) 12절

### 질문 3. 화면의 명령·번호를 누르면 바로 실행할까, 입력줄에 찍기만 할까? (01 G3, 05 Q-13)

- 왜: 문서가 셋으로 갈린다. 시안·구현·데모 조작(번호 눌러 고르기)이 모두 이 답에 걸린다
  - commands:200 "명령 하나가 칩 하나이고, 누르면 입력줄에 찍혀 실행된다."
  - commands:201 "누르면 그 명령이 입력줄에 찍힌다."
  - user-flow:63 "입력줄에 명령이 들어감 (바로 실행하지 않음)"
- 이전 결정: 2026-11-26, 김태인(안은 외부 디자이너 검토), STATE:311 "화면의 명령·번호는 누르면 입력줄에 찍힘". 근거 "명령은 가장 빠른 길로 두되 유일한 길로 만들지 않는다. 첫 30초 안에 찾기 → 고르기 → 넘기기가 한 번 성공하게 한다". 실행 여부는 이 결정에 없다. 참고로 모바일 US-7(PRD:235)은 "인자가 없는 명령은 눌러서 바로 실행, 인자가 필요한 명령은 누르면 입력창에 들어감"

| 선택지 | 내용 |
|---|---|
| A (추천) | 명령 칩·번호는 찍기만 하고 엔터로 실행한다. 명령이 아닌 화면 칩(`펼치기`)은 누르면 바로 동작한다(06 5절 피드백 2). commands:200을 고친다 |
| B | 찍고 바로 실행한다. user-flow:63을 고친다 |
| C | 다 채워진 명령(`→ 넘기기`, `고르기 131`)은 바로 실행, 인자 자리가 빈 명령(`묶음 <이름>`)은 찍기만(US-7과 같은 규칙) |

- 추천 이유: 결정 문장 그대로이고, 누른 명령이 입력줄에 보여 청중이 "명령을 친 것"으로 읽는다. 확인이 필요한 명령을 잘못 눌러도 실행되지 않는다. `펼치기`는 입력줄에 칠 명령이 없어 예외가 필요하다.
- 포기하는 것: 누를 때마다 엔터 한 번. 1분 성공 기준에 몇 초가 더해진다.
- **결정: 김태인 (AI 제안 수용), 2026-11-26.** 추천안(A)을 골랐다. 이유는 위 AI 추천 이유이고 PO는 따로 말하지 않았다. 결정 로그 [STATE](../STATE.md) 12절
