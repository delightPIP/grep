## 0. 요약

- 문제: AI 활용자가 저장해 둔 자료를 AI 도구에 넣을 때 원문을 다시 열어 옮기는 수고를 줄이되, 원문과 다른 내용을 사실처럼 넘기는 일을 늘리지 않는다(1-2절).
- 비교 대상: 링크만 붙여 넣기, 원문 통째로 붙여 넣기, 사용자가 직접 쓴 메모.
- 적합성: 요약·태그·글자 추출 모두 "AI 자동 실행 + 사후 통제"(ADR-BCK-008, ADR-BCK-005, ARC-002와 같음). 사람 검토 지점은 넘기기 결과의 `펼치기` 미리보기와 넘길 글의 안내 줄이다(D-04).
- 현재 상태: 설계 초안. 화면 문구는 명령어 설명서 6절과 정책 문구를 따랐고, 요약 없음 문구는 새로 만들지 않고 handoff-format.md 3절·ARC-004·ARC-005 문구를 그대로 썼다. 원본이 없는 새 문구는 넘기기 실패(ST-19) 하나이고 제안으로 표시했다.
- 결정 필요: 8절 PO 질문 4개(질문 3은 확인만).

### 1-2. 문제 정의문

> AI 활용자가 AI 작업 중 저장해 둔 자료를 AI 도구에 넣을 때 자료마다 원문을 다시 열어 핵심을 옮기는 수고를, 지금처럼 링크만 붙이거나 원문을 통째로 붙여 넣는 방식보다 줄이되, 원문과 다른 내용을 사실처럼 넘기는 일과 무엇을 넘겼는지 모르는 일은 늘리지 않는다.

- `[가정]` 수고가 실제로 있는지는 검증하지 않는다(인터뷰 없음, STATE 12절 2026-11-25). 발표에서 한계로 밝힌다(PRD 11절).

### 3-4. 결론과 통제 수준

| AI 처리 | 결론 | 오류 영향 | 되돌리기 | 통제 수준 |
|---|---|---|---|---|
| 요약 | 자동 실행 + 사후 통제 | 중간: AI 도구의 답을 틀리게 만들 수 있다. 사용자가 미리보기로 알아챌 수 있다 | 쉬움: `고치기`, 다시 넘기기 | 자동 적용 + 표시(ARC-004) + 넘기기 전후 미리보기 |
| 태그 | 자동 실행 + 사후 통제 | 작음: 태그 찾기만 영향 | 지우기만 가능, 다시 붙이지 않음(ARC-002 규칙 2) | 자동 적용 + 지우기 |
| 글자 추출 | 자동 실행 + 사후 통제(약함) | 작음~중간: 찾기 결과와 연결 읽기 본문(ARC-009 규칙 3)에 영향 | 사용자가 고칠 수단 없음 | 자동 적용. 일치 위치 표시만 |
| 넘기기(복사) | AI 처리 아님. 사용자 실행 | — | 클립보드만 바뀜. 외부 전송은 사용자의 붙여 넣기 | 사용자가 명령으로 실행 |

가치 정의문:

> AI 활용자가 AI 작업 중 저장해 둔 자료를 AI 도구에 넣을 때, AI가 자료마다 요약을 미리 만들어 두는 일을 맡아 원문을 다시 열지 않고 넘길 글을 얻는다. AI가 틀리면 사용자는 펼치기로 넘길 글을 보고, 출처를 열어 대조하고, `고치기`로 요약을 바꾼 뒤 다시 넘길 수 있다.

### 5-3. 실제 길이 확인

데모 시드(계정 B)로 넘길 글을 handoff-format.md 2절 규칙대로 조립해 글자 수를 셌다. 날짜는 발표일(D=2026-12-01) 기준이다. 요약은 S25·S28만 handoff-format.md 예시이고 나머지는 디자이너가 쓴 모의 요약이다. 링크 주소는 길이 계산용 가짜 주소다(`https://example.github.io/news/s30` 등). 글자 수는 여는 줄부터 닫는 줄까지, 줄바꿈 포함(handoff-format.md 5절). `[사실]` 계산 결과이고 개발 빌드 실측이 아니다.

| 경우 | 입력 | 건수 | 글자 수 | 줄 수 | 확인한 것 |
|---|---|---|---|---|---|
| C1 짧은 자료 | `찾기 회고 \| 넘기기`(S11) | 1 | 303 | 8 | 붙여 넣은 글의 제목이 `단풍 라떼 캠페인 회고 (작년 가을) - 잘`로 낱말 중간에서 끊긴다(handoff-format.md 2절 제목 규칙 "앞 24자"). 데모 시드 표(demo-seed.md:47)의 제목 `단풍 라떼 캠페인 회고 메모`와 다르다. 같은 규칙으로 S32는 `텀블러 세척 메모 - 베이킹소다 한 숟갈 +`, S34는 `오늘 할 일 - 트렌드 보고서랑 파란컵 캡처`(데모 `최근` 맨 위)로 끊긴다(04 질문 6) |

| C5 긴 자료 | 요약을 상한 400자(handoff-format.md 2절 제안)로 채운 계산 | 1 / 8 / 23 | 622 / 4,101 / 11,571 | — | 23건 `전부`이면 1만 자를 넘는다. "길다" 기준이 없어(ST-23 보류) 언제 고르게 할지 정해지지 않았다 |

화면 쪽 확인:

- 넘기기 결과의 자료 줄 `<번호>  <제목>`은 제목이 가장 긴 C4에서도 100칸(design-review 4-1절 ResultList) 안이다. 모바일 375px 폭에서는 고정폭 글꼴로 한글 20자 안팎에서 줄이 바뀐다. 번호 열을 고정하고 제목만 줄바꿈한다(H-10, 상태 보드에서 확인).
- C4 `전부`는 결과 블록에 자료 줄 8줄이 나온다. 23건이면 23줄이다. 무엇이 나갔는지 늘 보이는 것(PRD 10절, N6)을 지키려고 줄이지 않는다(H-07).
- 미리보기는 가변폭 글꼴, 한 줄 한글 40자 안팎(design-review 4-1절 글꼴). 400자 요약은 미리보기에서 10줄 안팎이다.

## S6. 검증과 인계

검증 세 가지를 섞지 않는다. 사용성(사람이 이해·통제하는가), AI 품질(모델·설정이 쓸 만한가), 승인 범위(어디까지 허락됐는가)는 증거가 다르다.

### 6-1. 사용성 검증 (리허설 과업)

실사용자 테스트는 없다(STATE 12절). 외부 사람에게 첫 화면을 보여 주는 5초 확인도 하지 않는다(범위 결정 STATE 12절 2026-11-25와 같고, 04 질문 15 추천 A도 같음). 아래는 팀 리허설(11/30)에서 팀원이 처음 쓰는 사람 역할로 하는 과업이다. 결과는 사용자 검증이 아니라 리허설 관찰로만 쓴다.

| 가설 | 과업(버튼 이름을 알려 주지 않음) | 관찰 항목 | 판정 규칙 |
|---|---|---|---|
| H-01 | "겨울 텀블러 캠페인 안을 AI에게 받기 전에 필요한 자료 두 건을 넘길 준비를 해 주세요" | 펼치기를 여는가, 요약을 읽는가 | 펼치기를 열고 요약 한 곳 이상을 말하면 지지, 열지 않으면 반박 |
| H-08 | 위 과업 뒤 "지금 이 자료가 AI 도구에 보내졌나요?" | `✓ 복사됨`을 보냈다로 읽는가 | 붙여 넣어야 한다고 답하면 지지 |
| H-09 | S33을 섞어 넘긴 뒤 "넘긴 글에서 빠진 것이 있나요?" | `! 요약 없음`을 알아채는가 | 어느 자료인지 말하면 지지 |

판정은 `지지 / 반박 / 판단 불가`. 리허설을 하지 않으면 모두 판단 불가다.

### 결정

모든 결정의 상태는 **제안**, 결정자는 `AI 제안·미확인`(디자이너 에이전트)이다.

**D-01 요약은 자동 실행 + 사후 통제로 둔다(기존 결정 확인)**
- 대안: 수동 / 규칙 발췌 / AI 보조(승인 뒤 저장) / 자동 + 사후 통제
- 판단 기준: 저장 때 기다리지 않음(user-flow 3절), 틀린 요약을 알아챌 수단, 비용(COM-005)
- 결정: 자동 + 사후 통제. 근거 R-03, ADR-BCK-008, ARC-004 / 가정 H-01
- 감수한 것: 틀린 요약이 사용자가 보기 전에 넘어갈 수 있다
- 재검토 조건: E-01·E-03에서 지어낸 내용이 나오면 S3로 돌아간다
- 영향: ST-01~12, AC-01~09

**D-02 태그는 자동 실행 + 지우기로 둔다(기존 결정 확인)**
- 근거: ARC-002 / 감수: 사용자가 태그를 더하지 못한다 / 재검토: E-09 실패 / 영향: ST-13, AC-11

**D-03 글자 추출은 자동 실행으로 두되 사후 통제가 약하다고 기록한다**
- 근거: ADR-BCK-005, INS-04 / 감수: 틀린 글자를 사용자가 고칠 수 없다 / 재검토: E-04·E-05 실패, 또는 Q-12 답 / 영향: ST-14, AC-12

**D-04 사람 검토 지점은 넘기기 결과의 펼치기와 넘길 글 안내 줄 두 곳이다**
- 대안: (a) 저장 직후 요약 확인 요구 (b) 넘기기 전 미리보기 확인을 필수로 (c) 복사 뒤 펼치기(이미 PO 결정)와 안내 줄
- 판단 기준: 단계 수(1분 성공 기준, user-flow 1절), 외부 실행 여부(복사는 외부 실행이 아님)
- 결정: (c). 근거 R-02, R-06, INS-02, INS-03 / 가정 H-01
- 감수한 것: 펼치지 않고 붙여 넣는 사용자는 요약을 보지 않는다
- 재검토 조건: 리허설에서 H-01 반박
- 영향: ST-15~18, AC-13·17

**D-05 넘기기 실패 문구를 제안한다**
- 제안: `✗ 복사 안 됨: <이유>  선택은 남겨 둠`, 이유 `연결 끊김`·`응답 없음`·`서버 오류`·`클립보드 거부`, 다음 줄 `→ 넘기기`
- 근거: ARC-005 저장 실패 문구 모양, R-10 / 감수: 이유 낱말 하나 추가(`클립보드 거부`)
- 재검토 조건: PO가 다른 문구를 고름 / 영향: ST-19, AC-18

**D-06 요약이 없는 줄도 넘길 글 칸 이름은 기존 `AI 요약`을 쓴다**
- 대안: (a) 기존 `AI 요약` 칸에 handoff-format.md 3절 괄호 이유 (b) 새 이름 `요약` (c) 칸 없이 이유만
- 판단 기준: 확정 문구를 새로 만들지 않음(handoff-format.md, STATE 12절 2026-11-26), ARC-004 값 "넘길 글 칸 이름" 두 가지만
- 결정: (a). 근거 ARC-004 규칙 3·6, handoff-format.md 3절 / 가정 H-11
- 감수한 것: AI가 만들지 않은 줄에 `AI 요약` 이름표가 붙는다. 괄호 안 `요약 없음`이 이를 알린다
- 재검토 조건: 리허설에서 AI 도구가 이유 문구를 요약으로 읽는 일이 생길 때만
- 영향: ST-07·16, C3, C4

**D-07 `failed` 자료의 다음 행동으로 `→ 고치기 <번호>` 칩을 제안한다**
- 근거: `blocked` 꼬리표가 이미 같은 모양(ARC-005 사용자 문구) / 감수: ARC-005 문구가 바뀐다(정책 수정은 PO) / 영향: ST-08, Q-07

**D-08 측정 이벤트는 `item_saved`, `handoff_copied`, `connection_read` 셋만 둔다**
- 근거: R-01, PRD 4절 / 감수: AI 품질 신호(고치기 비율 등)는 이벤트로 남기지 않음. 평가 세트로 본다 / 영향: 6-5절
- 속성 목록은 제안이다. [공통 열린 질문](../../policies/common/open-questions.md)의 "지표 이벤트에 무엇을 넣지 않을 것인가"와 "지표용 이벤트를 얼마나 보존할 것인가"의 답 전이다. 답이 나오면 6-5절 속성을 그 답에 맞춘다

## 8. PO 결정 질문

결정자 표기: 이 문서의 추천안은 모두 `AI 제안·미확인`이다. 일정에 막히는 순서로 적었다.

**질문 1. 넘기기 실패 화면 문구를 정할까요? (Q-02, 04 질문 2와 같음)**
- 배경: commands.md 6절 넘기기 행에는 성공 문구만 있다. design-review-2026-11-26.md:75는 Safari가 서버 응답 뒤 클립보드 복사를 거부할 수 있다며 "실패 화면 준비"를 적었다.
- 선택지: (A) D-05 문구 `✗ 복사 안 됨: <이유>  선택은 남겨 둠` + `→ 넘기기` (B) 문구를 두지 않음
- 추천: (A). 이유: 데모 필수 흐름의 마지막 단계라 실패해도 다음 행동이 보여야 한다. 포기하는 것: 설명서에 문구 한 줄과 이유 낱말 `클립보드 거부`가 늘어난다. 데모 브라우저는 PO 질문이 아니다(개발·리허설이 정함, 04 4절 개발 안 1).

**질문 2. 웹에서 자세히 보기로 가는 길을 둘까요? (Q-01, 04 질문 4로 합침)**
- 배경: ARC-004 규칙 1 "자세히 보기에서는 요약 앞에 `AI 요약` 또는 `요약 (직접 고침)`을 붙인다." commands.md 2절 명령 13개에는 자세히 보기를 여는 명령이 없다. 모바일은 메뉴 시트에 `열기`가 있다(design-mobile-desktop.md M3). 목록 태그 규칙과 함께 정한다.
- 선택지와 추천: 04 질문 4. 이 문서는 추천 A(모든 목록에 태그 앞 3개, 웹 자세히 보기는 발표 뒤)를 `[가정]`(H-11)으로 따른다. 포기하는 것: 웹에서 태그 4·5번째와 `요약 (직접 고침)` 이름표는 발표 뒤까지 넘길 글 미리보기에서만 보인다.

**질문 3. 요약이 없는 자료의 넘길 글 칸 이름을 기존 `AI 요약` 그대로 둘까요? (Q-04, 04 질문 12와 같음)**
- 배경: ARC-004 값 "넘길 글 칸 이름 `AI 요약`, `요약(직접 고침)`". handoff-format.md 3절은 요약 칸에 `(요약 없음: …)`을 쓴다고만 했고 칸 이름은 따로 없다. 구현은 한 가지를 골라야 한다.
- 선택지: (A) `- AI 요약: (요약 없음: …)`(새 문구 없음) (B) 새 칸 이름 `- 요약: (요약 없음: …)`(ARC-004 값 수정)
- 추천: (A). 이유: 확정 형식과 정책 값 안에서 끝난다. 포기하는 것: AI가 만들지 않은 줄에 `AI 요약` 이름표가 붙는다.

**질문 4. 연결된 AI 도구가 "검색"만 하고 "읽기"는 안 한 경우도 넘기기로 셀까요? (Q-08, 04 질문 18과 같음)**
- 배경: PRD 4절 북극성 "넘기기는 넘길 글 복사, 또는 연결된 AI 도구가 자료를 읽은 것". ARC-009 규칙 2는 검색 응답에도 요약을 준다.
- 선택지: (A) 검색 응답도 셈 (B) 읽기 도구만 셈 (C) 둘 다 기록하고 발표에서는 읽기만 셈
- 추천: (C). 이유: 연결은 P1이라 발표 수치에 영향이 거의 없고, 기록만 남기면 나중에 고를 수 있다. 포기하는 것: 이벤트가 하나 늘어난다(6-5절 수정).

나중에 정해도 됨: Q-06·Q-09(04 질문 20), Q-07(04 질문 17), Q-11(04 질문 6·19), Q-12(04 질문 21).
