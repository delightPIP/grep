## 0. 다음 AI가 먼저 알 것

- **사용자는 PO다.** 검토·제안은 PO 관점(발표 이야기, 데모 대본, 범위, 정책·문구, 주장과 근거의 일치)으로만 한다. CI 상태, PR 머지 순서, 배포 작업, 구현 방법·순서 같은 개발 영역은 제안하거나 건드리지 않는다. 개발 진척은 "되는지/안 되는지"만 사실로 적는다
- 개발 판단은 개발자(기석) 안을 따른다. PO 질문으로 남기지 않는다
- 범위는 기획 → 개발 → 발표까지다. 실사용자·베타·인터뷰는 없다
- 먼저 읽을 문서(이 순서)

## 3. 발표까지 할 일 (PO)

1. **개발자에게 리허설 요청 보내기** (4절 초안). 보냈는지는 이 문서 작성 때 확인하지 못했다
2. **리허설에서 체크리스트 확인** (5절) → H-1~H-4 결정
3. **결정 반영**: 발표 메모 5절 대본을 한 갈래로 확정, 데모 시드 5절 장면표 기대값 맞추기
4. **슬라이드 만들기**: 발표 메모 1절 뼈대(불리한 숫자 → 문제 좁히기 → 푸는 것/풀지 않는 것 → 데모 → 차별점 → 근거의 한계 → 예상 질문). 숫자와 문장은 [설문 결과](survey-results.md)에서 그대로 옮긴 것만 쓴다
5. **"이후" 범위 말하기**: F9·F10·F11·F13·F18·F19(#141~#146)는 발표 메모 4절 "모으는 과정은 풀지 못했다"와 같은 말로 한 번에 묶는다

## 5. 리허설 PO 확인 체크리스트

순서는 발표 메모 5절 대본을 따른다. 기대 문구와 건수는 데모 시드 5절 장면표가 기준이다.

**준비**
- [ ] 계정 B가 34건 그대로이고 찾아둔 검색어가 없는지(데모 시드 6절)
- [ ] 2번 장면의 "자료 없이 AI에 시킨 결과" 화면이 준비됐는지

**대본 순서대로**
1. [ ] 계정 A 첫 화면과 `도움말`(18줄). `샘플 8건으로 해 보기`는 보이기만 하고 누르지 않는다
2. [ ] 로그아웃 → Google로 계정 B 전환이 끊김 없이 되는지
3. [ ] `최근`에 기사 링크·캡처·붙여 넣은 글·PDF가 한 목록에 보이는지
4. [ ] PDF를 끌어다 놓으면 `✓ 저장됨`·`요약 생성 중`, 같은 링크를 다시 넣으면 `! 이미 저장됨`
5. [ ] `찾기 텀블러` 8건 → `찾기 텀블러 캠페인` 4건. 맨 아래 `→ 찾아두기 …` 줄은 설명만 하고 누르지 않는다
6. [ ] `고르기 25 28` → `넘기기`로 넘긴 글이 AI 입력창에 붙여 넣기 좋게 읽히는지(PO 판단)
7. [ ] 2번 결과와 나란히 놓았을 때 차이가 청중 눈에 보이는지

**그 자리에서 정할 것**: H-1~H-4(2절)

**적어 둘 것**: 정책 문구와 다르거나 어색한 화면(스크린샷), 기다림이 길어 무대에서 어색한 곳
