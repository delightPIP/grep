# 기획 한눈에 보기

2026-11-25 기준. 서비스 이름은 그렙(영문 grep), 팀 이름은 Unwrap(김태인 PO, 박기석 개발)이다.
이 문서 하나로 지금까지의 기획을 볼 수 있게 정리했다. 근거와 세부는 맨 아래 원본 문서에 있다.

> 인물은 모두 가상이고, 문제와 원인은 가설이다(인터뷰는 하지 않는다). 설문은 응답 12개라 방향만 본다.

## 1. 한 줄로

**SNS, 유튜브, 웹 등에서 저장해 둔 자료를 한곳에 모아 두고, Claude 같은 AI에게 일을 시킬 때 그 자료가 같이 들어가게 해 주는 서비스.**
화면은 터미널 느낌이고, 쉬운 명령어 몇 개로 쓴다.

## 2. 누구의 어떤 문제인가

| | |
|---|---|
| 누가 | 알고 싶은 게 많고 써 보고 싶은 게 많은 AI 활용자. SNS, 유튜브, 웹 등에서 본 걸 이것저것 저장한다 |
| 언제 | 프로젝트를 하면서 Claude에게 일을 시킬 때 |
| 무엇이 문제 | 저장해 둔 자료가 **떠오르지 않는다.** 떠올라도 여러 앱에 흩어져 있어 찾기 어렵다 |
| 그래서 | 같은 질문을 또 하고 같은 검색을 또 한다. 결과물이 평범해지고, 저장한 자료는 쓰이지 않는다 |

### 한 사람의 하루 (가상 인물 서윤, 29, 스타트업 PM)

| 단계 | 하는 일 | 기분 |
|---|---|---|
| 발견 | 스레드에서 프롬프트 글을, 유튜브에서 뉴스레터 디자인 사례 영상을 본다 | 😀 +2 |
| 저장 | 스레드 저장, 유튜브 나중에 볼 동영상, 북마크, 캡처. 그때그때 다른 곳에 | 🙂 +1 |
| 쌓임 | 2주 동안 열어 보지 않는다 | 😐 0 |
| 작업 시작 | 주말에 Claude에게 “구독 페이지 만들어 줘” | 🙂 +1 |
| **떠올리기** | **저장한 자료가 떠오르지 않는다. 잊은 줄도 모른다** | 😐 0 |
| 다시 묻기 | 자료 없이 묻고, 결과가 밋밋해 같은 검색을 또 한다 | 😕 −1 |
| 며칠 뒤 | 유튜브 나중에 볼 동영상에서 그 영상을 발견. “아, 저장해 놨었는데” | 😞 −2 |

**핵심:** 잊은 사람은 잊은 줄 모른다. 그래서 사용자가 직접 찾아 넘기는 방식만으로는 시작이 안 된다. AI에게 일을 시키는 순간에 서비스가 자료를 먼저 보여 줘야 한다.

## 3. 설문 신호 (응답 12명, 판정은 보류)

| 질문 | 결과 |
|---|---|
| 지난 4주, 저장해 둔 걸 모르고 또 찾거나 또 저장한 적 | 2번 이상 **6명**, 모르겠다 4명, 없다 2명 |
| “검색하면 대체로 바로 찾는다”에 동의 | **2명** (비동의 6명, 보통 4명) |
| 저장하는 이유 | “언젠가 쓸 것 같아서” **8명**, “곧 작업에 쓰려고” 0명 |
| 저장한 자료 형식 | 링크 9명, 이미지·캡처 7명 |
| 못 찾았을 때 | 8건 중 7건이 비슷한 자료를 새로 찾아 씀. 직후 웹에서 다시 검색 4, 포기 3 |

응답자는 경력 1년 미만이 12명 중 7명으로 치우쳐 있고, AI 사용은 묻지 않았다. 설문은 응답 12개로 마감했다.

## 4. 해결: 서비스가 도와야 할 네 순간

| 순간 | 지금 | 그렙이 하는 일 |
|---|---|---|
| 저장할 때 | 앱마다 다른 곳에 저장 | 링크 공유나 캡처 이미지로 한곳에 모은다. 요약은 알아서 만든다. 분류는 묻지 않는다 |
| **Claude에 요청할 때** | 저장한 게 떠오르지 않는다 | **서비스가 먼저 알려 준다** (아래 세 방법) |
| 같은 걸 또 찾거나 저장할 때 | 같은 검색·저장 반복 | “이미 저장한 자료가 있어요”와 관련 자료를 보여 준다 |
| 대화를 새로 시작할 때 | 같은 자료를 다시 넣는다 | 자주 쓰는 묶음에 이름을 붙여 한 줄로 다시 넘긴다 |

### Claude에 요청할 때, 자료가 먼저 나타날 세 곳

| | 어디서 | 사용자가 보는 것 | 조건·한계 |
|---|---|---|---|
| 방법 1 | Claude 안에서 | Claude: “저장해 두신 레퍼런스 3개를 참고했어요” | Claude에 처음 한 번 연결(MCP)해 둬야 함 |
| 방법 2 | 우리 앱에서 | `start 뉴스레터` → 관련 자료를 모아 붙여 넣을 글 복사 | 앱을 열 생각이 나야 함 |
| 방법 3 | Claude 입력창 옆에서 | 질문 쓰는 동안 “관련 저장 자료 3개 [넣기]” | 브라우저 확장 필요. 나중 단계 |

### 기억날 때와 잊었을 때

- **기억날 때:** 내가 명령어로 직접 찾아 골라 넘긴다. `grep 인증 | copy` → 지금 차별점.
- **잊었을 때:** 서비스가 대신 챙긴다. Claude가 먼저 찾아보고(방법 1), 같은 걸 또 저장하면 이미 있다고 알려 준다.

## 5. 기능 목록 (기획서 0.3의 제안. 범위는 개발자가 정한다)

| 묶음 | 기능 |
|---|---|
| 먼저 (P0) | 저장(링크·글·이미지·PDF, 분류 없이) · 요약 자동 생성 · 터미널 화면에서 찾기 · 골라 묶어 붙여 넣을 글 복사 · 첫 사용 안내(예시 명령, 버튼) · 지우기·고치기 |
| 다음 (P1) | 기기 간 동기화 · Claude 연결(MCP) · 북마크 가져오기 · 이름 붙인 묶음 · 뜻이 비슷한 자료 찾기 · 이미지 속 글자 읽기 · 잘못 친 명령 고쳐 주기 |
| 새 후보 | 작업 이름으로 자료 모으기(`start`) · 같은 걸 또 저장할 때 알려 주기 |
| 나중 | 다른 앱(노트 앱, 카톡 등)에서 가져오기 · 영상 내용 · 브라우저 확장 · 작업에 맞춘 요약 |
| 안 함 | 앱 안에서 AI와 대화 · 팀 공유 공간 · 화면 자동 기록 |

## 6. 정해진 것 (PO 결정)

| 항목 | 결정 |
|---|---|
| 솔루션 | 여러 플랫폼에서 자료를 저장해 모으고, AI 도구가 쓸 수 있게 요약해 넘긴다 |
| 원칙 | AI와 경쟁하지 않는다. 답을 만들지 않고 자료를 넘기는 쪽에 선다 |
| 컨셉 | 터미널 느낌의 화면, 쉬운 명령어 몇 개. 진짜 명령줄 도구는 아니다 |
| 차별점 | AI가 알아서 찾아 읽는 연결형 서비스와 달리, 사용자가 명령어로 직접 골라 묶어 어떤 AI 도구에든 넘긴다 |
| 명령어 이름 | `grep`, `ls`, `copy` 같은 유닉스식 + 한국어 한 줄 설명 |
| 북극성 지표 | 한 주에 넘기기를 한 날이 하루 이상인 사용자 수 |
| 첫 시장 | 국내, 한국어 |

## 7. 기석님께 부탁 (개발자가 정할 것)

1. **MVP 범위와 첫 플랫폼.** 5절 표의 P0·P1이 현실적인지, Android·iOS·Web·Windows 중 어디부터 할지
2. **기술 구조.** 자료를 어디에 두고 어디서 처리할지(서버·기기), 요약을 만들 모델
3. **Claude에 요청할 때의 세 방법 중 무엇이 현실적인지.** 4절 표의 방법 1~3

## 8. PO가 아직 정할 것

- “떠올리지 못한다”를 정식 원인 후보로 올릴지
- “잊었을 때는 Claude가 알아서 찾는다”를 넣어도 “직접 고른다”는 차별점이 흐려지지 않을지
- `start` 명령, “이미 있어요” 알림을 범위에 넣을지

## 9. 아직 모르는 것

- 서윤 같은 사람이 실제로 얼마나 되는지 (설문으로 방향만 본다. 인터뷰와 일지 연구는 하지 않는다)
- 사람들이 “Claude가 알아서 찾기”와 “직접 골라 넘기기” 중 무엇을 원하는지
- 이미 Claude 프로젝트에 자료를 모아 두고 쓰는 사람이 많은지 (많으면 차별점을 다시 본다)
- 비개발자가 터미널 느낌의 화면을 반기는지, 꺼리는지
