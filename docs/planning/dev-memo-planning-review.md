# 개발자 전달 메모: 기획 첨삭에서 나온 것

- 작성일: 2026-11-26
- 근거: 외부 PO 첨삭(2026-11-26)을 PO가 받아들인 것. 발표 쪽은 [발표 메모](presentation-notes.md)에 있다
- 성격: 요청과 제안이다. 개발 범위(데모 필수 4개)는 바꾸지 않는다. 할지 말지와 방법은 개발자가 정한다

## 1. 해 주면 좋은 것 (비용 거의 없음)

| # | 내용 | 이유 |
|---|---|---|
| 1 | 요약 지시문에 "수치·고유명사·핵심 문장은 원문 그대로 남긴다"를 넣는다 | 작업을 모르고 만든 요약은 작업에 필요한 세부(숫자, 코드, 문장)를 지운다. "요약해 넘긴다"(PO 고정)를 지키면서 보완하는 방법 |
| 2 | 실패·0건 문구에 다음 행동을 붙인다. 예: `0건. 다른 단어: 찾기 [단어] · 최근 저장: 최근`, `없는 명령: 찿기. 혹시 찾기?` | 성공은 건조하게, 실패는 다음에 칠 것까지. 입문자가 명령어 화면에서 막히지 않게(명령어 설명서 6절 말투는 유지) |
| 3 | 결과 목록 줄에 저장 날짜를 보인다 | 설문에서 못 찾은 8건 중 6건이 대략 언제 저장했는지 기억함. 시점으로 찾기(F22)가 데모에 못 들어가도 눈으로 거를 수 있다 |
| 4 | 요약을 만들 때 검색용 핵심어를 함께 만들어 `찾기` 대상에 넣는 것을 검토한다(자동 태그와 같은 처리라면 이미 됨) | 뜻으로 찾기(F15)의 값싼 대용 |

## 2. 미리 알면 좋은 함정

- 한글 조합 중 Enter가 두 번 처리되는 문제(IME composition 중 keydown)
- 조사 때문에 낱말 단위 검색이 빗나가는 문제("결제를", "결제는"). 부분 일치 검색(PGroonga)이면 해결된다
- 같은 글의 다른 주소(모바일 주소, 단축 주소)는 COM-001 비고의 "나중에 붙일 것"
- 스레드·유튜브 링크는 서버가 본문을 못 가져올 수 있다(ARC-006 `blocked`). 데모 시드의 S10 장면과 함께 오늘 한 번 확인 부탁

## 3. 확인 부탁

| # | 질문 |
|---|---|
| 1 | 묶음 최소판(마지막에 고른 것을 새 대화에 다시 넘기기)을 데모에 넣을 수 있는가. 안 되면 N5 장면은 `고르기`를 다시 하는 것으로 보여 준다 |
| 2 | 로그인과 서버 저장이 있으면 기기 간 동기화(F6)는 따로 만들 일이 있는가, 자동으로 따라오는가. 발표에서 기능 목록을 정리할 때 쓴다 |
