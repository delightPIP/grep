# 문서 지도

이 폴더는 그렙의 설계 결정, 서비스 정책, AI 활용 기록을 담는다. 프로젝트 소개는 [루트 README](../README.md)에 있다.

## 읽는 순서

1. [ADR 목록](adr/README.md): 왜 이런 기술과 구조를 골랐는가
2. [정책 목록](policies/README.md): 서비스가 어떻게 동작해야 하는가
3. [AI 활용 기록](ai-usage/README.md): 이 프로젝트에서 AI를 어떻게 썼는가

## 폴더별 설명

| 폴더 | 담는 것 | 단위 | 고치는 방법 |
|---|---|---|---|
| `adr/` | 설계·기술 결정과 대안, 기각 이유 | ADR 1개 = 파일 1개 | 채택 후 내용을 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고 옛 ADR의 상태만 바꾼다. |
| `policies/` | 서비스 정책(정책의 유일한 근거) | 정책 1개 = 파일 1개, 영역 폴더별 | `docs:policy-manager` 스킬 절차로 추가·수정·폐기한다. |
| `ai-usage/` | AI 활용 이력(외부 제출 가능) | 항목 1개 = 파일 1개(`log/`) | 추가만 한다. 기존 항목은 고치지 않는다. |
| `templates/` | ADR·정책·AI 로그 작성 틀(`adr.md`, `policy.md`, `ai-log.md`) | 문서 종류당 파일 1개 | 형식을 바꿀 때만 고친다. 새 문서는 이 틀을 복사해 쓴다. |

## 파일 이름 규칙

- 공통 ADR: `adr/ADR-<네 자리 번호>-<영문-슬러그>.md`(번호는 프로젝트 전체 순번)
- 플랫폼 ADR: `adr/<플랫폼 폴더>/ADR-<플랫폼 접두어>-<세 자리 번호>-<영문-슬러그>.md`
  - 플랫폼과 접두어는 [ADR 목록](adr/README.md)의 "플랫폼과 접두어" 표를 따른다.
- 정책: `policies/<영역>/<접두어>-<세 자리 번호>-<영문-슬러그>.md`
  - 영역과 접두어는 [정책 목록](policies/README.md)의 "영역과 접두어" 표를 따른다.
- AI 로그: `ai-usage/log/NNN-<영문-슬러그>.md`

정책·ADR·AI 로그 폴더의 `README.md`에는 목록 표가 있다. 파일을 추가하거나 상태를 바꾸면 그 표도 같이 고친다.

## 무엇을 어디에 적나

| 내용 | 적는 곳 |
|---|---|
| 대안이 있었고 트레이드오프를 따져 고른 설계·기술 결정 | `adr/` |
| 서비스가 보장해야 하는 동작과 문구, 값 | `policies/` |
| AI와 한 작업의 요청, 산출물, 판단, 검증 | `ai-usage/log/` |
| dev 스킬이 읽는 팀 정보(다음 관문, 결정권, 원본 위치) | [dev-team-config.md](dev-team-config.md) |
| 화면·데이터·로직·모듈이 어느 문서에 있는지(값은 옮기지 않는 색인) | [SPEC.md](SPEC.md) |

## 문서를 고친 뒤에

`bash Scripts/check-docs.sh`를 실행한다. 상대 링크, 정책·ADR·AI 로그 목록 표, 정책·ADR 번호 참조가 맞는지 확인한다.
